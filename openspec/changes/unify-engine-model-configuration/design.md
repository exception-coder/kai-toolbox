# 统一引擎模型配置

## 目标与边界

在同一会话内选择当前引擎的模型及其已声明的推理强度、速度；保留 Codex 既有通道、快捷组合和 Auth 目录切换。Claude 通过安装的 Agent SDK `applyFlagSettings` 设置当前会话强度及独立 Ultracode 开关，设置进入下一轮，不修改用户全局配置。没有显式配置的旧会话不加覆盖。来源：[Claude 模型配置](https://code.claude.com/docs/en/model-config)、[SDK 类型参考](https://code.claude.com/docs/en/agent-sdk/typescript)；实际权限与引擎限制优先。

## 产品原则和交互

适用 OBJ-01、NAV-03、CTX-01、DENS-01、FEED-01、EVID-01、IDEM-01，无新增导航。对象是当前 Forge 会话及其当前引擎；复用模型目录、会话设置、服务商与授权切换。桌面使用单层 Popover，手机使用底部抽屉；权限与高级设置独立分区。关闭恢复焦点并保留草稿。手机 Codex 快捷组合保留在同一抽屉内，切换导致强度/速度变化前必须确认。

目录可用时展示已声明的能力；目录缺失或失败保留当前模型并提供同步，网关支持手填；不依据模型名称推断其他能力。设置保存失败与引擎拒绝必须暴露错误，未配置/已保存/实际运行不能混称。重复打开或刷新只读取，不自动发送任务或写配置。运行中修改不取消当前轮次；本轮派发快照与下一轮选择分开显示，快照只表示请求参数，不伪称已由引擎确认，未知时明确显示未回传。原生环境与组织限制可能限制最终结果。

## 数据与验证

Sidecar 负责获取和调用原生引擎，宿主透传模型能力并以当前会话为键保存 Claude 选择，工作台把各引擎已返回的数据映射为同一选择控件。Codex 使用既有模型、强度、速度协议；不把同名强度认定为跨引擎同一能力。Claude SDK 提供 Ultracode 开关，但模型目录没有声明该开关的可用性；不把 xhigh 强度当作支持证明，界面明确由引擎及工作流决定。既有会话及设备重新连接恢复设置；复制会话时继承，删除会话清理设置。真实桌面/手机视觉、引擎原生调用及目标运行版本各自验证，不能用组件测试代替。
