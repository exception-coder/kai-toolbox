# 决策与边界

适用原则：OBJ-01、NAV-01、CTX-01、DENS-01、FEED-01、EVID-01、CTRL-01、IDEM-01，无例外。新写操作按 L3 核对数据完整性，使用项目 forge-lite，验证按风险定向执行。

## 结构

对象身份为会话 ID + 服务端解析的仓库引用，继续使用 SessionGitRepositoryService 与 ProjectAccess；界面不接受任意路径，不扩大原会话授权。多仓库先选择仓库，后显示分支与同步。提交查询、同步快照和写操作都传同一仓库身份；异步请求按代次隔离，换仓或换分支后旧响应不能回填。

一个 Radix Dialog 包含概览、分支选择、历史、详情四种视图；移动端底部抽屉，桌面居中。只有内容区域滚动，Header 48px，安全区留给底部；分支完整换行，按钮不压缩。关闭恢复原触发器焦点，内部返回保留各视图滚动位置，不卸载聊天主界面和草稿。目录管理复用原会话工具菜单，不在此面板再放一套。

默认只显示最近 3 条提交，不显示提交正文；历史按每页 100 条加载，固定首屏提交版本，分支变化要求刷新，不拼接不同版本。分支列表独立搜索，区分本地/远程/当前，可复制完整名称；“查看提交”与“切换到此分支”是不同动作。

## Git 能力

Common 只增加 GitWorkspaceOperations 端口与 DTO；tool-projects 通过现有 Git 命令边界和仓库互斥实现，tool-claude-chat 解析会话仓库并授权后调用，不增加工具模块依赖。只读本地状态为默认；统一刷新显式 fetch 当前上游，再获取分支和历史，不更新工作文件。远端失败保留本地状态并提示，成功核对 5 分钟内才可能标记“已同步”；ahead、behind 均为 0 只是必要条件，缺失上游或计数、缓存状态均不能声称已同步。

分支切换预检查与确认后执行都检查工作树、暂存区、未跟踪文件、未完成合并/rebase/拣选；指纹包含规范仓库路径、源分支与 HEAD、完整目标引用及提交、本地名称、跟踪关系。目标变化拒绝；远端分支只新建未存在的本地分支并跟踪，不覆盖同名本地分支。不强制、不自动 stash，不覆盖被忽略文件；已有 Git worktree 限制由普通 checkout 拒绝。用户须先停止正在修改仓库的 Agent，本功能不分配 Agent 分支、不接管写锁或调整内部任务分支策略，AI 编程架构契约不变。

领先提供推送、落后提供拉取、分叉只读查看提交后引导本机处理；沿用既有确认快照和快进保护。请求进行时禁止关闭、换仓和重复写操作。失败保留上下文，未知结果先刷新核对，不自动重试；重复切换到当前分支明确拒绝，不重建分支或再次写入。无上游提供设置指引。

## 验证依据

定向覆盖跨仓/跨分支迟到响应、默认 3 条、固定版本分页、缓存零计数与远端核对区分、写入确认和关闭保护，以及真实临时仓库中的脏文件、过期目标、跟踪关系、被忽略文件保护。宿主装配覆盖新增 Bean。真实手机/桌面与实际版本加载单独记录，不由编译或预览入口成功替代。

项目沿用 React 19 与已安装的 Radix Dialog，不为此次改造升级依赖。[Radix Dialog 官方说明](https://www.radix-ui.com/primitives/docs/components/dialog) 用于核对焦点与关闭行为；[Git fetch 官方说明](https://git-scm.com/docs/git-fetch) 用于核对远端跟踪引用更新与工作文件边界。
