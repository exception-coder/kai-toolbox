# 轮次 Git 观察记录设计

主对象是当前会话，唯一记录身份为 sessionId + 平台 turnId。复用 SessionGitRepositoryService 的主仓库、父仓库、关联项目及 ProjectAccess 检查。适用 OBJ-01、NAV-01、CTX-01、EVID-01、FEED-01、IDEM-01；不新增全局变更页。菜单归入“工作区 · 项目”，实时轮次结束行可打开该轮记录。

开始派发前采集 HEAD 与脏文件 SHA-256；结束后比较内容及 HEAD 区间。原先未变的脏文件排除，原有修改仅被提交时明确标识。文件列表采用 NUL 分隔保护中文、空格及重命名路径。仅保存路径、状态、摘要与提交端点，不保存文件正文。SQLite 由正常启动的 SchemaInitializer 幂等建表，无人工执行迁移。DDL 知识基线尚无新表；以本次新建 schema 和真实 SQLite 测试验证新结构，不将既有知识库认作已核验。

这是一组工作区观察，不是 Agent 作者审计。并发或手动改动无法仅凭 Git 区分，界面始终声明该边界。起止之间修改又撤销的文件无净差异，可能不出现；被 Git 忽略的文件不采集。HEAD 端点差异不证明提交由本会话产生。无 HEAD、非 Git、读取失败、链接、超过采集上限均记录缺口，不能显示为完整无变更。后台断连或宿主崩溃未收到终态时基线保留“尚未收口”，不在下次启动用新工作区补造结束快照。

最多 8 个仓库、每仓库 200 个文件、单文件 8MB、每次摘要 32MB；Git 子进程复用公共超时及输出上限。同步采集发生在派发与队列下一轮前，避免串用后一轮工作区；采集失败不阻断 Agent。检索限定 sessionId、参数化字面匹配、每页 20 条并取第 21 条判断下一页。索引先限定会话，但 JSON 检索仍随该会话历史增长；本次不宣称大规模历史性能已验证。

加载、无记录、搜索无结果、部分采集、错误和新版后端未加载分别展示；失败可重试，关闭回原会话，保留草稿。Radix 模态复用焦点恢复、Esc 和窄屏滚动。验证真实临时 Git 仓库、SQLite 幂等/分页/会话隔离，前端错误与搜索、桌面/390px 布局；后端启动验收待用户明确重启授权。此业务记录不修改 Forge/OpenSpec/Graphify 套件协作及治理证据契约，无 AI 编程架构文档影响。
