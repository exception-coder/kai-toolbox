# 设计与故障证据

## 证据与根因

MockMvc 已复现两个 HTTP 500：`Set.of().contains(null)` 来自未建立 SDK ID 的开发会话，`Map.of().get(null)` 来自未知创建人的历史咨询。前者另有调用端未按历史索引规则 trim ID 的问题。运行日志存在 NPE，但线上页面读取被站点权限策略拒绝，不能声称已捕获截图对应请求。

咨询页面原先等待咨询历史和开发会话列表同时成功，任何一个失败均锁住所有系统。运行列表只是恢复时的忙碌提示，原咨询 WebSocket 的 ready 与实时状态才决定能否继续发送。

## 恢复边界

1. 等待本次咨询历史请求完成，不因缓存为空提前解锁。
2. 历史失败保留锁定及重试按钮；重试只重新查询历史。
3. 历史成功，复用最近待归档咨询的 `sessionId / devSessionId`；没有待恢复咨询时开放新问题入口。
4. 运行列表失败或未返回不影响上述判断；恢复仍调用原 `switchTo`，等待原连接 ready，不自动新建或重发。
5. 空 SDK ID 不判定为记录丢失；未知创建人保留为空，不删除记录、不赋予新所有者。服务端原访问过滤保持不变。

## 产品原则

适用 OBJ-01、CTX-01、FEED-01、AI-01、EVID-01、IDEM-01，无例外。主对象仍为原咨询，使用既有列表及恢复方法，无新增导航或覆盖层；失败后原位置可重试，移动端与桌面共用同一恢复流程。原会话草稿与发送 ready 保护不变，重试不能制造第二条咨询。键盘可操作既有重试按钮，窄屏没有新增布局；交互回归使用组件测试，真实浏览器验收待部署及站点读取许可。
