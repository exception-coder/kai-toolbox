## 业务定义

- **工作线**：代表一条持续的工作主线（例如某个项目、某个长期方向），是组织工作记录的最高一级容器。一条工作线有名称和说明，下面挂着若干工作条目，条目之间可以手工调整先后顺序。
- **工作条目**：挂在某条工作线下的一次工作记录，由三部分组成：
  - **标题**：概括这次工作是什么；
  - **核心内容(coreContent)**：这次工作具体做了什么；
  - **成果(achievement)**：这次工作做出了什么成果/产出。
- 条目之间存在两级层级关系（详见同模块的层级约束知识点）：顶层摘要条目代表一个相对完整的工作单元，明细子条目是该单元下更细粒度的补充记录。
- 关系基数：一条工作线对应多个工作条目（1:N）；一个顶层摘要条目对应多个明细子条目（1:N，仅两级）。

## 适用范围 / 边界

- 工作线模块面向"个人记录自己做过的工作与成果"，是单用户单机场景，没有多用户/团队协作维度，也没有指派、截止日期等任务管理属性。
- 与需求管理池（reqpool，管理"要做什么"及其状态流转）、PRD 澄清助手（prd-clarify，管理"需求怎么落地成文档"）是完全不同定位的模块——工作线不参与需求的生命周期管理，纯粹是工作内容与成果的个人记录载体。

## 备注

- 口径来源：kai-toolbox 代码调研起草，待 owner 核实。
- 易混点：workline 里的"工作线"是使用者自己命名、自由组织的工作主线概念，不对应任何外部项目管理系统里的固定实体（如迭代、看板列等），纯粹由用户自定义。
