# 文件树宽度与阅读

适用 OBJ-01、CTX-01、DENS-01、FEED-01、EVID-01，无例外。对象为 sessionId 下的 FileEntry.path；绝对路径仅使用后端已提供的 abs，不猜测目录。沿用 list / read / reveal 公共接口和懒加载，展示变化不增加扫描或写操作。

参考 [VS Code 树组件的横向滚动能力](https://github.com/microsoft/vscode/blob/main/src/vs/platform/list/browser/listService.ts)，查阅于 2026-10-14。本项目采用原生 overflow 及内容固有宽度，不接入 IDE 框架，也不宣称复制完整 IDE 行为。

侧栏仍固定在当前宽度，搜索与关闭入口不随树横向滚动。树内容使用 max-content / min-width:100%，行内文件名不省略、不换行；保留每层缩进、大小和定位操作，超宽部分只在树区域滚动，不撑宽对话或页面。手机顶部面板使用同一内容策略，限定原有高度。预览标题允许换行显示完整文件名。

文件 / 目录按钮悬停可查看 abs 或原始相对路径。滚动区可键盘聚焦，文件及定位按钮有焦点提示。展开、筛选、预览和右键添加 / 复制路径仍使用原条目；关闭预览不清空树状态。加载、空目录、查询错误及预览错误沿用现有反馈和关闭入口。没有第二份项目配置或 AI 编程架构契约变化。

浏览器使用真实 FileTreePanel 与隔离 API 的深层 Java 文件样例，验证桌面常规 / 短屏及手机横向滚动后能辨认同前缀文件名、文件大小和定位入口，预览正确文件且标题完整；页面不得随内容产生横向溢出。纯呈现改动不增加镜像 CSS 的单元测试，采用真实布局几何和交互证据。现有运行不重启，实际会话页待新版加载后核对。
