## ADDED Requirements

### Requirement: 会话记录大小以原生文件实测为准
平台 SHALL 按逻辑会话绑定的引擎句柄和授权目录读取本地记录文件元信息，汇总去重后的字节数，并明确统计范围与获取时间。平台 SHALL NOT 将共享数据库、工作目录、Token 或费用估算包装成会话记录大小。

#### Scenario: 多引擎会话与账号隔离
- **WHEN** 逻辑会话绑定多个引擎记录，且 Codex 使用独立授权目录
- **THEN** 平台仅汇总这些绑定的文件，分别显示各引擎的统计状态，不读取其他账号同 ID 的记录

#### Scenario: 未知与零字节区分
- **WHEN** 记录尚未生成、已缺失、引擎未适配或部分文件读取失败
- **THEN** 平台明确显示相应状态，部分已知字节不能显示成完整总量；只有已确认归属的空文件或空的独立会话目录才允许显示 0 B

### Requirement: 大小查询不阻塞会话使用
平台 SHALL 使用有权限校验的受限批量只读查询，不读取消息正文，且 SHALL 保留切换会话、输入与发送操作的可用性。

#### Scenario: 缓存及晚到响应
- **WHEN** 用户切换会话或授权目录，或旧查询稍后返回
- **THEN** 展示数据按用户、会话与原生定位身份匹配，不串用旧会话大小

#### Scenario: 文件边界与失败恢复
- **WHEN** 存储路径通过链接越界、扫描超限或查询失败
- **THEN** 平台返回可观察的未知/部分状态，前端可重试，不读取跨界文件或执行清理
