# 最近会话看板设计

## 范围与证据

会话名单来自 `listSessions`，访问策略已在服务端过滤；`lastSeenAt` 是已有活动排序字段。队列保存在 `claude_chat_queued_message`，由现有 `listQueuedMessages(sessionId)` 返回，不使用当前浏览器 `chat.queued` 推断其他会话。现有“推进”是 OpenSpec 自动监督看板，本看板负责最近开发会话与用户待发送任务，两者范围不同。

本次不改变工程上下文、治理、Agent 执行或验证生命周期契约，无需更新 AI 编程架构正文。Graphify 查询因现有图文件超过加载上限不可用，代码事实通过定向源码和当前接口补齐。

## 用户任务与页面构成

使用者为开发者；首屏回答“最近在做什么、哪些还在运行、哪些尚有消息没有发送”；发现后进入对应会话核对或处理队列。

Page Anatomy：现有全局导航 → 会话视图页签 → 看板标题/刷新 → 状态筛选 → 会话明细。密度采用 Compact，便于比较 20 个会话；桌面用列对齐的行，手机用同一明细行的纵向排版。看板内容区是唯一纵向滚动容器，输入区在此视图隐藏但草稿保留，手机首屏直接出现最近会话。

| 判断 | 展示方式 | 行动 | 选图决定 |
|---|---|---|---|
| 最近工作的先后 | 标题、项目与真实活动时间的倒序列表 | 进入会话 | 不画趋势；没有工作量历史口径 |
| 哪些仍在运行 | 运行状态文字与进行中筛选 | 进入运行会话 | 不画份额；用户要定位具体对象 |
| 哪些队列尚未发送 | 条数与队首任务摘要；空闲队列同样保留 | 进入会话处理 | 不画积压图；明细本身即可回答 |
| 数据未取得 | 加载、部分失败与上次更新时间 | 重试 | 不以零值补齐未知 |

## 数据与查询

- 最近集合在共享名单上纯投影：排除业务咨询和 `planExpired`，按 `lastSeenAt DESC, id` 稳定排序，取 20 条，然后做看板筛选。收藏不改变顺序。
- 进行中依据 `status === RUNNING && live`；RUNNING 但不 live 是待恢复；IDLE、DONE、INTERRUPTED 分别显示既有状态含义。不能据此声称队列必然自动执行。
- 队列缓存键包含当前账号 ID 和逻辑会话 ID。每条请求独立成功/失败，服务端返回的 `sessionId` 必须与请求目标一致。仅投影数量、显示文本、附件数量及创建时间，不展示隐藏指令。
- 每行显示前三条任务，摘要最多 160 字；标题可从完整会话名称区分工作。未核对队列在待发送筛选中保留，并明确说明，不误导为已确认有任务。
- TanStack Query v5 提供多查询与 AbortSignal，遵循 [useQueries](https://tanstack.com/query/v5/docs/framework/react/reference/useQueries) 和[查询取消](https://tanstack.com/query/v5/docs/framework/react/guides/query-cancellation) 官方契约，保持 Query 层为服务端数据唯一缓存。
- 复用现有接口，新增最多 20 次有界队列读取；同一时刻最多 4 次，每次 8 秒超时，退出取消。首次会话名单立即显示，队列渐进补齐；正常每 15 秒刷新队列，隐藏页面不轮询。不读 20 份 transcript 或逐行请求 Sidecar 运行态。
- 当前名单只读样本为 190 条；20 个队列、并发 4 的本机 HTTP 测量为 487ms，最慢单次 144ms，全部成功，队列样本为空。该测量不代表公网手机或大队列的端到端性能。单行现有接口约为权限/会话校验/队列各一次 SQL，最坏 20×3 次；不新增 SQL 或索引。若规模扩大，另行提供集合摘要接口，不默认扫描全量队列。

## 产品原则与交互

适用 OBJ-01、NAV-01、CTX-01、DENS-01、FEED-01、AI-01、EVID-01、CTRL-01、IDEM-01。

1. 主对象是现有逻辑会话，身份为账号与 `session.id`；名单和队列均复用公共 API，不创建平行会话状态。
2. 用户明确需要跨会话比较，因此在现有会话工作区增加稳定信息页签；这是 OBJ-01 的跨对象工作区例外，不另建第二套项目列表。“推进”仍专注于规格监督。
3. 打开、筛选和刷新仅查询；原会话与草稿保留。成功、加载、部分失败、过期缓存均明确；空列表或筛选无结果提供返回全部/重试。
4. 原生按钮与清晰焦点样式支持键盘，手机无横向溢出或浮动操作遮挡标题；打开目标会话后回对话视图，保持既有恢复规则。
5. 重复点击复用查询缓存，刷新不创建或执行任务；按会话 ID 关联晚返回的数据。

## 验证

集中执行最小充分验证：最近集合/会话归属/并发取消风险的定向测试，真实组件的筛选、进入和失败恢复，前端类型检查、该 change 严格校验与 Forge 门禁。浏览器核验桌面和手机、末条可达与进入目标会话；观察当前前端至少 60 秒。不运行共享 SDK 发布构建，不重启服务，不重复全套测试。
