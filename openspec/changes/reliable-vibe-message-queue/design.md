# 可靠消息队列设计

## 普通开发任务等待用户决定（2026-11-27）

普通开发轮次用原回复末行回执表达回答已完成、任务已完成、任务未完成或待用户确认。Sidecar 在持久保存轮次结果前识别回执，Java 按原轮次身份核对回执和引擎的安全终态。模型自报仅是完成声明。未完成、待决定、缺少回执或断线无法确认结果时，保留原任务及发送记录，阻止后续自动派发。恢复只读核对原轮次，不另发完成核对消息。已明确未接收的首次派发仍按原消息身份有界补投。

沿用 OBJ-01、CTX-01、FEED-01、AI-01、EVID-01、CTRL-01、IDEM-01。原生交互可在原轮次等待用户回答或授权。轮次已结束时，通过原会话回执说明待决定的问题，队列提供用户确认原任务完成后的恢复入口，并复核引擎空闲。已有自动追问记录仅兼容显示和隔离，不能替原任务放行。用户主动启用的 OpenSpec 监督执行有独立规则。无需新增表，后端及 Sidecar 按同一版本交付。

## 入队写锁竞争（2026-11-23）

用户报告入队 INSERT 抛出 SQLITE_BUSY。save 原先在 DEFERRED 事务中先读会话与队列，再写入；并发写入会使 WAL 读快照无法升级，busy_timeout 不能修复旧快照。save/clear 现于首次读取前执行零行 UPDATE 取得写入资格，不改变数据；竞争者使用既有 5 秒 busy_timeout 等待后再读取最新数据。保留原事务、撤回保护与相同 ID 原文复用，不增加内存接受队列，不在落盘前回报成功，也不串行化不同会话的模型任务。

运行现场的具体锁持有者未捕获，长期持锁超过等待期限仍明确失败。DDL 未核验：prepare_sql_context=DDL_MISSING（扫描上限），资源目录没有 Forge SQLite 绑定；列名依据源码，不修改表结构或运行库数据。真实 WAL 文件、多连接 12 条并发入队及幂等/撤回测试通过，服务尚未重启加载。

## 输入发送后的原文恢复（2026-11-23）

沿用 OBJ-01、CTX-01、FEED-01、CTRL-01、IDEM-01。主对象仍为 sessionId，恢复记录使用发送时已有 messageId，按当前登录用户及会话隔离保存于本机浏览器。清空草稿及发出请求前同步保存完整原文和已上传附件引用，存储失败则保留输入并提示未发送。服务端 sendAccepted 回执只更新为已接收，轮次结果与发送失败分别更新状态。排队保存失败也保留原文。新建会话的首条自动指令等待目标身份确认后提交，拒绝提交时复用目标会话草稿。

消息列表的“发送记录”打开既有抽屉，显示时间、原文、附件及已知状态，提供复制、恢复到输入框和删除本机记录。恢复追加到现有草稿，复用原附件引用，用户自行核对服务端队列及实际执行结果后手动发送。刷新后未收到回执的记录显示结果待确认，已接收不推断为执行完成，不以该记录触发自动重放。原有同页断线待发逻辑仅补发尚未成功写入连接的消息。浏览器记录不能代替服务端队列、引擎历史或运行状态，不能恢复修改前已经丢失且未记录的内容。

每条消息独立写入，避免多个标签页覆盖彼此的原文。新消息到来时清理较早的正常结果备份，未确认和失败原文由用户删除。附件不保存短期 blob URL 或文件内容，跨刷新通过现有服务端路径恢复。更换浏览器或清除站点数据后不承诺恢复。窄屏使用原抽屉单滚动区，键盘和关闭焦点由现有 Sheet 处理，实际浏览器验收单独记录。

## 忙碌期间接单与拒收恢复

「中台测试环境」会话的持久记录显示，11 月 27 日 00:35:44 提交的消息已进入 Codex。原生执行从 00:36:36 到 00:37:00，Sidecar 在 00:37:01 持久保存完成回执。00:36:57 的再次发送被状态校验拦下，00:37:05 的再次发送遇到 Java 忙碌。之后的完成核对在 00:37:47 获得完成回执。首条发送记录仍为已派发，和 Sidecar 完成回执有差异。现存证据未覆盖首次拒收瞬间的 Java 与 Sidecar 状态。

派发登记和发出命令期间持有会话锁。巡检在该锁内读取期望轮次，在锁外查实时状态，处理前再次核对。Sidecar 明确拒收且查无接收回执时，只在会话空闲、回执存储代际一致的情况下使用原轮次标识有界重投队首。核对轮本身被拒收时保留原任务待人工确认。已有匹配轮次的旧结果可更新自己的发送记录，当前轮次和放行条件由现有生命周期负责。

适用 OBJ-01、CTX-01、FEED-01、CTRL-01、IDEM-01，无例外。普通 HTTP 接单碰到已登记的活动轮次时，原会话的稳定消息 ID 和附件进入既有队列，队列项和接单状态同事务提交。用户在原会话的发送记录及队列看到等待状态，可使用现有的删除和恢复入口。原有抽屉的键盘、关闭焦点和窄屏交互继续适用。跨会话的相同消息 ID 不得覆盖其他会话队列项。没有在途轮次证据的发送异常仍保留原文供核对。无需迁移现有数据。

## 对象、范围与交互

适用 OBJ-01、CTX-01、FEED-01、AI-01、EVID-01、CTRL-01、IDEM-01，无例外。主对象仍是 sessionId，队列项 messageId 与当前执行 turnId 分离；不增加页面或导航。复用队列列表，显示执行、追问次数、挂起原因和“已核对，继续队列”。键盘使用原生按钮，窄屏原因换行；真实浏览器检查及运行启用单独记录，不能以预览入口代替验收。

## 状态与一致性

SQLite 原队列保存输入，新 runtime 表保存当前轮次、完成准入、原任务文本、追问次数及阶段；delivery 表保证同一会话最多一个在途队列项。认领与关闭准入在同一事务，正常终态与删除原文在同一事务。每次新任务重置追问次数，重启/刷新同一任务不重置。新建表通过应用 SchemaInitializer 幂等创建，不交付人工执行脚本。

Sidecar 回执保存在当前本机用户数据目录，每端口独立文件；只存轮次元数据，不复制消息及凭据。接收记录 fsync 后才开始执行，终态落盘后再广播；重复轮次返回旧回执。最多保留 2048 条，优先裁剪已完成记录并更换证据代际；全为未收口记录则拒绝新输入。损坏文件不得静默当空文件。

原文直到确认完成前保留。FAILED/UNKNOWN 保持队列暂停，恢复只核对原轮次和持久回执。取消/中断、待确认授权、后台任务及内部 OpenSpec 监督消息保持各自语义。

巡检串行、每批 16 项，网络查询在会话锁外，返回后对比持久轮次防止迟到快照覆盖新任务。进程停止关闭 worker。有持久队列时，首次巡检沿用现有 SidecarProcessRegistry 受管懒启动，应用启动周期仅尝试一次，不等待浏览器先打开。随后只尝试有界连接已监听的 Sidecar；启动失败保留输入，不形成巡检重启循环。恢复保留原 native session 与引擎/服务商/模型/权限，不能创建随机原生会话伪装恢复。所有真正开始工作仍经过 admission gate 和项目访问检查；确认继续前反查真实空闲，并核对查询期间任务未变。

## 历史记录：完成核对的状态显示修复

2026-11-11 续接采用 L2：修复既有模块的状态反馈和兼容快照，保留原准入、暂停/删除、回执及安全放行规则，不修改数据库、权限或原生 SDK。适用原则仍为 OBJ-01、CTX-01、FEED-01、AI-01、EVID-01、CTRL-01、IDEM-01，无新增导航与例外。主对象是 sessionId，核对轮是既有持久 turnId。

`result → queueCheck → assistantDelta` 必须形成前端新轮次：收到结果关闭上一轮，只有 Sidecar 接收当前核对轮后广播 `queueCheck`，前端据此解除终态门闩。准备派发不等于接收，发送异常保留 UNKNOWN 及原文。`ready.queueCheck` 从现有 runtime 与当前轮次恢复已接收核对进度，避免断线缓冲被淘汰后退回泛化“正在运行”。已结束轮次的重复核对与旧结果不得影响当前新轮。公开评审投影继续剔除核对元数据。

前端以状态事件递增的查询代次隔离 HTTP 快照，结束、核对、审批/回答、中断回执和后台任务变化立即换代并取消旧请求。相同渲染批次中 running 先结束后再次运行也不能复用旧查询。顶栏、专注阅读、底部状态栏共享执行状态投影，历史结果仅在权威空闲后补充展示；发送门禁继续由后端决定。

回归覆盖同轮接收去重、手动任务无 delivery 行、派发失败、恢复快照、迟到请求、快速连续轮次、审批/收口与断线。沿用既有键盘、焦点及窄屏结构，不自动发送真实用户消息。源码、构建、质量探测和新版本浏览器/模型验收分开记录；本次未获重启授权。

## P1：原生状态与失败恢复

### 普通消息服务端接单补充（2026-11-23）

故障证据：`useClaudeChatSocket` 在普通发送时先显示临时用户气泡，未连接时仅加入 `pendingSendsRef`；切换会话会清空这份前端待发数组。服务端原 `sendUserMessage` 先恢复引擎与检查运行态，再进入 `startTurn`，因此接单前的初始化异常没有独立原文记录。原生历史尚未写入时，切回会话无法证明消息已提交。本次覆盖接单窗口，不将历史已丢失内容声称为可自动恢复。

本机备份不能替代服务端所有权。普通开发与有回复权限的共享会话使用固定 sessionId 的 HTTP POST `/submissions`，按原会话交互权限校验。原文和附件引用写入 `claude_chat_submission` 后返回 202，独立虚拟线程沿已有门禁启动轮次；不依赖 WS 观察者或当前 attach 归属。缺失运行上下文、忙碌、启动失败均保留记录及原因，不把拒绝说成正在执行。`(session_id,id)` 幂等，同 ID 不再次派发或覆盖原文。按真实 turnId 记录结果，服务重启只标 UNKNOWN，不自动重放。列表最多返回最近 100 条，后台数据不裁剪。恢复只写草稿，仍需用户核对后发送。咨询、公开评审、语音及运行中 steer 保留原协议，普通排队仍由原持久队列拥有。

适用 OBJ-01/CTX-01/FEED-01/CTRL-01/IDEM-01：沿已有发送记录入口展示服务端状态，无新导航；切换不撤销已接单工作，失败原文可复制恢复。新表由本模块 schema 初始化；prepare_sql_context 返回 DDL_MISSING（新增表且扫描达到上限），DDL 未核验，不证明运行库已部署。使用实际 schema 的 SQLite 测试验证契约，不执行运行库写入。新版本部署及浏览器验收单列。

继续沿用 L2 和以上交互原则。Codex Adapter 接收 `thread/status/changed` 的等待审批、等待回答、空闲及系统错误；Claude Adapter 开启 SDK 原生 `session_state_changed` 事件，并接收 `api_retry`。仅观察当前根会话、当前 Forge turnId，子线程及迟到旧轮不覆盖当前状态。原生 idle 只是执行证据，不能直接释放队列；已有 TurnLifecycle 仍等待结果和原生进程清理结束，后台任务、暂停及中断规则不变。不改变 SDK 后台子任务等待策略。

原生观察通过既有 `engineEvent` 协议的 `engine.status` 事件通知，运行快照携带 `nativeStatus`。前端只触发当前代次刷新，由后端聚合为等待回答、自动重试、收口或引擎异常。原生提供次数时显示次数，不推测重试总数。旧版本或未提供状态的引擎保留既有状态路径。

结果附带可选失败类别及短错误代码，按额度/限流、上下文、鉴权、网络/服务、请求/工具、拒绝、执行上限、未完整完成分类；没有结构化证据时保留未知。不根据助手自由文本猜测错误，不透传原始请求或凭据。成功、中断、用户暂停和未入队保持独立。分类是恢复提示，不改变完成核对、回执及队列放行规则。

最新失败轮复用消息详情、草稿、会话配置和同目录新建会话入口。压缩指令仅在引擎广告支持时出现，核对重试与调整需求写入草稿，不自动重发。次数上限或未完整完成可由用户点击继续，并再次通过现有发送门禁；运行中或出现新用户任务时不展示旧轮恢复操作。公开评审仍剔除技术元数据。历史原生记录缺少结构化错误代码时显示未知，不新建失败数据库。

验收覆盖原生 idle/result 两种到达顺序、子线程隔离、自动重试不中断、失败分类透传、迟到事件隔离、手机/桌面失败恢复与现有 Codex 生命周期/配置回归。构建在 Sidecar 隔离目录进行，禁止覆盖运行中 dist；新版启用和真实模型/浏览器验收仍须本次重启授权。
