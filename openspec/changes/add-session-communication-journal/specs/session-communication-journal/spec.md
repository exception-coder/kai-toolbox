## ADDED Requirements

### Requirement: 会话保存多条原始沟通记录

系统 MUST 以服务器会话身份保存多条带稳定 ID 的沟通记录，并分别保留原文、截图及用户整理备注。记录 MUST 遵守现有会话访问与规划锁定规则，不自动启动模型。

#### Scenario: 保存并回顾
- **WHEN** 用户在当前会话填写沟通主题及原文或图片并保存
- **THEN** 记录在该会话流水中可搜索、按沟通时间排序和再次读取，切换其他会话不显示原会话资料

#### Scenario: 重试与并发修改
- **WHEN** 创建请求超时后重试相同 ID，或不同客户端同时编辑
- **THEN** 相同创建意图复用已保存记录；不同内容的过期版本返回冲突，保留编辑草稿并允许重新读取

#### Scenario: 移除及恢复
- **WHEN** 用户移除记录后查看已移除列表并恢复
- **THEN** 原文与图片仍然存在，恢复后重新出现在正常流水列表

### Requirement: 资料引用由用户确认

系统 MUST 允许用户选择多条流水并引用到当前会话草稿，保留来源、时间、原文与整理备注的区别及相关图片。引用 MUST 不覆盖已有草稿、不自动发送、不自动变更规格。

#### Scenario: 引用多条沟通
- **WHEN** 用户选择当前会话多条记录并引用
- **THEN** 草稿追加可追溯资料与图片，用户可在发送前检查；其他会话资料和未选择记录不进入草稿

#### Scenario: 上传或读取失败
- **WHEN** 图片上传或流水读取失败，或操作期间会话切换
- **THEN** 保留原对象草稿并提供原位重试，迟到结果不能污染新会话，未完成保存不得显示成功
