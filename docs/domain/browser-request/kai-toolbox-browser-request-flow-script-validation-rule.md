## 业务定义

"AI 用例"允许用自然语言描述一段浏览器操作，由 LLM 生成一段结构化的动作脚本，但该脚本在被允许执行之前，必须先通过代码侧的确定性校验，体现"模型只负责提议、代码负责裁决"的原则：

- **动作类型白名单**：脚本中每一步的动作类型必须落在受支持的动作集合内（打开页面、填写、点击、按键、滚动、等待、断言这几类），出现集合之外的类型即判定整段脚本非法。
- **各类型必填字段**：不同动作类型有各自的必填信息，例如打开页面必须给出目标地址，填写必须同时给出选择器与要填写的文本，点击/等待必须给出选择器，按键必须给出按键内容，滚动必须给出滚动距离或目标选择器二选一，断言必须给出具体的断言方式（如网址包含某片段/某选择器可见/某文本存在）及对应的校验值。任一步缺少对应必填信息即判定该脚本非法。
- **强制断言要求**：一段动作脚本里必须至少包含一个"断言"步骤，否则即便前面的操作步骤本身都合法，整段脚本也判定非法——因为没有断言就无法用确定性的方式判断这段脚本执行后是否达到了预期效果。
- 脚本一旦通过校验被确认保存，后续执行走纯确定性回放；只有当回放失败时才会带着失败上下文回到 LLM 重新生成/修正脚本。

## 适用范围 / 边界

该校验只用于"AI 用例"这条自然语言生成脚本的通道；用户直接手工编排的普通请求回放任务（见 record-replay-flow）不受这套动作类型/断言约束。LLM 原始输出即便包裹了多余的说明文字或代码块标记，也会被代码侧提取出其中的脚本数组部分再校验，但提取不到合法脚本数组本身也视为非法。
