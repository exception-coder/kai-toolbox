# 设计

## Page Anatomy

保留单行 Header → 唯一消息滚动区 → 单行 Dock → Composer。单条消息组织为角色与时间 / 轻量内容块 / 原文小节 / 原有详情展开；手机更多与角色同一行，不再独占操作横栏。先区分信息单位，再区分信息层级。

主对象是原 session ID 与 ChatItem ID，既有虚拟列表、加载、跳转、工具偏好不变。适用 OBJ-01、CTX-01、DENS-01、FEED-01、EVID-01、CTRL-01，无例外。尊重用户明确要求的轻量消息区块；不增加多层卡片，小节只用排版与分隔。

## 呈现与事实边界

- 主 Coding MessageList 增加局部层次类，使用现有 color-background / color-card / color-border / color-primary，保留明暗、暖色与材质偏好。手机正文 15px / 1.5、标题 16px，小头像 24px，弱边界和 10px 圆角，无阴影。验证小节只加弱色竖线，不使用绿色暗示通过。
- AssistantReply 继续使用 Markdown，replySections 从已有 heading / 独立标签投影原文小节；不重写正文、不抽取推定标题、不猜测执行状态。流式保持单一完整 Markdown，完成后才分层。
- 原有手机长文 preview 与 details 保留，关键变化、验证及风险仍留在概览。共享引用式链接定义时回退整段 Markdown，避免按小节渲染丢失链接上下文。复制使用原始全文，代码、图片和本地文件访问继续使用现有能力。
- 不新增 JSON 消息协议或通用跨 Agent 框架：当前引擎输出是 Markdown，本次只建立可复用的现有消息呈现层。

## 操作与恢复

手机角色 / 时间 / 更多同一行，菜单包含复制、原有分叉及转卡片；无分叉锚点不提供分叉。Esc 与操作后关闭恢复触发器焦点。复制失败显示原位重试，不关闭菜单或丢失全文。桌面悬停 / focus-within 显示原操作；触屏宽屏仍显示，键盘不被隐藏操作困住。减少动画偏好与强制颜色保留。

不添加新加载或保存流程，原错误、附件重试、轮次状态仍由原组件承载。图片不能成功时不伪装生成成功。会话切换、滚动 key、列表分页与输入草稿不改。

## 验证

复用消息手机与历史回归，补复制失败重试 / 全文与引用链接保护。运行 frontend typecheck 与一次生产 Vite 构建、项目质量门禁。真实浏览器检查 390×844、360×640、桌面、明暗主题、小节 / 展开 / 更多 / Esc、横向溢出和末项可达。当前实际会话浏览器需要登录，使用生产组件隔离页验证时单列限制，不声称真实会话验收完成。
