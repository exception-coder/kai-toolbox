# 设计

适用产品原则 NAV-01、DENS-01、CTX-01、FEED-01。主对象是现有 Vibe Coding 模块和其会话；入口仍指向 manifest 中的 `/tools/claude-chat`，不创建第二套会话或菜单目录。

React 挂载前，首页 HTML 根据同源已缓存的登录、权限及菜单可见性显示分组功能入口，不再以“正在准备工作台”挡住菜单。元数据由现有菜单目录生成器从 FeatureManifest 同步到 HTML，复用 `hasFeatureAccess` 和菜单合并迁移规则编译出的独立内联脚本；不加载 React、业务模块或等待 API。隐藏模块、chrome 管理页、showcase 展示页不进入此导航；生成目录检查同时检查 HTML，禁止手工维护第二份菜单。缓存仅用于导航展示，主应用接管后继续同步账号权限和菜单偏好。无快照、快照损坏或无权限时不展示受保护入口；最终访问仍由现有路由守卫和服务端鉴权决定。链接可用键盘聚焦，窄屏单列且可滚动；十秒未接管显示“重新加载”。入口仍为同一对象和路由，重复点击不创建业务数据。

React 首页一次显示全部已授权且未被用户隐藏的入口，Vibe Coding 保留优先位置，不再额外等待浏览器空闲。命令面板及视频搜索依赖首次触发 Ctrl/⌘+K 或搜索按钮时加载。失败会输出诊断日志，后续触发可重试。重复点击快捷入口仅导航至同一现有路由，不产生写操作。用户切换页面后沿用路由及会话恢复规则。

验证需覆盖生产构建、OpenSpec 校验、权限快照分支、键盘入口和真实手机从 HTML 响应到可交互的时间。构建成功不代表真实手机秒开；当前较大的公共启动包仍需单独测量。
