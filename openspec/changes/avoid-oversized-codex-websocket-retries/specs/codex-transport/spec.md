## ADDED Requirements

### Requirement: 大上下文必须在发送前选择兼容传输

Forge SHALL 在官方 Codex 主轮次和续问预测开始前，基于当前有效原生上下文与本次输入选择传输。达到已验证消息限制的保守预算时 SHALL 使用 HTTPS，保留原生鉴权、内容、线程身份及错误处理。

#### Scenario: 大图片历史中的连续短消息
- **WHEN** 历史图片使当前上下文达到预算，用户连续发送两条短消息且每轮进程重新创建
- **THEN** 两轮均在执行前选择 HTTPS，不为相同的大历史先耗尽五次 WebSocket 重试
- **AND** 不裁剪历史图片、重写凭据或重放业务轮次

#### Scenario: 小会话或压缩后体积回落
- **WHEN** 新会话或最新压缩后的有效上下文低于预算
- **THEN** 保留或恢复原生 WebSocket 策略，不依据累计文件大小、token 数或其他账号的失败全局禁用 WebSocket

#### Scenario: 预检失败或不适用
- **WHEN** 原生历史不可读、配置冲突、读中变化，或提供商不属于适用范围
- **THEN** 不覆盖用户配置，失败保留可观测记录，继续由原生执行逻辑报告真实结果
- **AND** 不将预检失败当成业务成功或自动重放依据

### Requirement: 恢复必须有界且避免回传完整历史

Forge SHALL 使用仅返回元数据及实时状态的恢复与分叉方式，保持原生历史和模型上下文；恢复使用独立有界预算，取消仍受进程退出与队列保护契约约束。

#### Scenario: 大历史恢复超过普通 RPC 时间
- **WHEN** 恢复耗时超过普通 20 秒 RPC 预算，但未超过恢复的 120 秒上限
- **THEN** 保持当前恢复，不因普通 RPC 预算而提前切换 SDK
- **AND** 主轮次与预测恢复均不要求返回全部轮次历史

#### Scenario: 用户在恢复过程中取消
- **WHEN** 用户在尚未提交 turn/start 时取消
- **THEN** 中断恢复并清理本轮所属进程，不等待完整恢复预算，不启动或重放模型轮次
- **AND** 未确认退出时继续保持原有清理屏障

#### Scenario: 完成后读取最新分叉锚点
- **WHEN** SDK 轮次完成，需要读取最新原生 turn ID
- **THEN** 倒序最多读取一轮且不加载消息 items，不再要求全历史响应

#### Scenario: 终态通知丢失后的对账
- **WHEN** 已出现回答但未收到终态通知，需要核对原生轮次状态
- **THEN** 倒序最多读取一轮且不加载消息 items
- **AND** 只有匹配当前 turn ID 的真实终态能够进入原终态处理；其他轮次完成不能释放当前队列

### Requirement: 安全回退必须继承本轮传输选择

Forge SHALL 在原有安全回退条件下，将已选择的传输配置交接给本轮独立的 SDK 客户端；不得将大上下文 HTTPS 选择丢失到 SDK 默认策略或泄漏给其他会话。

#### Scenario: 已选 HTTPS 后恢复失败
- **WHEN** 官方 App Server 已为大上下文选择 HTTPS，恢复失败且确认原进程已退出，轮次符合安全回退条件
- **THEN** SDK 使用相同 HTTPS provider 及原生鉴权，并保持当前权限、MCP 和开发约束
- **AND** 后续其他小会话继续依据自己的配置和体积选择传输

#### Scenario: 初始化早于传输选择失败
- **WHEN** App Server 尚未取得传输选择，且符合安全回退条件
- **THEN** SDK 在模型执行前重新通过只读配置和所属历史元数据进行相同预检
- **AND** 自定义 provider、预检失败仍遵守原有不覆盖和可观测契约

#### Scenario: 原生没有提供关闭码
- **WHEN** 原生只报告 stream disconnected 或 websocket closed，而未提供关闭码
- **THEN** 诊断记录错误类别、执行路径及可用的上下文估算，关闭码为未知
- **AND** 不把估算体积或历史事件当成本轮真实 1009 证据，不记录消息、凭据或配置正文
