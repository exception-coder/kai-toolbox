# 专注模式与个人偏好

## 控制点

ChatPage 保留原 MessageList、Composer 和 runtime 实例，专注状态只切换展示；导航、监督条、运行状态和用量条由局部 data-focus-chrome 隐藏，停止生成及权限/问答对话框仍可操作。当前分屏/视图/附属面板在进入时记录，退出时恢复；草稿与附件不重置。顶栏 portal 在专注时归还页面内部，避免逃逸全屏；浏览器原生全屏使用现有 fullscreen portal 容器。

桌面优先 requestFullscreen，不支持或拒绝时使用 fixed 视口布局；手机使用窗口内专注，避免原生全屏与输入键盘/H5 容器争用视口。返回图标、Esc 和原生 fullscreenchange 收敛为同一退出逻辑，退出后焦点返回会话工具且不滚动页面。其他弹窗与输入菜单先消费 Esc；不将专注状态持久化。窗口降级时背景兄弟节点 inert，退出恢复原值，避免键盘进入不可见导航。

## 个性化

工作区个性化位于会话工具的“系统 · 设置”。最近会话默认状态存于当前浏览器 localStorage；缺失或不可读时默认展开，保存失败明确告知且不伪装成功。useSyncExternalStore 订阅同页事件和跨页 storage，已挂载侧栏立即应用；点击最近会话标题只做临时展开/收起，刷新或重新挂载回到偏好。无需另建服务器配置或项目数据。

## 交互与边界

应用 CTX-01（恢复视图/焦点/草稿）、DENS-01（对话优先）、CTRL-01（显式退出及浏览器降级）、FEED-01（保存失败可恢复）、OBJ-01（保留会话身份）。无原则例外。手机保留至少 44px 退出/设置操作区及安全区；MessageList 保持原滚动归属。不重启服务，不启动任务、不更改监督或生产授权。

## 验证

## 专注阅读布局

应用 CTX-01、DENS-01、CTRL-01、OBJ-01，无原则例外。专注视图保留消息列表与输入组件实例，以局部 CSS 和语义类切换布局，不改变普通聊天、草稿、附件、停止生成或权限弹窗。正文和输入 surface 使用同一中轴：860px 内容宽度加两侧 12px 留白；用户可显式扩展为 960px，手机按可用宽度收缩。宽度按钮仅改变展示，不触发模型请求。

顶部为 48px 单行导航（安全区另计），只显示返回图标、可截断的会话标题、实际连接/运行状态和更多。取消专注页头独立的 OpenSpec 查询与未绑定提示，规格管理保留原工作台入口。宽版阅读只在至少 984px 可用视口的更多菜单显示，确保可以容纳 960px 正文与留白；运行详情从菜单返回原工作台的既有轨迹视图，不复制管理工具栏。助手正文取消背景卡片、边框、阴影和头像框，保留角色时间，用户消息靠右采用中性底色；局部选择器必须覆盖后加载的移动聊天样式。轮次完成保留相邻的紧凑详情入口，失败仍醒目；运行状态复用原 Dock 放在输入框上方，不再放列表 Footer，空闲/正常完成且无队列时收起 Dock 摘要。队列、异常与待处理确认仍可发现。长代码和表格在列内滚动。

进入/退出前捕获可见消息身份和相对视口偏移，布局提交后通过 Virtuoso 公开 scrollToIndex 恢复；贴底时继续定位末项，分页到达使用当前消息索引，跨会话的旧恢复无效。不为切换模式改列表 key、新建连接或重置草稿、附件与任务。输入框复用现有随内容增高逻辑，专注时收起低频配置按钮。局部 VisualViewport 高度/offsetTop 监听处理键盘与视口变化，退出清理，不改变全局 Shell 或强制接管用户缩放。此取舍依据 [Chrome 键盘视口说明](https://developer.chrome.com/blog/viewport-resize-behavior) 与 [VisualViewport 文档](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)；Android Chrome 与飞书 H5 的实际输入、缩放和安全区仍须分别验证，桌面模拟不作替代。

个性化入口已经归入“系统 · 设置”，专注模式位于“视图”。本次无后端、数据库或 AI 架构契约影响，无需服务重启。静态实例沿用既有已提交前端构建与版本提示，不强制刷新用户正在编辑的页面。

单元覆盖草稿 DOM 保留、背景不可聚焦及恢复、Esc、全屏拒绝降级、偏好跨挂载持久化和存储拒绝。浏览器核对桌面/手机、全屏/窗口降级、设置与刷新。在线服务不可用时保留明确限制，隔离验证不宣称生产会话验收。
