## Goals / Non-Goals

目标：现有约 1 GiB 会话冷读低于 20 秒，后续分页不再扫描整个文件；用量与历史共享索引。保留 before/limit、h 序号、工具配对、用量计算及 review cwd 起点。

不改变前端、模型配置、原始日志、数据库和其他引擎；不引入新的索引数据库或缓存依赖。

## Decisions

- 在 claude-chat service 内新增聚焦的 Codex 历史索引读取器。SessionHistoryService 只负责引擎路由。将现有轮次和用量聚合提取为同模块共享能力，保持统计口径。
- 冷读用 Jackson 流式 token 解析跳过不展示的巨大 content/arguments/output，仅保存显示项的位置、工具输出位置、时间及合成 result。按页随机读取正文，避免为完整 rollout 构建 JSON 树和消息正文列表。
- 按规范化真实路径与 review cwd 缓存有限数量索引，同一索引同步更新；历史和用量共享索引，已有文件只从完成的记录位置继续读取。
- EOF 的未完成 JSON 保留到下次重试；完整坏行跳过并记录诊断。截断、同长度修改、文件身份改变、首尾校验段改变时重建。追加检查固定大小的文件校验片段，无全文件哈希。
- 尾轮 result 为读取时快照，不提前永久加入索引；下一轮开始才落定，保留旧序号和工具调用跨轮回填。
- 缓存仅在进程内，不写含会话内容的旁路文件。相比持久化索引，减少迁移和损坏恢复复杂度；代价是进程重启或缓存淘汰后冷建一次轻量索引。

## Risks / Trade-offs

- 冷建仍顺序扫描文件字节 → 跳过巨大字符串分配，真实 1 GiB 文件计时验证；不宣称无限大小都有固定延迟。
- 外部任意就地修改无法靠有限校验识别所有情况 → 基于 Codex append-only 文件约定，验证常见替换/截断/改写，固定样本用于识别伪追加。
- 文件在读取中变化 → 锁覆盖快照与物化，对快照限制长度，下一次吸收追加，IO 错误不伪装空历史。
- 超大单条工具正文仍需原样返回 → 本次不截断或改变内容契约，索引不缓存正文。

## Migration Plan

无持久化迁移。先回归当前消息语义与新增边界，再对用户文件只读测量冷页、热页和用量；运行 Forge 全量门禁。回滚仅还原本 change 的 Java 变更，原始会话不受影响。
