## 业务定义

- **开销 vs 待办**："开销"类目专指用户已经实际花掉的钱；只是计划要花、还没花的钱（如"要买牛奶"）属于"待办"，不算开销。
- **账号密码不可拆分**：账号、密码、API key、登录凭据等信息一旦被识别为"账号密码"类目，必须整条记录保留、绝不可再拆分成多条（哪怕它包含账号 + 密码 + 备注等多个信息片段）。
- **记录拆分总原则**：一段输入里如果明显包含多件互不相关的事，才拆成多条独立记录（如"买牛奶；明天开会；打车38元"应拆三条）；但同一件事情的多个细节（如一条账号密码记录里的账号/密码/备注，或同一件事的时间+地点+备注），始终算作一条记录，不能拆开。
- **金额兜底抽取**：分类落在"开销"但结构化抽取没给出具体金额数字时，代码侧会从原文按"数字 + 货币线索词（元/块/¥ 等）"的模式再抽一次金额，避免开销记录金额缺失；这一兜底只对"开销"类目生效，其余类目不做金额兜底抽取。

## 适用范围 / 边界

这套分类与拆分口径只用于"记录态"文本 → 结构化解析这一步（见 capture-flow），不影响用户在界面手动编辑分类的自由度。金额兜底抽取要求原文中带有明确的货币线索词或货币符号，纯数字（如时间点"3点"、路线编号"38路"）不会被误抽为金额。
