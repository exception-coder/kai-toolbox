## 业务定义

账号管理是"管理员管别人"的功能：ADMIN 角色可以停用/启用、重置密码、删除、改角色其他账号。但有一条硬性例外——**任何管理员都不能对"自己当前登录的这个账号"执行停用或删除操作**，不区分该管理员是不是系统里唯一的 ADMIN。

判定逻辑很简单：目标账号 id 与当前登录人的账号 id 相同 → 直接拒绝这次操作，不管请求参数是什么。这条规则的业务目的是防止误操作导致"系统里没有任何一个能登录的管理员"这种自锁死状态——一旦发生，只能靠运维直接改数据库或重启找后门，正常业务流程走不通。

角色调整（把自己的 ADMIN 角色拿掉）不在这条硬性拦截范围内（当前实现只挡"停用"和"删除"两个动作），是否要把"自我降权"也纳入同一条防锁死规则，属于口径待 owner 确认的点。

## 适用范围 / 边界

- 成立范围：管理员对"账号管理"里任意一个账号发起停用/删除操作，且目标账号恰好是操作者自己。
- 不适用：管理员对其他账号做同样操作，不受此限制；账号只有一个 ADMIN 还是有多个 ADMIN，规则表现一致（不做"是否为最后一个管理员"的动态判断，而是一律禁止对自己操作，更简单也更保守）。
- 特例/待确认：自我角色调整（去掉自己的 ADMIN 身份）目前不在拦截范围内，是否应该拦截待 owner 澄清。
