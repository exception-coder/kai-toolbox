# 历史测试资产整理

目标是减少重复维护、环境准备和无关执行，同时保留有效风险保护。不以文件数、用例数或删除比例判定成功，不因 Java、TS、脚本语言或文件名决定去留。

本目录可以独立复制，不依赖中台 SDK、目录或外部套件。验证与提交遵循目标自己的 AGENTS 和已有入口；目标没有下文引用的基础 Skill 时，采用其已声明的等价规则，不要求为整理测试安装整套平台。

## 确定本批范围

- 读取目标 AGENTS、当前实现、相关测试、执行命令与已有结果。选择用户指定范围；范围宽时先从有证据的重复或高成本模块形成可独立验证的一批，不自动扩展到全仓治理。
- 先判断问题在测试资产还是执行入口：构建捆绑多组测试、重复调用套件、基线混用，应修入口和执行判断，不能靠删有效测试解决。
- 只要求审计或方案时不修改资产；已授权清理时按证据连续完成本批整理与验证，不逐个文件重复等待确认。保护已有工作区与暂存修改，保留必要回退能力；跨仓写入、推送、部署和数据库操作按实际授权。

## 核对覆盖后决定动作

按被测行为比较触发条件、预期断言、调用层、运行配置、生命周期、状态隔离和实际消费者。相同名称、Mock、import 或代码相似只能提示审阅，不能证明覆盖等价。

| 资产情况 | 处理依据与动作 |
| --- | --- |
| 功能已经移除 | 确认没有兼容、迁移或历史数据读取责任后删除失效测试；旧命名本身不代表功能失效 |
| 多处覆盖同一风险 | 明确由哪条保留用例承接原触发条件与断言，覆盖等价后才合并或删除 |
| 重复搭建夹具、Mock、数据库或上下文 | 复用准备过程，保留每例可变状态隔离、清理及失败定位；不将不同接口或层级的独立失败保护当成重复 |
| 断言内部写法或源码字符串 | 区分实现细节与对外合同；生成结果、协议、入口导出和必要结构规则可能正需文本或 AST 检查，有等价行为或静态检查承接后再替换 |
| 权限拒绝、租户隔离、数据完整性、并发、迁移或历史故障 | 保留独立风险断言；证明等价后可去重，不因耗时较高或已有成功路径就移除 |
| 模板副本、测试样例或支持类 | 先识别分发、工具自测和夹具职责；不计作重复业务覆盖直接删除 |

证据不足的候选保留，说明具体缺口，继续处理其他可确认项。不用“删除后全绿”证明原测试无价值，也不为降低数量将独立风险塞进难以定位的巨型测试。

## 整理与定向验证

1. 在会话、已有任务或提交说明中简记“原资产 → 动作 → 保留覆盖或失效依据”，无需新建审计报告、台账或治理平台。
2. 按稳定业务行为整理现有套件，优先复用夹具或参数化。较低层承接规则，上层保留关键调用链及不同失败风险，不机械按每个接口、每一层再复制一套。
3. 同步实际受影响的命令、发现规则、引用与说明。确认保留用例仍被原有适用入口发现；不能靠新增 skip/only、扩大排除目录、关闭门禁或降低断言强度制造通过。
4. 复用输入未变的有效证据，必要时先取得本批基线，再执行受影响套件与必要消费者检查；范围遵循 Kai 的[验证节奏](../../../../AGENTS.md#ai-原生开发验证节奏)。不因整理、提交或归档默认跑全仓测试、重新安装依赖或构建所有应用。
5. 夹具、上下文或测试环境改变时，核验状态隔离及相关失败路径；出现不明失败先核对原因，不以删除失败用例收尾。当前证据不足的部分如实保留未完成事实。

## 完成与停止

交付本批已删除、合并、复用和保留的资产及依据，说明实际检查与缺口。可比较重复准备次数、维护代码和已有命令耗时；未测量不宣称性能提升，不为收集更多指标扩展验证。

本批覆盖、发现入口和必要隔离均有证据后结束，不自动清理下一模块。按 Kai 的[Git 约定](../../../../AGENTS.md#自动提交与交付记录)提交自有改动；整理测试不授予修改业务规则或取消原有安全要求的权限。

## 可选后台执行

需要独立后台作业时，使用随本目录分发的[通用执行器](scripts/maintenance.mjs)，从目标 Git 仓库读取规则与可选项目配置。默认仅预览，显式 `--run` 才执行；不自动安装定时任务或推送候选。子应用按[接入说明](references/automation.md)直接使用，普通开发不调用此入口。CLI、沙箱或必要验证受限时记为 blocked，不把退出码 0 或静态审计当作自动清理已验收。
