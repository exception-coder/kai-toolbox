## 业务定义

**1）匹配优先级：竞品 > 客户 > 地址提示（非定论）**

一次确定性匹配会依次尝试三种信号，且互相有严格优先级：
- 先查是否命中**竞品名单**（含别名匹配）。命中即直接裁决为"竞品"身份，不再看客户库。
- 只有未命中竞品，才查是否命中**客户库**（含主名/手机号/别名匹配）。命中即裁决为"客户"身份。
- 若竞品和客户库都未命中，再看**地址软匹配**（申请地址与客户库某条记录的"城市+区"是否相同）——这个信号**不构成定论**，只作为提示信息传给下一层（灰区 LLM 判别）参考，不会单独决定身份。

**2）客户"流失"判定阈值**

命中客户库后，还要进一步区分是"在用客户"还是"流失客户"：满足以下任一条件即判定为流失：
- 客户当前状态本身就标记为"已流失"；或
- 最近一次成交时间距今**超过 365 天**（一整年）。

**3）不同命中方式的置信度取值**

判别结论落库时会带一个置信度数值，取值规则如下：
- 命中竞品名单：置信度 **0.99**（无论是否通过别名命中，竞品判定都是高置信）。
- 命中客户库——通过主名或手机号精确命中：置信度 **0.95**；通过别名命中：置信度 **0.90**（比精确命中略低，因为别名匹配的确定性弱于主名/手机号精确匹配）。
- 精准去重规则命中（手机/名称/关键字与底库完全一致）：置信度 **0.99**。
- 灰区 LLM 判别结论：置信度取 LLM 给出的值（会被裁剪到 0~1 区间），且只有达到设定的"人工复核阈值"才会被采纳为无需复核的结论，低于阈值、身份判定为"未知"、或企业数据增强处于降级状态时，一律标记为"需人工复核"。

## 适用范围 / 边界

- 优先级规则只在"确定性匹配"这一层生效，一旦进入灰区 LLM 判别，身份判断依据 LLM 提议+代码裁决，不再套用这里的优先级顺序（但置信度阈值判断仍然适用）。
- 流失判定的 365 天阈值只影响"客户"身份下的关系细分（在用 vs 流失），不影响是否命中客户库这件事本身。
- 置信度数值本身是当前产品给出的经验口径，反映的是"不同命中方式的确定性差异"这一业务判断，调整需 owner 评审。
- 地址软匹配的提示不会单独触发任何身份结论，只在申请进入灰区判别时作为补充上下文使用。

## 备注

- 口径来源：kai-toolbox 代码调研起草（visitor-analysis 匹配与置信度赋值逻辑），待 owner 核实 365 天阈值、各置信度数值是否仍是当前生效口径。
- 易混点：置信度不是"匹配是否正确"的概率，而是产品对"不同命中方式确定性强弱"的经验赋值——例如别名命中比精确命中低 0.05，不代表实际错误率的精确统计。
