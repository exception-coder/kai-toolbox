# 设计

## 范围与原则

沿用移动工作台及同一咨询状态、附件、模型策略和发送接口，不增加后端接口。适用 NAV-01、CTX-01、DENS-01、CTRL-01、FEED-01、EVID-01、IDEM-01，无例外；保持既有 AI 编程架构契约。

## 交互与状态

- 手机及平板顶部显示文字与加号组成的新建入口，触控区域至少 44px。进入新草稿后焦点移到编辑入口。
- 新建仅打开独立的首问草稿，原咨询保留挂载但隐藏，不归档、不停止回答、不切换底层会话、不创建空记录。返回当前咨询恢复焦点，新问题草稿保留。
- 用户实际发送时才复用创建接口，默认自动识别，不携带旧咨询模块；新建成功后进入新咨询。创建失败保留问题和附件及重试入口。
- 初始恢复未完成、创建或首问分发未完成、归档进行中时禁止重复新建。旧回答生成中仍可准备新问题。
- 咨询组件以咨询 ID 为身份重建。当前页面使用按 ID 隔离的内存草稿缓存，恢复历史咨询时恢复其追问及附件，避免草稿串到新咨询。缓存不承诺刷新或离开页面后的持久性。
- 沿用历史咨询入口继续未归档咨询，结束归档仍为独立明确操作。桌面布局及业务规则不变。

## 验证边界

定向组件测试覆盖新建不归档、返回、历史刷新不抢回旧咨询、新问题发送、追问隔离与恢复；类型检查与项目质量门禁补充工程验证。真实移动浏览器验收独立记录，不能以组件测试代替。

## 历史阅读与普通用户入口

历史咨询有关联底层会话时直接切到原消息流。进行中记录继续追问，已归档（SUCCESS/FAILED）记录只读；只读状态隐藏组合器、归档、引用、评分与运行恢复操作，不触发缺陷自动登记，也不绑定问答增量同步。打开历史不修改归档记录的底层标题。归档不是开始另一项咨询的前提。

无底层会话的旧记录保留既有 turns/rawReferenceJson 兜底，手机和平板内嵌到咨询内容区，标题和关闭入口位于工作台顶栏下方，正文独立滚动；加载失败可重试，返回重新打开历史列表。切换时收起更多菜单，避免菜单叠在内容上。原消息流是否仍可访问取决于底层会话保留情况，不承诺重建已删除的运行记录。

进行中的记录不走只读归档兜底。历史列表缺少底层关联时，自动获取该咨询的最新详情；拿到关联后立即进入原会话，不要求用户返回图谱找入口。关联仍未就绪时，每 2 秒刷新，最多自动等待 30 秒，之后保留原记录并提供原地重新连接；不猜测底层会话身份、不创建替代会话、不重复发送首问。组件离开后停止刷新，已归档记录不触发自动恢复。

风格、数据归属、连线切换、Bug 登记仅对管理员显示，桌面和移动端一致；历史与更新保持可见。这是入口收敛，不扩大或替代后端权限。复用原面板、消息和响应式实现，不新增一套移动业务逻辑。适用 CTX-01、DENS-01、CTRL-01、FEED-01、EVID-01，无例外。
