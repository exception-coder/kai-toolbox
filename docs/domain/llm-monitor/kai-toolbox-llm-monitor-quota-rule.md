## 业务定义

配额是对"当日消耗"设的上限，用来防止某个档位或某个具体模型被无节制地调用（比如误触发了循环调用、或者某个自动化流程失控）。规则要点：

1. **配额维度可以是"档位"或"具体某个模型"两种粒度之一**：可以只限定某一整个档位当天总共能用多少 token / 调多少次，也可以单独限定某一个具体模型。没有配置配额规则的档位/模型视为不限额，开箱即用不受影响。
2. **限额分 token 数和调用次数两个独立指标**，可以只设其中一个，也可以两个都设，任意一个先达到上限都算触发限额。
3. **软阈值只告警不拦截**：当天用量达到上限的一定比例（默认 80%）时，系统只是发出告警提示"快用完了"，调用本身照常放行，不受影响。
4. **硬上限直接拒绝，且拒绝是"当场"的、不会转移**：当天用量真正达到 100% 上限后，新发起的调用会被直接拒绝，不会尝试换用同档位下的其他模型来顶替完成这次调用——因为超限是"档位/模型整体额度用完了"，不是"这一个模型出故障"，换其他模型没有意义。
5. 未配置任何配额规则的档位/模型，永远不会被这条规则拦截，行为等同于"无限额"。

## 适用范围 / 边界

- 成立范围：配置了配额规则的档位或模型，限额按"当天"为周期滚动重置。
- 不适用：未配置配额规则的档位/模型不受本规则约束；配额拦截不等于模型调用异常，二者是完全不同的两种业务状态（参见配套的"调用记录状态语义"条目）。
- 特例：软阈值告警是纯提示性质，不会以任何方式影响调用结果；即使连续多次达到软阈值，只要没有到硬上限，调用永远正常放行。
