# 设计与边界

复用当前 sessionId、持久 run/generation、终态事件和内部队列。新建界面默认需求模式；未指定策略且没有 change 的 API 请求按需求处理，携带 change 的旧调用仍为严格模式。已有运行不迁移、不自动恢复。

失败、报告 FAILED、需求模式缺少报告或连续无新增证据进入完成核对。次数记录在原步骤表的 OUTCOME_CHECK_1..3，与运行版本同事务提交；下一次巡检确认空闲、预算、审批和写入准入后才派发。原会话核对现有代码/提交/报告，只做剩余工作；第三次仍失败或不明挂起。正常有效进展或完成结束这组核对，换任务/阶段/代次不继承旧次数。手动中断、真实阻塞、权限与预算仍优先暂停。

已收口的 FAILED 内部控制项可移交监督，普通用户项、未知接收状态不可删除。保留队列 release_ready=false；只有内部项通过原空闲门禁可发送，不能顺带释放普通用户队列。重启从持久步骤重建核对指令，重复终态不能重复计次。

严格模式保留实现核验、质量门禁、规格校验和人工事项。autoArchive 缺省为 false；全部适用检查通过后可完成但保留活动 change，明确“未归档、未上线”。显式授权归档才执行归档；历史 ARCHIVE 阶段也重新核对授权。批次按原规则进入下一已确认规格。

保留 spec-driven 和现有 artifact 身份，通过项目 context/rules 缩短生成内容：proposal 说明目标/范围/影响，specs 只写变化和必要场景，design 只记实际决定/风险/验证，tasks 按可用功能集中验收。不新建模板框架、不改历史文档、不因每个场景自动增单元测试。配置是生成引导，不是自动证明正文或实现正确的检查器。[官方配置说明](https://github.com/Fission-AI/OpenSpec/blob/main/docs/customization.md)支持 context 与按 artifact 注入 rules；本机 CLI 输出须核对实际注入。

适用 OBJ-01、NAV-01、CTX-01、DENS-01、FEED-01、EVID-01、CTRL-01、IDEM-01，无例外。复用原位覆盖层、草稿与当前项目，不新增导航；保留键盘关闭和焦点恢复、手机滚动。默认需求优先展示，可选归档不预勾选，详情不展示未启用归档阶段。失败可原位恢复，幂等身份沿用原运行及前序 turn。

验证复用现有服务、SQLite 队列和组件用例，只补三次核对、重启计次与控制项衔接的缺口，执行适用类型/构建、配置指令与质量检查。无需 DDL 或人工 SQL。新版运行与真实模型验收仍待本次重启授权；源码与静态测试不代表已生效。
