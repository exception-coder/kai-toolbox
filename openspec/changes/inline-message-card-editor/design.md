# 设计

## 直接复制图片（2026-11-06）

沿用 OBJ-01、NAV-01、CTX-01、DENS-01、FEED-01、CTRL-01，无例外。对象是当前编辑卡片，直接在原操作栏增加「复制图片」，独立工具与聊天弹框共用，不新增页面或弹层。复用 PNG 捕获；点击栈内通过含 Promise<Blob> 的 ClipboardItem 调用原生 clipboard.write，避免等待渲染后丢失用户激活。多页幻灯合为单张长图，避免系统只保留第一项；图片只驻留内存，没有下载或上传兜底。

复制与导出共用忙碌互斥及关闭保护，重复点击不重复受理；成功明确提示可以粘贴，失败、不支持和权限拒绝保留原文与重试入口。沿用语义按钮、44px 触控与换行操作栏、原焦点恢复，不改变路由、草稿和聊天状态。原生 Clipboard API 的浏览器权限与尺寸限制保留；自动化替身不代表真实应用粘贴通过。依据 [WebKit Async Clipboard API](https://webkit.org/blog/10855/async-clipboard-api/)。无 AI 编程架构契约影响。

适用 OBJ-01、NAV-01、CTX-01、DENS-01、FEED-01、CTRL-01，无例外。主对象是当前会话的一条回复；正文以完整 Markdown 快照传递，不用手机概览替代全文，不改变消息或引擎协议。

Page Anatomy：固定标题及全屏/缩小/关闭 → 可滚动编辑与预览区。手机默认全屏预览，可切回编辑；桌面默认最大 1200px 弹框、保留原双栏布局。弹框内容是唯一外层滚动区，编辑文本自身可滚动；安全区留白、触控按钮至少 44px，Esc 与关闭回到原触发器，触发器已卸载时回消息区。全屏是 CSS 视口布局，不调用浏览器全屏 API；Portal 仍适配外层已有原生全屏。

MessageList 在虚拟列表之外拥有当前卡片快照和焦点引用。手机更多菜单关闭后再由列表持有编辑器，阻止菜单关闭时抢回焦点；虚拟行消失不带走编辑器，切会话时清除，避免返回后复活旧弹框。不会创建路由、会话或新菜单。

Markdown 卡片模块公开 `public-api/dialog`，轻量弹框先显示骨架，再动态导入原 MarkdownCardPage；失败原位重试，权限不足可关闭恢复。权限规则与内容工具一致：ADMIN、超管、menu:content-tools 或 menu:markdown-card。现有主题、分页、水印、PNG/移动分享原实现不复制。Page 接受初始正文与禁用自动保存参数；独立菜单仍自动保存，弹框不覆盖独立草稿，改动只在本次编辑器中，关闭后以原回复重新开始。

全屏/缩小只改容器样式，不重新挂载编辑器。导出复用原 DOM 捕获链路，互斥避免重复导出；期间保留节点并暂时禁用关闭和缩放，失败解锁并显示原错误，可重试。没有服务端写入或外部自动发送。

验证重点是原路由不变、完整正文、菜单/虚拟行卸载、切会话、尺寸切换保留状态、独立草稿隔离、原权限、导出失败恢复和焦点。JSDOM 不作为视觉和真机分享证明；当前浏览器访问策略限制不绕过，待目标版本加载后验证手机与桌面显示及真实图片导出。

## 写作主题（2026-11-01）

按用户提供的 ChatGPT 写作卡片截图增加 `writing` 主题，保留原五套主题及默认选择。适用 OBJ-01、CTX-01、DENS-01、FEED-01，无交互原则例外：主对象仍是当前回复的 Markdown 快照，沿用原主题选择、分页、移除段落、独立草稿保存和导出反馈。截图只用于版式参考，不复制产品品牌或在图片内放置无效操作按钮。

白底、16px 圆角细边框、小号文档图标与“写作”标识，正文左对齐，标题与段落用字重、行高和留白区分。长图采用适合 750px 原始画布的字号，响应预览在窄屏收拢内边距；幻灯沿用既有固定尺寸和分页，不自动改变原文。公共标识位于真实卡片节点内，预览、长图和幻灯离屏导出共用；复制/导出仍在既有工具栏操作。

主题只更新本地视图，不创建服务端对象或额外导航；独立工具可持久化 `writing`，对话弹框继续隔离独立草稿。重复选择是同一状态赋值，失败/重试/关闭/键盘及焦点恢复沿用现有编辑器，不新增写入或幂等协议。检查现有草稿回归、适用类型/构建和主题在三种渲染器中的接入；真实移动/桌面显示及导出仍须与实际运行版本分别核对。没有 AI 编程架构契约变化。

## 图片直接分享（2026-11-01）

采用 L2 模块内扩展，适用 OBJ-01、NAV-01、CTX-01、DENS-01、FEED-01、CTRL-01、IDEM-01，无例外。对象仍为当前编辑的卡片，不新增弹框、分享凭证或独立应用接入。沿用现有工具权限与本地图片捕获，准备文件放在卡片模块 `lib/sharing.ts`；保存只负责下载，原有导出保护和焦点恢复继续使用。此处只有用户主动分享，不改变业务系统身份/权限边界或 AI 编程架构。

当前原生分享在异步图片捕获及 Blob 读取后调用，可能失去 transient activation；多页还会逐张唤起面板。改为显式两阶段：点击「分享」生成内存 File 数组，显示数量/进度；图片就绪后点击「选择应用分享」，在同一次点击栈内调用 `navigator.share`，多页一次交给系统。没有客户端 UA 白名单，不把桌面一概判为不可分享。

共享的操作状态复用在页头与手机预览栏，两处都用同一个互斥引用防止重复受理。准备结果绑定原状态对象和可见段落集合，正文、主题、模式、比例、分页和水印变化后失效；即使异步生成跨过编辑变化，旧结果也不能进入分享动作。生成和系统分享期间保护外层编辑器关闭/缩放；本地准备文件不跨刷新持久化，也不覆盖任何草稿。操作失败原位保留内容与可重试入口，不自动调用下载。

系统完成回执只表述「交给系统分享」，不等于应用已发送或对方收到；AbortError 按取消处理。能力不足或多文件被拒时说明限制，保留明确的「保存 PNG」。不创建 QQ/微信/飞书假定向按钮，不读联系人、不自动发送、不引入远端 SDK。主按钮保留 44px 点击高度，键盘仍使用既有按钮，原位状态朗读，不改路由、滚动归属或关闭后的焦点位置。

2026-11-01 核对 [W3C Web Share](https://www.w3.org/TR/web-share/) 与 [Navigator.share](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)：文件能力需实际 canShare 检查，分享需用户点击授权，应用列表由设备决定，网页不能读取选择结果。自动检查覆盖点击栈调用、多页一次交付、取消/失败、不支持与编辑失效；真实各容器/应用是否显示及最终发送必须单列实机验证。
