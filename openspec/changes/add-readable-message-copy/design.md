# 设计

适用 OBJ-01、NAV-03、CTX-01、DENS-01、FEED-01、EVID-01，无例外。复制依附原消息或轮次，从完整源文生成，不依赖折叠或虚拟列表当前渲染的片段。用户输入仍默认原文；代码块、SQL、链接和配置的原始复制入口不变。

回复的复制按钮默认写入易读文本，旁边的格式菜单提供易读文本、富文本、Markdown 原文。易读文本统一用于飞书、企微、钉钉聊天，不建立三份无实质差异的平台适配器；目标应用如何呈现粘贴内容由接收端决定，页面不承诺未经实测的平台效果。标题用缩进与【标题】保留层次，列表保留编号、缩进和任务状态，表格转为带列名的记录，代码保持字面内容，链接保留目标。Markdown 原文逐字保留，复制不概括、不截断、不自动发送。

复用项目 Marked 与 DOMPurify 生成受控 HTML，再从同一结构得到易读文本。排除脚本、图片与其他活动元素；图片转为说明和地址，不请求远程内容。富文本一次写入 text/html 和 text/plain，由接收端选择支持的表示。浏览器不可用或拒绝富文本时复用既有纯文本降级并明确提示；全部失败才显示重试，不伪称已复制。清理临时选择区、恢复焦点和选区沿用原剪贴板函数，格式菜单沿用全屏兼容的 Popover。

依据：[ClipboardItem 官方浏览器文档](https://developer.mozilla.org/en-US/docs/Web/API/ClipboardItem)。这是现有回复操作的局部扩展，不改变 Harness、工具权限、任务生命周期或整体 AI 编程架构契约，无后端、数据库或新发送服务。
