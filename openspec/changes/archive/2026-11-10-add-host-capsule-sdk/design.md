## Decisions

The browser connects only to its host. Host Java obtains the participant from its authenticated principal, never from browser request headers, and adds client Basic credentials upstream. Forge combines client and participant into stable ownership and pins the project route to the client identifier. Capsule sockets always use consult-readonly and permit only the existing consultation, context, history and feedback commands. REST forwarding is allowlisted and retains existing ownership checks. No administrative principal or bearer token is issued.

A one-use host ticket bridges browser WebSocket limitations; it is bound to the authenticated host participant and expires quickly. Stored direct-Forge connection preferences and login controls are disabled in host mode. Configuration changes retire the host SDK generation and subsequent reconnects use the replacement.

The structured requirement contract is shared with the existing workbench. Cached module prose is unverified context, not evidence that source/spec exploration happened.

## Mobile visibility recovery

Implementation: `visibility.storageKey` selects the host-local preference. The widget reads/writes only hidden/visible and catches storage exceptions. Forge's Bridge owns one in-flight initialization and pending open; its menu reports loading/error/ready. Failed Loader scripts are removed before retry. Development uses workspace SDK source for authorized hot update; packaged hosts still require a separate stable SDK release. Browser recovery passed at 390px; no channel publication or service restart was performed.

Apply CTX-01, DENS-01, FEED-01 and IDEM-01: retain the current page and assistant instance, expose recovery in existing session tools, and never add another floating launcher. The stable identity is an explicit host-local visibility storage key. Forge opts in; other hosts retain their existing defaults. This is a presentation preference, not authorization or a new business action permission.

The widget owns hidden/visible transitions through a focused storage adapter. Panel close does not alter the preference; hide saves hidden; explicit open saves visible. Storage failure does not prevent current-page interaction. A host control bridge exposes the existing SDK open action to the menu, reports loading/unavailable status, and permits retry without starting a second instance. No credentials are persisted.
