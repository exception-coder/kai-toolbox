## 业务定义

秘书"长期记忆"是区别于日常记录（笔记/待办/开销等）的一类画像级、长期稳定的用户认知，分三类：

- **偏好**：用户稳定的喜好/习惯/风格（如口味、作息、沟通偏好、工具习惯）；
- **禁区**：用户明确划定的红线/不可触碰的事（如忌口、隐私边界、话题雷区）；
- **核心人物**：对用户重要的人（家人/同事/老板/朋友等），以人名为键，记录关系/备注。

这三类记忆遵循"提议 → 裁决 → 确认"的生命周期：

1. **提议**：每次记录或问答之后，异步、不阻塞地把原文交给 LLM，只在确有把握时提炼画像候选；模型宁缺毋滥，没有明确画像信息就不提议。
2. **裁决**：代码侧对 LLM 提议的候选做合法性校验（类目必须是三选一之一、键值不能为空），并按"同类目 + 同键"去重——如果同一类目下同名的键已经存在（不论当前是提议中还是已确认状态），就不会重复生成新的提议，避免每轮对话都刷屏式重复提议同一件事。合法且不重复的候选进入"提议中"状态。
3. **确认**：用户在界面上查看提议中的候选，确认后置为"已确认"状态；用户也可以直接手动新增一条画像记忆，视为直接进入"已确认"状态。

只有"已确认"状态的记忆才会被后续对话/问答场景当作背景信息注入模型上下文；"提议中"的候选不会进入任何 prompt，避免未经确认的错误画像误导对话。

## 适用范围 / 边界

一次性的待办/日程/开销等具体事项不属于长期记忆范畴，那些走"记录态"的笔记体系（见 capture-flow）；长期记忆只收"稳定、长期"的画像信息。三类画像是当前唯一受支持的类目，模型给出的其他类目字符串会被判定为非法而丢弃。
