## ADDED Requirements

### Requirement: 仓库状态优先展示
系统 SHALL 在代码与分支概览展示当前仓库、完整分支与明确同步状态，默认只展示最近 3 条提交，目录管理使用独立入口。

#### Scenario: 手机查看
- **WHEN** 用户打开代码与分支
- **THEN** 使用紧凑 Header 的底部抽屉，长分支可完整查看复制，历史按需展开，页面无需横向滚动

#### Scenario: 获取远端失败
- **WHEN** 用户统一刷新而 fetch 失败或上游缺失
- **THEN** 保留本地状态并说明未核验，不能由零计数认定已同步

### Requirement: 分支操作保持仓库身份与数据完整性
系统 SHALL 区分只读浏览和真实切换，真实切换须先检查再确认，并重新核验源与目标快照，不覆盖本地数据。

#### Scenario: 确认前后状态变化
- **WHEN** 确认后出现脏文件、未完成 Git 操作或目标提交变化
- **THEN** 拒绝切换并保留当前视图，不自动暂存、合并、覆盖或重试

#### Scenario: 远端分支已有同名本地分支
- **WHEN** 用户选择从远端分支创建跟踪分支但本地名称已存在
- **THEN** 引导选择已有本地分支，不覆盖其文件和跟踪关系

#### Scenario: 跨仓库迟到响应
- **WHEN** 用户切换仓库后旧查询响应到达
- **THEN** 不回填旧仓库状态或提交，写操作仍绑定当前授权仓库

### Requirement: 历史按需加载同一版本
系统 SHALL 在独立历史视图分页读取固定版本的记录，返回概览保留对象上下文。

#### Scenario: 分页期间分支变化
- **WHEN** 加载更早提交时分支已不指向首屏版本
- **THEN** 提示刷新，不拼接不同版本记录
