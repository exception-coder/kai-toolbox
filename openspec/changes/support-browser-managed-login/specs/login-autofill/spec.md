## ADDED Requirements

### Requirement: 支持用户选择的密码管理器
登录表单 MUST 使用稳定的账号与密码字段及正确的自动完成用途。应用 SHALL 从实际表单读取提交值，即使自动填充没有触发 React change 事件也能发起登录；未填必填项 MUST 阻止认证请求。

#### Scenario: 无输入事件的自动填充
- **WHEN** 密码管理器填入账号密码，未产生 React change 事件，用户提交表单
- **THEN** 登录按钮可操作，应用发送实际字段值且只发起一次请求

#### Scenario: 登录失败与修正
- **WHEN** 认证失败
- **THEN** 表单展示错误，保留字段供修正，并允许再次提交

### Requirement: 应用不额外保留密码
应用 MUST NOT 将登录密码写入持久存储、URL 或日志。保存密码 SHALL 由用户选择的浏览器或系统密码管理器负责；页面 MUST 提示共用设备不保存。关闭或成功后 MUST 移除密码表单，重新打开不得恢复应用保留的上次密码。

#### Scenario: 取消后重新打开
- **WHEN** 用户取消登录并重新打开
- **THEN** 应用不恢复上次输入的账号密码，浏览器仍可根据用户设置重新自动填充

#### Scenario: 登录成功
- **WHEN** 认证成功
- **THEN** 复用现有登录回调关闭弹窗并移除表单，供浏览器识别成功，应用不承诺浏览器必定提示保存
