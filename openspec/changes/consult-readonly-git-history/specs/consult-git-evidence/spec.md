## ADDED Requirements

### Requirement: 定位源码后提供只读提交线索

系统 SHALL 通过受限工具查询授权源码文件的本地提交历史或行归属，不提供通用命令、仓库写入或自动远端同步。

#### Scenario: 运维寻找相关开发联系线索

- **WHEN** 助手已定位相关源码文件且当前咨询具备历史工具
- **THEN** 可查询最多 20 条最近提交并跟随重命名，或最多 200 行的 HEAD 归属
- **AND** 提供哈希、作者、提交者、时间和说明，区分本地版本与生产版本
- **AND** 不把最新提交人、行归属或提交数量直接视为主要开发者或故障责任

#### Scenario: 越界或命令注入请求

- **WHEN** 请求逃出授权目录、指向父仓库、缓存或 Git 内部文件，或传入非允许动作及超限范围
- **THEN** 拒绝请求，不读取其他仓库，不执行任意选项或写命令

#### Scenario: 历史缺失或不完整

- **WHEN** 本地为浅克隆、文件无提交、目录不是 Git 仓库，或请求超时超量
- **THEN** 明确说明缺口与本地证据范围，历史查询本身不拉取、写入或猜测作者；源码工具前置的服务端安全同步按consult-source-auto-sync执行并返回独立同步证据

### Requirement: 装配遵守既有源码权限

系统 SHALL 在默认流程登记该工具，并为已有 source_read 的冻结流程追加只读文件历史；不改写原快照。

#### Scenario: 旧咨询具有源码读取能力

- **WHEN** 服务端恢复含 source_read 的冻结流程
- **THEN** 两引擎均可装配 source_git_history，仍限制于当前源码根

#### Scenario: 咨询没有源码读取授权

- **WHEN** 流程无 source_read 或没有冻结流程快照
- **THEN** 不自动追加历史能力，未装配调用被拒绝
