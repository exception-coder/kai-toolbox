# 设计

适用原则：AI-01、CTRL-01、CTX-01、FEED-01、EVID-01。对象是已配置仓库和不可变候选 SHA；复用已有配置、状态 API、Java worker、持久队列及 Forge/PM2，无新增菜单或弹窗，因此键盘/移动焦点无改动。

## 检查与应用

- 默认 interval=300 秒，已有 running 锁禁止并发，失败退避仍有效；daily 配置保留。
- fetch 比较、稳定窗口、独立 worktree 构建可以正常工作时进行。manual 策略只准备候选。idle 策略要求构建成功后至少五分钟空闲；两个采样之间 admission 世代不变且两端安全，才能应用。登记任务即增加世代，捕获短任务；异常、授权、后台任务和持久队列均阻断。
- 等待期间不获取 drain，用户仍能发起任务；仅短暂交接阶段关闭入口，再检查世代、活动、队列、远端和本地 HEAD。变化则释放入口延期。窗口按轮询采样，因此实际空闲等待可能超过五分钟，不承诺实时触发。
- 原有 require-idle=false 不再允许跳过安全检查；状态始终报告 requireIdle=true。状态新增 restartPolicy/idleSeconds。人工 check 同样服从策略，idle 下属于有副作用操作。

## 本地修改与故障恢复

在候选构建完成、空闲和最终核对之后，先写 Git 私有 journal，再 stash 已跟踪改动。未跟踪/忽略文件留在原处，原生 Git 拒绝覆盖碰撞。按固定 SHA ff-only，使用固定 stash 对象 apply --index；恢复成功删除 journal、保留 stash 备份供核对。已提交 ahead/diverged 不自动改写历史。制品只包含远端提交。

中断或身份未知保留 journal；恢复冲突保留 stash 和现场，禁止重启及重复恢复。Git 操作只保证其自身索引锁；外部编辑器仍应避免在最终短暂应用阶段写同一文件，不声称对任意外部写入具有事务隔离。现有 admission 保护 Forge Agent，并非操作系统写锁。

重启交接失败/超时保持旧服务可接收任务；持久 pending-restart 阻止自动再次重启，需人工核对并确认。新进程的运行验收不能由候选构建或交接 accepted 替代。

## 授权与验证

用户已要求轮询和自动暂存；此前仅授权每日自动重启。此次提供 idle 策略但默认 manual，不改私有配置、不立即重启。明确确认全天空闲重启后才启用并加载目标版本。按既有 Forge 规范验收进程、版本、HTTP、日志及至少六十秒稳定性。

测试使用临时真实 Git 仓库覆盖 staged/unstaged 恢复、未跟踪碰撞、冲突持久阻断；服务测试覆盖队列、短任务、空闲窗口、最终检查竞态、manual、候选失败与固定 SHA。无数据库结构变更。
