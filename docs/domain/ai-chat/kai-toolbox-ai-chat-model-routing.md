## 业务定义

模型网关返回的模型清单，需要先归类到"对话 / 绘图 / 视频 / 其它"四种能力类别，才能决定该模型出现在前端的哪个使用模式下、以及请求时允许携带哪些参数。

- 分类判定优先级（从高到低，命中即止）：
  1. **视频**：命中"视频模型名称模式"，或网关能力标签把该模型标为视频类端点，或标签中出现分辨率/时长这类"视频规格"关键词。
  2. **绘图**：未命中视频，但命中"绘图模型名称模式"，或标签标为绘图类端点。
  3. **其它**（音频/向量/重排等）：未命中以上，但命中"其它模型名称模式"，或标签标为音频/向量/重排类端点。这类模型不作为对话/绘图/视频窗口出现，直接从可用清单中剔除。
  4. **对话**：以上均未命中时的兜底分类。
- 能力元数据来源优先级：优先用网关 pricing 接口返回的能力标签（如"多模态""推理"）与支持端点类型作为权威判据；pricing 接口不可用时，退化为按模型 id 的名称字符串模式匹配。
- **温度下发规则**：模型被标记为"推理"类（标签或名称模式），则该模型的对话请求不下发温度参数（网关会拒绝携带温度的推理模型请求）；其余模型正常下发温度。
- **多模态判定规则**：模型被标记为"多模态"（标签或名称模式），则允许该模型的对话请求携带图片附件；否则携带图片会被直接拒绝。

## 适用范围 / 边界

- 仅对接入"OpenAI 兼容网关 + pricing 能力标签"这一类模型网关成立；若未来更换网关且标签体系不同，分类优先级与判据需要重新对齐。
- 名称模式匹配是 pricing 不可用时的兜底策略，具体模式串本身是可运营调整的配置，不是业务真理；真正稳定的是"标签优先、名称兜底"的两级判定顺序与四级分类优先级本身。
- "是否支持温度"与"是否支持多模态"是两条独立判定，一个模型可能同时受两条约束（如某推理模型既不支持温度也不支持多模态）。
