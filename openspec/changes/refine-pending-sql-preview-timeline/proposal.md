## Why

待执行 SQL 的常驻预览与管理弹窗在移动端同时强调状态、告警、DDL 证据、目标库和操作，登记时间又只是末尾的一行弱文本，导致用户难以快速确认“这是什么、登记给谁、何时登记、当前处于什么状态”。

## What Changes

- 重排 SQL 预览的信息层级，以登记标题、当前状态和目标库为主要扫描路径。
- 增加共享的登记时间线，明确展示登记、更新以及执行或取消时间。
- 将安全边界和 DDL 证据压缩为渐进披露的次级信息。
- 优化窄屏下的目标切换、表单区和操作区，避免信息堆叠与横向溢出。

## Capabilities

### Modified Capabilities

- `pending-sql-review`: SQL 登记预览必须展示可扫描的时间线和清晰的内容层级。

## Impact

- 仅调整 claude-chat 前端展示与交互，不新增接口、数据库字段或人工待执行 SQL。
- 复用现有 `createdAt`、`updatedAt`、`executedAt` 事实，不推断不存在的运行状态。
