# Codex 双通道能力清单

本清单核对 2026-10-03 项目源码与 [Codex SDK](https://developers.openai.com/codex/sdk)、[Codex App Server](https://developers.openai.com/codex/app-server) 官方文档。它区分官方接口存在、Forge 已接入和实际运行验收；接口存在不代表当前账号有权限，也不代表 Forge 已交付。

## 当前路由

| 会话条件 | Forge 路由 | 说明 |
|---|---|---|
| 官方 Codex 授权目录 | App Server 优先 | `codexEngine.ts` 以会话线程启动并消费流式事件 |
| App Server 在可安全重试阶段失败 | Codex SDK 回退 | 已产生可见输出或副作用时禁止重放 |
| 第三方兼容网关 | Codex SDK | 不使用官方账号的 App Server 通道 |

Sidecar 当前声明 `@openai/codex-sdk` 0.159.3。依赖文件已有其他作业的未提交修改，本批不改版本或锁文件。App Server 与 SDK 共用 Codex 运行时的部分配置，但不是同一个功能面；不能用 SDK 回退来声称所有 App Server 方法都有 SDK 等价实现。

## 能力对照

| 能力 | App Server | TypeScript SDK | Forge 当前状态与下一步 |
|---|---|---|---|
| 新建、续接、流式执行与取消 | 稳定线程/轮次接口 | `startThread`、`resumeThread`、`runStreamed` | 两条路径已接入；保持安全回退边界 |
| 模型、推理强度、速度与沙箱 | 模型目录与轮次配置 | 线程选项 | 已接入主要配置；账号可用性仍须以实际轮次验证 |
| 图片输入 | 轮次输入 | SDK 输入 | 两条路径已接入；文件输入需另立业务场景与上传边界 |
| 中途追加指令 | `turn/steer` | 无同等线程方法 | App Server 已接入；SDK 不伪造正在执行轮次的追加能力 |
| 会话分叉 | `thread/fork` | 无同等方法 | App Server 已接入；第三方 SDK 路径不能承诺精确原生分叉 |
| MCP 与 Skills | 运行时目录、工具和认证状态 | 配置传入 SDK 运行时 | 已接入；App Server 的 MCP 分页完整性是本批修复点；SDK 的配置态不能标成运行时核验 |
| 原生语音 | App Server 实时会话 | 当前 TypeScript SDK 无等价接口 | 仅官方 App Server 路径接入 |
| 原生线程搜索、命名、置顶、归档 | 稳定线程接口 | 无对应管理接口 | 尚未全面接入；优先沿用 Forge 现有会话身份，避免第二套列表 |
| 主动上下文压缩与原生审查 | `thread/compact/start`、`review/start` | 无等价接口 | 待设计明确用户入口、事件反馈与结果归属 |
| 结构化结果 | 轮次输出配置 | SDK `outputSchema` | 尚无跨通道统一业务场景，先不暴露空白控件 |
| 账号、额度与认证 | 账号及额度接口 | 本地认证配置 | 额度已部分接入；登录管理与权限不能仅由模型目录推断 |
| 插件与 Apps 管理 | 官方文档中部分接口仍在开发 | 不属于 TypeScript SDK 客户端接口 | 只做成熟度核验；不自动安装或启用 |
| 后台终端、分页历史条目等 | 部分方法要求实验能力 | 无对应接口 | 暂不作为生产交付承诺 |

## 分批实施

1. **能力目录准确性**：完整读取 App Server 的 MCP 分页目录，并让诊断与执行前校验共用结果。SDK 保留配置态来源标记。本批代码与目标测试完成，服务更新和运行验收未执行。
2. **会话管理一致性**：核对原生线程命名、归档、检索与 Forge 会话身份的对应关系，只补不会产生第二套会话列表的能力。SDK 路径明确无等价接口。
3. **工作流能力**：围绕明确的审查、压缩或结构化结果场景分别设计入口、事件、失败恢复，再接 App Server 与 SDK 实际支持的接口。
4. **扩展生态**：对 Skills、MCP、插件和 Apps 逐项核对官方成熟度、账号授权与宿主权限；实验或标注“不要在生产客户端调用”的接口不默认开放。

实施顺序由稳定接口与现有业务入口决定。每一批需分别记录目标版本、静态测试、服务更新后的运行观察，以及两条路径实测覆盖情况；未测项保持未验收。
