# 评审工作台调整

主对象为现有评审空间内的需求，使用既有 requirement ID、revision 与来源指纹；原会话继续拥有执行确认权。候选仅展示，不自动写入清单；主动加入后默认未确认，人工确认绑定当前正文版本，编辑或合并使确认失效。旧需求不推定已确认。AI 不再静默更新、移除或清空已存在需求；重复来源复用，类似候选由用户显式选择合并。

移动端 48px 单行 Header、剩余高度消息流、底部 44px 清单入口和自适应输入。项目、依据与检测进入详情；清单采用模态 Bottom Sheet，桌面同对象侧栏。主消息流不卸载，覆盖层关闭恢复触发器焦点、阅读锚点与输入草稿。加载失败保留最后数据和编辑草稿；提交结果未知按稳定需求版本核对，不能重建任务。

唯一提交入口在清单内，先展示服务器确定的目标项目和已确认摘要，再交付已确认版本。服务端拒绝未确认及过期版本；结构化提交键由空间内所选 ID/revision 确定，同一事务保存交付记录和原会话待办。记录真实提交时间、需求身份、原文快照、服务器目标项目；无登录身份明确写“评审链接访问者（未登录）”，不伪造实名。已提交内容不可变，编辑后作为新版本重新确认交付；执行和异常仍取既有队列回执。

需求类型、问题、预期行为和验收标准使用已有正文的明确小节存储并编辑，避免创建平行需求模型。来源对话及截图复用既有历史读取与附件权限，缺失原消息时只展示已保存证据并明确缺口。不放开评审编码、重启或发布权限，也不强制创建 OpenSpec。

清单打开时刷新当前需求及交付信息，仅展开期间轮询进度；来源按空间批量读取，不逐项查库。最近交付元数据最多 50 次，列表不选择原文字段，用户点击后才按空间及提交 ID 读取一条完整快照，避免周期性传输历史长文。新接口性能未单独压测，不以结构推断代替运行计时。

适用 OBJ-01、NAV-01、CTX-01、DENS-01、FEED-01、AI-01、EVID-01、CTRL-01、IDEM-01，无例外。沿用 Radix Dialog 焦点约束及 VisualViewport 的尺寸与 offset 适配，不升级组件依赖；依据：[Radix](https://www.radix-ui.com/primitives/docs/components/dialog)、[MDN](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)，核对于 2026-10-31。Graphify 大图查询限制沿用，定向源码补齐；DDL 知识基线 PARTIAL，仓库 schema 及隔离 SQLite 验证各自明确，不产生人工执行 SQL。
