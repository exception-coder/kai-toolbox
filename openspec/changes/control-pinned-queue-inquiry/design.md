## 操作与状态

复用会话控制队列，置顶执行/追问/待核对项显示“终止询问”，每项显示“删除”，44px 触控目标可换行。沿用主题 Token，不添加导航。请求中禁用重复操作，失败保留消息并通过现有同步警告反馈；切换会话后旧请求不得改写当前会话。

后端复用会话访问检查和会话锁。待发项仅删除自身；有派发记录或置顶完成追问时，先核对 Sidecar 的活动轮次，匹配才请求中断。无法查询、轮次不符、中断未送达均保留消息。`user_cancelled` 使用已有 stop_reason 字段，关闭完成准入并阻止自动追问、内部续跑和迟到成功回执重新释放；活动引擎仍等待原中断回执链路确认结束。单纯终止前一任务追问时保留待发队首；删除则另外移除指定项。清空携带确认过的消息 ID 集合，避免误删新增项；旧客户端不传集合时兼容旧清空语义。

引擎状态 RPC 在会话锁外等待，取得快照后在锁内重新核对原轮次与所选消息，避免接收线程先处理终态时被会话锁堵住。批量清空逐项核对并加锁，不在外层持锁等待引擎；失败时已处理项与未处理项由重新读取列表反映，不伪报全部清空。

不新增表或字段。知识库 DDL 工具返回 DDL_MISSING，缺少 `claude_chat_queue_runtime`、`claude_chat_queue_delivery`、`claude_chat_queued_message` 基线。实际依据仓库内 claude-chat-schema.sql 与 claude-chat-queue-reliability-schema.sql，并用隔离 SQLite 验证，不操作真实数据。

适用原则：NAV-01（动作依附队列对象）、CTX-01（保留会话与其他消息）、DENS-01（直接可见的关键控制）、FEED-01/EVID-01（区分终止请求与停止事实）、CTRL-01（使用者接管）、IDEM-01（旧 ID 不影响新任务）。无原则例外。现有业务全景中的会话排队、暂停能力及主流程不变；本次补齐该能力的具体恢复控制，不重绘全景图。
