# Vibe Coding 队列可靠续发与有界完成追问

## Why

用户夜间离开浏览器后，需要队列在上一项正常结束后继续。旧流程仅依赖一次完成通知，入队与完成事件交错可能漏发；先删队首再发送会在进程中断时丢输入。失败或结果不明时直接停下也不能满足尽力连续推进的需要。

## What Changes

- 原文、认领、完成准入和最多三次追问次数持久保存，服务端唤醒及巡检共同驱动。
- Sidecar 接收和终态回执可对账、同轮次去重，原文确认完成前不删除。
- 空闲后在原会话追问完成情况并处理剩余内容；三次仍未确认才挂起，提供人工确认继续入口。
- UI 仅展示及控制服务端队列，保留公开演示的浏览器临时队列边界。

## Impact

影响聊天服务、SQLite 启动 schema、Java/Sidecar 私有协议和现有队列组件。无需人工 SQL、新增中间件或修改菜单。运行版本待用户确认重启后核验。
