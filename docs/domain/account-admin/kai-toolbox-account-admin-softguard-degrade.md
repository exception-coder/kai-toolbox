## 业务定义

kai-toolbox 里大多数需要鉴权的接口，未授权时按常规 REST 语义抛 401（未登录）/403（无权限），前端据此弹出登录框或提示无权限。

但有一类接口被设计成"软鉴权"：这类接口对未授权访问的处理方式不是报错，而是**静默降级**——查询类接口返回一个"空的"结果（就像什么数据都没有一样），写操作类接口直接不生效（no-op），但对外看起来像是"成功"了（不会抛出鉴权错误）。业务意图是：这些接口所在的功能对未授权用户来说应该"看起来能用但拿不到真实数据/改不了真实状态"，而不是直接被拦在门外报错，通常用于把某些能力对"轻量访客/降级场景"保持界面可用但功能空转。

配套的一个专门角色是**只读(READONLY)**：这是一个全局角色，赋予它的账号在"软鉴权"接口上，只能通过安全的查询类方法（相当于 HTTP 语义里"只读不改变状态"的方法），任何带写语义的操作都会被当作未授权处理，走上面的静默降级路径。也就是说 READONLY 角色的语义就是"只能看、不能改"，且"改"被拒绝的方式也是静默的，不是报错。

还有一类是"配置驱动的管理员专属区"：某些路径整体被声明为只有 ADMIN 才能访问，命中这些路径的非 ADMIN 用户同样走静默降级路径，而不是显式报错。

## 适用范围 / 边界

- 成立范围：被标记为"软鉴权"的功能模块，以及被声明为"仅管理员"的路径前缀；READONLY 角色的语义在这些范围内生效。
- 不适用：绝大多数常规业务接口——它们走标准的"未登录/无权限即报错"语义，只有显式标了软鉴权/管理员专属的那部分才降级为静默处理。
- 特例：即使账号本身拥有 ADMIN 角色，也总能通过软鉴权检查（ADMIN 对软鉴权模块始终视为已授权）。
