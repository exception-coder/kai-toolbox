## Context

业务咨询通过 `ForeConsultPage` 创建咨询记录，再把记录中的模型快照交给复用的 Vibe Coding 会话。当前页面对非管理员传 `null`，管理员可传任意目录中的模型；`ConsultService.startSession` 原样保存该值，因此普通用户实际模型不稳定。

适用产品原则：OBJ-01（咨询会话是唯一对象）、DENS-01（固定策略不应伪装成可编辑配置）、AI-01（前端与 Agent 共用同一服务端业务边界）、EVID-01（模型快照必须反映真实请求）。

## Goals / Non-Goals

**Goals:**

- 管理员从当前 Auth 的模型目录选择并保存默认模型，保存实际 ID 和展示名称，不依赖硬编码 slug。
- 普通用户的新咨询由服务端固定为已保存默认模型，页面只读展示该配置。
- 管理员保留单次咨询模型选择及其它已授权的 Codex 运行选项。
- 历史会话保持原模型快照。

**Non-Goals:**

- 不改变普通 Vibe Coding 会话的模型策略。
- 不批量迁移历史咨询记录，不改变模型目录同步机制。
- 不改变咨询 API 字段或数据库结构。

## Decisions

1. 新增业务咨询模型策略服务，以模块自有的单行表保存 `{model, displayName}`；专用 API 允许已登录用户读取，只允许管理员更新。独立存储避免通用配置写入口绕过管理员权限，表由启动 schema 幂等创建。
2. `ConsultService` 在服务端按当前身份解析模型：普通用户无条件使用管理员默认值；管理员优先使用本次请求模型，未选择时回退默认值。仅在前端限制无法防止旧客户端或直接 API 绕过。
3. `ForeConsultPage` 的管理员仍使用当前 Auth 模型目录选择真实条目，并可显式保存为普通用户默认；普通用户读取配置并只读显示。在通用 `CodexSessionOptions` 增加独立 `modelDisabled`，避免禁用推理强度、速度等其它选项。
4. 不修改历史记录。已有会话继续按创建时模型恢复，避免运行中的咨询被静默改写。

## Risks / Trade-offs

- [普通用户默认模型尚未配置] → 禁止开始新咨询并提示联系管理员配置，不静默回退 Auth 默认模型。
- [配置的模型已不在当前 Auth 目录] → 页面沿用现有 Auth 不匹配提示；管理员从当前展示目录重新保存，不根据旧 slug 猜测替代模型。
- [通用配置组件增加一个禁用维度] → 仅新增可选属性，默认行为不变，并用组件测试验证。

## Migration Plan

发布新前后端后，应用启动幂等创建策略表，管理员再在业务咨询页选择当前展示的目标模型并保存默认；随后只影响新咨询。回滚代码即可恢复原有请求模型行为。无需人工 SQL 或数据回填。
