## 业务定义

「收件箱」模块本质是自建一个能直接接收外部邮件的 SMTP 服务端点（而非转发/代收第三方邮箱），因此天然暴露在公网扫描风险下。为此在信件正式接受前设了两道准入判定：

1. **发件人白名单**（在 `MAIL FROM` 阶段判定）：白名单为空则不做限制、来者不拒；白名单非空时，发件地址需命中名单中的一条才放行，命中方式支持三种口径同时生效——
   - 以 `@域名` 开头的条目：按"域名后缀匹配"，即只要发件地址落在该域名下就算命中（例如 `@amazon.com` 匹配 `xxx@amazon.com`）；
   - 含 `@` 的完整地址条目：按"精确地址匹配"；
   - 不含 `@` 的普通字符串条目：按"地址中包含该子串"匹配（较宽松的口径，用于快速放行某些关键字）。
   - 不在名单内的发件人在 `MAIL FROM` 阶段即被拒绝，邮件不会进入后续处理。
2. **收件人域名白名单**（在 `RCPT TO` 阶段判定）：白名单为空则全收；非空时只接受收件地址的域名部分与白名单中某一项完全一致的邮件，域名不在名单内的收件请求被拒绝。

两道判定都通过后，邮件才会被真正接收、解析并入库；解析邮件内容本身失败时会临时性拒绝（要求对方稍后重投），而不是静默丢弃邮件。

## 适用范围 / 边界

- 仅适用于本工具「收件箱」模块作为 SMTP 服务端接收外部来信的准入环节，不涉及邮件内容的垃圾/病毒过滤、也不涉及发件功能。
- 白名单本身是否配置、配置了哪些条目属于运维配置范畴，本条只固化"两道白名单 + 三种发件人匹配口径 + 空白名单代表放行"这套判定规则本身。
- 若某发件人/收件域被拒绝，行为是直接在 SMTP 协议层拒绝该次会话动作（不接收信件），而非收下后静默丢弃或标记垃圾邮件。

## 备注

- 口径来源：kai-toolbox 代码调研起草，待 owner 核实（白名单具体条目、是否要支持黑名单/更多匹配模式等属于待定方向）。
- 易混点：发件人白名单的"子串匹配"口径较宽松（只要地址里包含该字符串即命中），与"域名后缀匹配"「精确地址匹配」是三种并存但判定粒度不同的规则，配置白名单条目时容易因为格式判断错走了哪种口径。
