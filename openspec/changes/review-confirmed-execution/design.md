# 评审交接边界

主对象为原会话内的评审待办，以评审空间、需求身份及修订版本去重；原会话确认权限沿用会话访问和标准执行策略。公开链接只可提交本空间的当前需求快照及读取本空间状态，不能指定原会话、队列消息或执行指令。普通评审问答不登记任务。旧反馈可幂等登记为一条待办，保留原文，不猜测拆分。

提交和登记同事务；确认时核对待办版本，持久化确认后的文本和队列消息关联，成功后才返回已交接。修订仅限待确认项，已排队或执行的内容不覆盖；新版需求保留旧任务，明确替代尚待确认的旧版。可按选择顺序合并执行，不自动生成完整 OpenSpec。执行结果来自既有接收、完成、异常及人工核对事件，结果未知不当完成，重试不新增相同任务。

原会话复用“计划评审”视图显示待办、来源、正文与验收条件，支持选择、编辑、合并及“确认并执行”；公开页原位展示交接和执行状态。不新建全局导航。后台入队不依赖浏览器存活，原队列失败挂起策略不变。初次批准队列无历史准入记录时仅建立首次调度凭据，现有未完成凭据不能覆盖；仍须 Sidecar 权威空闲、无待决策/后台作业并恢复原会话后才能派发。

适用 OBJ-01、CTX-01、DENS-01、FEED-01、CTRL-01、IDEM-01、AI-01、EVID-01，无例外。选择仅本会话有效，异步请求晚到不能覆盖新会话；编辑失败保留草稿，重复确认幂等。手机单列、操作可达、键盘可选择和确认；公开页面保留评审权限，不放开 steer 或编码命令。Ready 增量声明实际执行策略，普通工作台打开评审会话时也禁止自动回写开发设置，并使用本页排队讨论。

复用 SQLite 启动 schema 新增本模块待办表，不含人工运维 SQL；知识基线对新增表及队列回执表未核验，结构依据仓库 schema 与本次新增定义，验证使用隔离 SQLite。工程架构说明同步登记与授权、回执流。真实浏览器访问限制沿用，不换入口绕过；服务未重启时保留待运行验收。
