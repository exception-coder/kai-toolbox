# 设计

Forge 从现有模块标记文件识别构建模块；模块内 `features`、`domains`、`modules` 目录下的具名领域为子范围。父模块配置与子领域范围冲突，两个不同子领域互不冲突。前端共享源码及 Sidecar 普通源码按精确文件占用，两个执行只有修改同一共享文件才冲突。模块内数据库文件归所属模块或具名领域；仅仓库根 db/database/migration(s)/schema 目录和根构建配置保持全局范围；无模块归属普通文件、治理文件（含 design-baselines.json）按精确路径占用。OpenSpec change/spec 和设计文件继续按已有对象或精确文件归属。

已有索引（含旧单 writer）先核验项目、execution、session 与现存会话绑定，再从原执行 discovery.files、designFiles 和 change 重新投影；不信任旧 scopes 缓存。缺失或不一致记录明确拒绝，保留现场。读取不改写原执行、验证、代码或指针；新增索引不重复保存仍由旧指针持有的执行。扩大执行文件清单仍需重新 discover/assess；不根据代码引用关系猜测写入冲突。

适用产品原则：AI-01 保持项目、会话及声明文件范围身份；CTRL-01 冲突时明确阻断，释放只针对原执行；EVID-01 并行许可只表示文件范围不冲突，不代表构建或业务正确。此次没有新增导航或对话框。
