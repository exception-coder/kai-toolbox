# 项目编码门禁控制设计

## 控制点

项目真实目录下 `.forge/execution-control.json` 是唯一控制记录。Java 开发者 API 负责写入；Sidecar 与监督 Runtime 每次决策读取，不使用会话缓存。配置缺失默认启用，非法配置明确失败。控制文件不依赖 `.forge/spec-resolution` 的锁，因此损坏 writer 和旧存储锁不会阻止关闭。

GET/PUT `/api/claude-chat/sessions/{sessionId}/execution-control` 复用会话访问和项目排除策略，服务端从会话 cwd 得到真实项目。PUT 要求显示过的项目身份和 expectedRevision；版本冲突返回 409。同一后端写入串行化，文件原子替换，记录操作者、原因和历史；读取失败或保存结果不明时提供刷新核对。当前部署为单后端进程，不支持多个后端进程同时写同一项目控制文件。

## 关闭语义

WRITE/COMMIT/GIT/STOP、session_init 及编码执行绑定/完成/验证工具在读取旧 writer 前识别开关。返回 GOVERNANCE_DISABLED、skipped=true、verified=false、completed=false，宿主不回退到旧治理检查。原记录、工作文件和验证历史不变，不授予新文件范围或假完成旧执行。关闭后尚在运行的验证不能回写原执行。关闭不取消已启动命令，不保证中断之前已受理的原子操作。

监督候选预检、启动严格校验以及后续治理阶段服从开关；关闭时继续实际未完成的开发 task，开发项结束后以 DEVELOPER_HANDOFF 停止或进入所选批次下一项，保留人工事项。新交接明确覆盖旧门禁提示。已有暂停不自动恢复；预算、真实任务、会话访问、生产及服务重启授权保留。重新开启时按照现有证据重新检查；关闭期间改动可能需要正式补充范围和重新验证。

## 交互

适用产品原则：CTRL-01（开发者控制）、FEED-01（实际保存结果）、AI-01（不冒充验证）、EVID-01（记录来源）、IDEM-01（版本及相同状态幂等）、DENS-01（嵌入既有监督面板）。无需新增导航。开关说明项目路径及全项目影响，键盘可操作，移动端触控区域至少 44px、路径折行。网络失败保留已知状态并提供刷新，不乐观宣称已切换。没有原则例外。

## 边界与验证

不新增鉴权体系，不提供 MCP 修改开关，不绕过资源执行或生产权限；Hook 仍不是任意 Shell 的安全沙箱。回归覆盖项目隔离、同项目双会话、损坏 writer、开关恢复、审计、CAS、访问拒绝、监督交接和界面保存失败。代码与运行部署分别验收；首次加载新代码需明确授权重启，之后切换不需要重启。
