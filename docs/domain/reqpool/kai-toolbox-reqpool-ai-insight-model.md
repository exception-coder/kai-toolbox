## 业务定义

**AI需求洞察** = 由AI对一条需求做的价值评估分析结果，围绕以下七个维度展开：

- **建议优先级（priority）**：AI给出的优先级建议，分"战略级／高优先／可排期／可延期"四档——比需求本身人工填写的"优先级"多出一档"战略级"，专门用于标出对核心业务有战略性影响、必须优先做的需求。
- **价值星级（stars）**：1~5 分的综合价值打分，作为一个直观、可比较的量化排序信号。
- **一句话建议（recommendation）**：给产品经理的简短行动建议。
- **理由（reason）**：给出以上建议的简短说明，聚焦业务价值角度阐述。
- **影响面（impacts）**：这条需求会波及的系统/模块/用户群清单，用于评估改动的辐射范围。
- **投入产出比（roi）**：需求的价值与开发成本的比值高低，分"高/中/低"三档。
- **预估工时（estimatedHours）**：粗估的开发工时（含前后端），仅供参考，不是精确排期依据。

以上评估综合考虑四个维度：业务价值（覆盖用户面、解决痛点的迫切程度）、战略重要性（与核心业务的关联度）、实现复杂度（技术风险和工时）、投入产出比（价值/成本比）。

该结构存在一个"组合分析（Portfolio）"变体：不孤立评估单条需求，而是把一批需求放在一起横向比较，在同样七个维度基础上，额外附加"相对排名"和"与其他需求的对比差异说明"（见同模块的Portfolio横向优先级排序流程知识点）。

## 适用范围 / 边界

- AI需求洞察是给产品经理的"辅助决策参考"，不是需求状态机的一部分，也不会直接驱动需求状态流转——产品经理可以采纳建议，也可以忽略或手动覆盖。
- 单条分析与组合(Portfolio)分析共用同一份存储位置：触发一次组合分析后，此前单条分析得到的洞察结果会被整体替换为组合分析的结果。

## 备注

- 口径来源：kai-toolbox 代码调研起草，待 owner 核实。
- 易混点：这里的"优先级"有两套概念——需求本身人工设置的优先级（高/中/低三档）与AI洞察建议的优先级（多一档"战略级"，共四档），两者是独立字段，AI的建议不会覆盖需求本身人工设置的优先级值。
