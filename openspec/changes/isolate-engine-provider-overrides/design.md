## Decisions

服务商档案与凭据继续由既有 Java 服务持有。新增 OpenCode 覆盖通过 SDK createOpencode 的 config 参数传入子进程 OPENCODE_CONFIG_CONTENT，每轮独占随机端口进程，结束或失败释放；原生默认客户端不变。禁止修改用户配置和父进程环境，不调用全局 provider/auth 写接口。权限回复必须路由本轮客户端。

第三方目录由 Java 唯一提供，Sidecar 不发送原生目录覆盖它。前端统一能力判断与现有模型输入控件，服务端同样拒绝不支持的组合。Qwen modelProviders 优先级高于 env，未验证隔离前维持不支持；Trae、Antigravity 不假设支持通用 Key。

适用 OBJ-01、CTX-01、FEED-01、IDEM-01；沿用配置面板，不增加导航。错误保留会话，切换到不支持的引擎时提示先切回原生服务商，不偷偷清除凭据或切路由。

## Verification

Codex 具名复核：采用独立 OpenCode 进程及随机端口；请求前读取生效配置核对模型、地址和 Key，受管配置冲突时停止而非回退。目录携带当前工作目录，权限回复使用活动客户端。测试断言仅输出布尔比较结果，避免环境差异打印凭据。

回归覆盖独立配置、默认配置不变、凭据脱敏、模型目录所有权、能力矩阵和失败释放。真实供应商、目标版本运行验收须获重启授权后执行。未部署。

完整范围审阅结论：Java 能力集合拒绝未知引擎、原始地址和档案 ID 两类入口；前端复用同一判断函数。并发目录回写检查引擎、地址、Key、模型快照。当前 Sidecar 6 项及前端 9 项回归、Java 能力矩阵 1 项通过；本地 mock 验证不等于已验证目标 CLI 的全局插件或受管策略。
