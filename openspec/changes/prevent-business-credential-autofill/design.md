# 防误填设计

## 证据与范围

咨询标题、历史筛选初始化为空，只有输入事件改变本地草稿或筛选；不会因填入账号字符串而切换认证身份。截图尚不能证明填充来自浏览器内建密码管理器还是扩展，真实浏览器复核保持未完成。

采用现有 HTML 表单能力，适用 CTX-01、FEED-01、EVID-01，无例外。此次不改变 AI 编程架构、认证接口或权限。

## 实现

- 公共 Input 默认 `autocomplete=off`，调用者显式声明凭据或其他用途时继续尊重该值。
- 咨询标题和历史筛选使用稳定的业务字段名称与独立表单，关闭自动完成；提问人筛选使用 search 类型。手机编辑器标题同样声明用途与关闭自动完成。
- 真正的登录使用独立表单，账号/密码具有稳定 name、id 与 `username` / `current-password` 标记。通过原生 submit 调用现有登录方法，取消按钮不提交；保留错误反馈与焦点恢复。
- 管理员创建他人账号使用独立的新建表单，用户名不标记为当前登录账号；新密码保留 `new-password`。真实账号绑定中的凭据用途不改。
- 不按 admin 等具体字符串清理字段，不设置只读后解锁、不放置伪装密码框，不禁用用户正常手动输入或修改浏览器密码设置。

## 浏览器行为边界

自动完成是浏览器及密码管理器的能力，字段名称、类型、用途与表单归属参与识别。`off` 是页面表达的意图，无法保证所有浏览器或扩展强制遵守，不能仅凭属性回归宣称已复现并消除所有误填。

参考：[MDN autocomplete](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/autocomplete)、[Chrome 团队登录表单实践](https://web.dev/articles/sign-in-form-best-practices)，2026-10-18 查阅。前者说明密码管理器可能忽略 off，后者建议登录与搜索分别使用表单并明确字段用途。
