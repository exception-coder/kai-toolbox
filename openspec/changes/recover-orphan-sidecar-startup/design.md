## 证据和范围

用户提供的故障日志为 `Claude Sidecar 端口 18890 仍被占用，等待旧进程退出超时`。源码 `scripts/runtime/runner.mjs` 确实在后端启动前等待 15 秒并抛错退出；`SidecarProcessRegistry` 的清理发生在 Java 启动后的首次会话，所以无法打破这个启动阻塞。原 Node 关闭依赖信号和无截止时间的异步清理，Java 强制结束后未等待确认便清空句柄；这些代码缺口支持遗留进程风险，不证明同事机器的具体退出时序。当前本机日志另有历史构建 EPERM，不与同事现场混为一谈。Graphify 图谱超过读取上限且陈旧，使用上述定向源码核对。

## 生命周期与安全归属

Java 仍是 Sidecar 的唯一进程所有者，使用绝对入口 argv 和专属 stdin 管道启动 Node。Node 仅在声明的父 PID 与实际父 PID 一致时监控管道 EOF、close 和 error；父进程异常退出也会关闭写端。退出先释放监听和客户端，再清理 Graphify 与 telemetry；3 秒仍未完成则以失败退出。Java 关闭管道后等待 3 秒，再分阶段终止并等待，仍未退出则保留句柄和错误，不假报停止。关闭与启动串行，关闭后禁止重新拉起。

正常启动等待端口释放；超时后只读核对实际监听 PID、Node 可执行文件、绝对入口、本工作区及父进程状态。Windows 用 netstat 与有超时的 CIM 查询，显式 UTF-8，优先 PowerShell 7，缺失时使用清理模块路径后的 Windows PowerShell；Unix 使用 lsof/ps，不能取得证据时保守保留。终止前再次核对 PID、命令和可用的创建时间，拒绝已变化的身份；回收后最多再等 5 秒。不会仅凭全局 pid 文件、进程名、端口或相对 `dist/server.js` 杀进程，也不杀仍有活跃父进程的另一实例。

## 启动隔离与兼容

| 条件 | 构建与宿主行为 |
| --- | --- |
| 端口空闲或正常退出已释放 | 准备依赖、构建 Sidecar，再启动 Java |
| 本工作区绝对入口且父进程已退出 | 核验并回收，确认端口释放后正常准备 |
| 无法确认归属、活跃父进程、回收失败 | 不改 node_modules/dist；通过本次进程的 Spring 配置阻止 AI 启动，宿主继续启动 |
| 构建过程中出现新端口占用 | 明确记录构建失败并阻止 AI 使用，宿主继续启动 |
| 无端口冲突的编译或依赖错误 | 保留原失败行为，不吞掉一般构建错误 |

`toolbox.claude-chat.sidecar-startup-error` 仅在本次启动环境传递诊断，不写持久配置；后续授权重启重新判断。受阻时用户的 AI 操作返回既有 SIDECAR_DOWN 错误及具体恢复说明；普通模块可用不代表 AI 就绪。SDK 升级仍必须确认端口释放，不能因进程句柄为空而覆盖在用产物。

旧版 Windows Sidecar 若只留下相对 argv，无法安全证明工作区归属，因此不会自动回收；需要在原所属进程管理器处理后再明确确认重启。此兼容边界保证宿主可恢复，不宣称无需人工介入即可恢复所有旧版 AI 进程。安装本次代码不会立即改变运行中的旧进程。

## 验证边界

隔离端口覆盖真实孤儿回收、父管道断开、清理卡住、错误身份和并发占用。Java 定向回归覆盖拒绝未知监听者、启动阻断、关闭等待及 SDK 升级；完整宿主装配用于验证配置和依赖，不启动另一个 Forge。真实 Forge 重启、同事现场及 60 秒稳定观察须另获本次重启确认后执行；不以 PM2 online 或单测通过代替运行验收。
