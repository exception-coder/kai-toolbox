## ADDED Requirements

### Requirement: 普通 Codex 会话尾部优先读取
系统 SHALL 允许当前授权会话选择字节游标分页，在有界完整轮次窗口中读取最近消息，不等待全文件用量索引。

#### Scenario: 首次读取与继续分页
- **WHEN** 普通 Codex 会话请求 pagination=cursor 的最近页或更早游标
- **THEN** 从文件尾部完整轮次读取最多请求项数，以文件位置形成稳定消息身份，并提供可跨读取器重建的 nextCursor
- **AND** 不足一页或空窗口不冒充终点，追加内容不移动已签发快照的分页边界

#### Scenario: 文件变化与超长单轮
- **WHEN** 游标不匹配、文件被替换/截断，或快速窗口不能覆盖完整轮次（包括超长单轮与缺少轮次标记的旧记录）
- **THEN** 保留现有消息，分别提示用户重试最近页或选择完整历史兼容读取，不自动重放消息或无限扫描

#### Scenario: 兼容与评审隔离
- **WHEN** 旧客户端、旧服务器、其他引擎或公开评审读取历史
- **THEN** 保留整数 before 的原逻辑；评审拒绝普通字节游标，普通游标不绕过逻辑会话权限与 CODEX_HOME 归属

### Requirement: 首屏按需加载

系统 MUST 保留前端 manifest 的菜单与路由权威性，注册菜单时不求值无关页面组件。隐藏的悬浮窗和语音界面 MUST 不阻塞首屏下载；开启后仍可使用同一常驻会话。普通 Markdown MUST 不预先下载图表库，品牌图标 MUST 保持原有形状与可访问属性。

首屏工具类 MUST 仅由真实 UI 源码生成，不将父目录、本地缓存或构建输出作为扫描范围。入口 HTML 加载壳 MUST 沿用独立的手写样式。

#### Scenario: 进入开发工作台

- **WHEN** 用户直接进入 Vibe Coding，未开启悬浮窗与语音界面，消息不含图表
- **THEN** 先加载工作台必要资源，不通过菜单注册连带下载交付弹窗、SQL 控制台、整套品牌图标集合或图表库

#### Scenario: 使用按需功能

- **WHEN** 用户开启悬浮窗或语音界面，或收到后台提问，或消息含 Mermaid 图表
- **THEN** 加载对应功能，维持现有会话与权限边界，功能失败由自己的错误边界或源码降级呈现，不拖垮工作台

#### Scenario: 工作区存在本地构建或分析缓存

- **WHEN** 开发工作区中存在临时构建产物或本地分析缓存
- **THEN** 主样式仅扫描 UI 源码，现有桌面和手机界面的工具类继续生成，入口 HTML 的加载壳样式保持独立，不因无关文件扩张样式扫描

### Requirement: 最近会话快速恢复

系统 MUST 在有近期已确认会话提示时立即启动恢复，并异步核验提示；无提示时按服务器列表恢复最近会话。提示 MUST 不包含聊天内容且不能绕过服务端授权。

#### Scenario: 刷新最近会话

- **WHEN** 用户刷新 Vibe Coding 且浏览器有有效会话提示
- **THEN** 客户端不等待完整会话列表即可发起连接，聊天记录另行加载

#### Scenario: 提示失效

- **WHEN** 列表中不再存在提示会话
- **THEN** 客户端更新提示并恢复有效的最近会话，不覆盖期间用户主动选择的其他会话


### Requirement: 最近历史有界复用与加载恢复

客户端 MUST 以当前登录凭据和服务器会话身份隔离最近消息页缓存，限制缓存容量、数量与有效期。缓存 MUST 不落盘，切回显示缓存时 MUST 标明正在更新并继续请求最新页；公开评审和演示不得复用登录缓存。

#### Scenario: 切回已读取会话

- **WHEN** 当前登录凭据下存在未过期且未被淘汰的最近页
- **THEN** 立即显示该会话缓存，在 ready 后更新权威历史，更新失败保留内容并提供重试，重试不误读更早页

#### Scenario: 过滤导致空白

- **WHEN** 已加载消息经工具隐藏过滤后没有可见消息
- **THEN** 页面说明已加载及隐藏状态，并提供显示工具记录的按钮

#### Scenario: 切换期间旧会话迟到事件

- **WHEN** 用户选择其他会话，原会话的输出、ready 或历史响应随后到达
- **THEN** 不将这些内容写入新会话或其缓存，不改变当前选择；目标会话的正常输出继续呈现，快速连续切换只连接最终目标

#### Scenario: 登录变化或缓存超限

- **WHEN** 登录凭据变化、缓存过期或正文容量超限
- **THEN** 不复用失效缓存，按现有授权流程读取历史且显示最近消息加载状态

### Requirement: 最新消息导航核对权威末尾

已有历史加载能力的消息视图 MUST 在用户点击「跳到最新」时区分实时输出与历史恢复。连接 ready、正在生成、已有可见消息且没有历史请求在途时，MUST 直接定位当前实时末条底部并继续跟随，不用可能滞后的落盘快照替换输出。其他状态 MUST 读取权威最近页，等待新数据提交后定位当前末条底部。客户端 MUST 不将旧缓存末尾或更早分页的完成误当作最新页确认；同一最新页在途请求 MUST 复用。最近页替换前后条数不变时，仍 MUST 按最新条目身份维持贴底，且不打断主动上滑的阅读。

#### Scenario: 正在生成的回复领先于落盘历史

- **WHEN** 已连接会话正在生成，列表已有可见消息、没有历史请求在途，用户点击跳到最新
- **THEN** 立即定位当前实时末条，不发起最近页替换，不等待落盘进度
- **AND** 同条回复增长或追加下一条回复后继续贴底，用户主动回看仍撤销跟随；连接尚未恢复时保留权威历史读取

#### Scenario: 慢速更新替换同条数缓存

- **WHEN** 用户在缓存中点击跳到最新，权威最近页延迟返回且条数与缓存相同
- **THEN** 显示获取中，等待新数据提交后对齐最新消息末尾；高度校正不因固定时间窗口提前停止，实际贴底后才隐藏入口

#### Scenario: 更早分页尚在执行

- **WHEN** 用户加载更早消息时点击跳到最新
- **THEN** 更早页完成后另取权威最近页，不将更早请求视作最新页结果，不重复并发读取同一最近页

#### Scenario: 定位后的列表尺寸校正

- **WHEN** 最新消息定位后，回复增长或输入区、队列改变消息列表尺寸
- **THEN** 在用户未主动撤销定位且实际离底时，通过虚拟列表校正到末项，不要求消息总高度变化
- **AND** 用户主动上滑或定位旧消息后停止校正，不将其误当作自动尺寸变化

#### Scenario: 定位完成后重复收到位置与尺寸通知

- **WHEN** 最近页已定位完成，列表重复报告离底状态或相同尺寸
- **THEN** 离底状态通知只更新呈现状态，不触发新的滚动；已经实际贴底时尺寸通知不再校正，清除加载状态不重复定位

#### Scenario: 长历史跳转后滚动补偿移回旧回复

- **WHEN** 回看长历史后点击跳到最新，虚拟列表在命令执行后调整滚动位置，总高度没有变化
- **THEN** 在实际挂载的消息滚动容器收到滚动事件后，每帧合并核对真实离底距离，通过虚拟列表公开接口重新对齐实际底部
- **AND** 实际贴底后停止写入；用户主动回看、切换会话或卸载列表时撤销待执行校正，不持续轮询

#### Scenario: 跳转后末项仍需重新测量

- **WHEN** 点击跳到最新后，最后一批消息挂载测量导致滚动总高度变化
- **THEN** 显式跳转重建当前虚拟列表的旧测量缓存，从 LAST/end 开始，使用末项索引定位及其测量重试、补偿抑制能力对齐真正末项，不以首次临时滚动范围固定像素目标
- **AND** 正常实时消息追加不重建列表，输入草稿与会话身份保持
- **AND** 用户主动回看或切换会话仍撤销后续自动定位

#### Scenario: 虚拟列表反复补偿导致位置往返

- **WHEN** 同一次最新定位期间，滚动补偿持续移回旧位置，消息总高度与视口高度不变或在已见组合之间交替
- **THEN** 每个测量组合最多自动补偿一次，不通过原生滚动和高度通知形成逐帧写入循环
- **AND** 实际新尺寸仍可校正；用户再次点击跳转开启新的定位，主动阅读或切换会话取消定位及其校正记录

#### Scenario: 从多页历史回到最近页

- **WHEN** 最近页更新裁掉前面的历史，或更早分页与末尾新消息同时到达
- **THEN** 同一消息的虚拟索引与高度测量保持对应，最新定位不因旧页裁剪发生错位

#### Scenario: 获取失败与定位撤销

- **WHEN** 获取最新页失败，或用户等待期间主动上滑、定位旧消息或切换会话
- **THEN** 失败保留现有消息与原位重试入口；主动导航取消定位意图，迟到响应不强制跳转或污染其他会话
