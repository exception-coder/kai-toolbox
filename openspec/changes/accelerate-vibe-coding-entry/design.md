# 首屏恢复设计

## 大 Codex 历史尾部读取（2026-10-20）

适用 CTX-01、FEED-01、EVID-01、IDEM-01，无原则例外。界面保留原消息页与加载更早/重试入口，不新增导航、弹框或后台写操作。已核实目标约 658 MB，旧冷读取 21.56 秒超过前端 20 秒预算；每次最多返回 30 项不能约束旧索引的首次全文件扫描。旧索引热读、用量与评审能力保留，不将界面历史读取混同于模型原生恢复。

一期采用可选 `pagination=cursor`，普通 Codex 会话从文件尾部 2 MiB 窗口按需倍增至 32 MiB，定位完整 task_started，再复用原元数据索引与正文物化逻辑。turn_context 可能来自中途恢复或压缩，不能独立作为边界；孤立用户消息也不足以恢复前置去重与轮次状态。窗口可覆盖全文件时从文件头读取；否则缺少完整轮次标记的旧记录与超长单轮均提供旧协议兼容入口，不返回半轮统计。不同窗口独立加锁，最多缓存 8 个窗口，不等待用量索引的全文件锁。不增加常驻扫描、Redis 或 SQLite 表。每页最多 100 项的服务端上限；Vibe 仍请求最多 30 项。

字节分页的返回值新增可选 nextCursor；旧 nextBefore 和三参数 MessagePage 构造保留。游标含版本、快照长度、文件身份/固定片段摘要、窗口范围和页内索引，不含正文或可指定的文件路径，不作为授权凭据；登录身份、逻辑会话、原生句柄和 CODEX_HOME 仍由原控制器校验。消息 ID 以 hb 前缀和源偏移形成，在窗口重建和追加时稳定，仍与实时项分离。快照追加允许继续旧页；替换、截断或不匹配游标返回 409，用户重试重新读取最近页。游标跨进程可重建，因此首期不持久化完整索引或最近消息正文。

不足 30 项不等于终点，空窗口仍以是否有推进的 nextCursor 判断；不自动无限追逐旧页。单轮超出 32 MiB 时返回 413，保留消息并提供明确的用户点击兼容读取，重置到完整历史最近页，可能仍较慢，不放宽原 20 秒超时或伪造完整数据。服务端不静默截断工具正文或统计。公开评审保留原 cwd 继承边界并拒绝普通字节游标；其他引擎、旧前端、旧后端及整数 before 继续旧协议。

Java 21 的 FileChannel 绝对位置读取是实现依据（[官方 API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/nio/channels/FileChannel.html)），不依赖新的 SDK 或外部服务。二期只在实际需求驱动下扩展超长单轮细分和其他引擎，不在本轮引入第二套持久会话索引。真实样本计时、分页语义对照、文件变化/账号边界、旧协议及前端恢复为首期验收；服务加载和浏览器端到端证据单独记录。

## 首屏静态依赖与按需下载

适用 DENS-01、CTX-01、FEED-01、EVID-01，无原则例外。2026-10-08 启动诊断再次记录应用挂载前等待约 12–18 秒；生产构建的入口及静态依赖含 304 个项目源码模块、约 1.43 MB 压缩前 JavaScript。菜单注册的汇总导出连带求值交付弹窗、消息列表和 Mermaid；开发服务中两个品牌图标集合响应合计约 7.64 MB。它们是可消除的首屏负担，不能据此认定已解释全部手机网络耗时。

菜单继续由原有 eager manifest 发现，入口适配单独通过轻量 public-api/navigation 导出；实际页面与业务 API 保持原边界。保留旧路由、查询参数和资源权限校验。跨路由聊天实例继续常驻，但悬浮窗仅在开启且路由可见时首次下载；即使记住开启状态，进入聊天页也不下载隐藏浮窗。语音层在开启时下载，后台提问出现时下载答题层，各层使用独立 Suspense 和错误边界。浮窗首次使用后保留组件状态，隐藏时连同其错误恢复一起隐藏；手动首次弹出显示完整窗口，刷新恢复沿用紧凑形态与原最小化、位置和尺寸。胶囊宿主桥仍正常挂载，不因其他隐藏层等待而一起消失。

普通 Markdown 不下载图表库；遇到 Mermaid 代码块才加载并初始化，失败仍展示源码与错误，卸载或内容改变时拒绝迟到渲染。品牌图标从当前锁定的 react-icons 生成六个 SVG 数据子集，沿用其小型运行时与原路径、尺寸、着色及许可证；新增或升级图标时可重新生成并核对差异。不会改成通用图标或减少引擎入口。

本轮验证发现未忽略的临时构建产物被样式扫描和开发服务监听，伴随重新加载，CSS 请求超过 20 秒仍未返回。主样式使用 Tailwind 的显式 source，仅扫描 `frontend/src`，排除本地分析缓存和构建输出；保留全部真实 UI 源码及共享组件的样式。注册位于父目录的 `../index.html` 仍会触发昂贵遍历，两组交换顺序的实测扫描为约 10–22 秒；只保留源码扫描为约 0.6–1.4 秒，生成 CSS 完全一致。加载壳沿用 HTML 内的手写样式，不注册到扫描器；回归在内存中提取 HTML 候选并确认没有新增工具类。验证构建产物保存在已忽略、已有监听排除规则的 `frontend/dist/entry-verification`，不扩张扫描范围，不修改开发服务配置或重启服务。

验证覆盖菜单元数据不求值页面组件、隐藏层不下载与开启后可恢复、图表延后加载及失败降级、生成图标与依赖原图一致，以及真实 Tailwind 编译的扫描文件范围和必要工具类。比较修改前后的入口静态依赖和构建产物；复用受限阶段日志核验浏览器实际挂载耗时，明确区分本机、手机布局与外网真机。不触发 assistant:release 或生产发布。本次为内部加载边界调整，不改变 AI 编程证据与交付架构契约。

## 首页渐进入口

适用 NAV-01、DENS-01、CTX-01、FEED-01。主对象是现有 Vibe Coding 模块及其服务器会话，入口仍使用 manifest 中的 `/tools/claude-chat` 路由；不建立第二份会话或菜单目录。首页最先显示已获授权且未隐藏的 Vibe Coding 入口，其他菜单在空闲时补齐。命令面板及视频搜索首次打开再下载，避免抢占首屏资源。

React 尚未挂载时，HTML 加载壳可基于同源登录权限快照显示快捷链接；仅用于提前导航，最终访问仍由现有路由和服务端鉴权裁定。无快照、快照损坏或无权限时不显示。链接有明确焦点样式，手机窄屏可触达；点击后保留普通可分享路由。资源失败继续显示加载壳，现有根错误边界处理应用挂载错误。该优化不新增写操作，重复点击只导航到同一路由。需要在真实手机上分别测量 HTML 响应、React 挂载和 Vibe Coding 可交互时间；构建成功不等于秒开验收。

刷新诊断：每次页面装载生成一个 trace ID，记录应用、聊天运行时、会话查询、会话切换、ready 及最近/更早消息分页的相对时间和结果。仅登录请求可以上报，后端只接受固定阶段、状态、时长和 UUID；日志不含消息正文、URL、凭据或音频。诊断上报异步发送，失败不阻塞聊天。会话列表在服务端另记录授权、transcript 检查、规划状态及映射各阶段耗时。该日志用于区分静态资源、会话恢复和历史消息请求的等待时间；真实手机耗时需在新版后端启用并刷新后核验。

首屏资源诊断补充 HTML 响应结束时间及静态模块汇总：Vibe Coding、其他功能、公共模块的请求数量，以及合计传输字节、最晚完成时间、最慢单项耗时。客户端只发送数字，不发送资源路径；结合现有 app/page mount 可分辨网络模块加载与后续执行。Vite dev 的模块响应为 no-cache，外网经隧道单个主脚本/会话路由请求在本机观察约 0.67/1.05 秒，因此仅凭后端 API 加速不足以判定整页秒开。补充日志上线后以真实手机 trace 核验。

HTML 入口在主应用未取代 boot-shell 的 10 秒后，用同一 trace ID 报告一次 bootstrap_timeout。此小脚本只在 Vibe Coding 路径运行；仅持有登录 token 时通过受保护诊断接口发送固定字段，正常挂载后不发送，避免主应用尚未执行时出现观测盲区。

运行诊断显示会话列表在 609 条记录上耗时约 3.5–5 秒，其中访问过滤占 3.3–4.7 秒。列表已有完整实体，却逐项用 ID 重新查询数据库。改为对已读实体执行同一访问策略，保持所有权与项目可见性规则，并用回归测试确认不会逐项查库。第二次后端重启后，访问过滤日志约 0.09–0.20 秒，HTTPS 前端代理三次列表请求耗时 0.25、0.24、0.34 秒，均返回 200。手机浏览器从导航到可交互的完整耗时尚未核验。

适用 CTX-01、DENS-01、FEED-01、IDEM-01。主对象仍是服务器会话 ID。浏览器按登录用户 ID 仅保存最近一次已由会话列表确认的 ID，七天过期；刷新时可直接用它开始连接，服务端负责最终授权。若列表显示提示失效或另一设备有更新的会话，回到最新有效会话；用户期间已主动切换时不覆盖其选择。明确 URL 会话和 PRD handoff 仍沿用各自校验路径。

聊天消息不进入提示缓存，继续在会话 ready 后分页加载。最近一页与更早分页要区分错误文案；旧页只由用户点击顶部入口或显式定位操作触发，列表首屏挂载和初始滚动不得自动拉取旧页。定位操作失败后停止自动分页，等待用户重试，避免大历史或慢网络下连续请求压住最近消息。对于直接访问 Vibe Coding 的开发服务页面，Vite 保留的独立 HTML 模块脚本提前请求路由模块，利用浏览器模块缓存复用 React.lazy 随后的同一导入；自由对话模式和生产制品不执行开发模块路径。Mock 模块只在 Mock 模式加载，运行时开启 Mock 时先完成注册再切换，避免正常启动引入无关开发资源。轨迹、用量、文档、SQL、推进、评审、Git 工具及低频弹窗代码从会话首屏拆出。此更改不调整后端协议、持久数据或架构边界。


## 最近消息缓存与空白恢复（2026-10-07）

已确认 Codex 后端使用最多 16 个会话视图的增量索引，热读取只扫描新增记录并物化目标页；冷启动仍需建立索引，不能仅凭文件大认定每次请求全量读取。前端切换会话原先立即清空消息，等待 ready 后才请求最近 30 条；隐藏工具时最近页可能没有任何可见消息。截图不足以证明具体一次空白由哪一条件造成。

适用 CTX-01、FEED-01、IDEM-01、EVID-01。保留现有会话页及公共历史接口，用当前 hook 内的独立最近页缓存减少切回空白；以服务器会话 ID 为身份，登录凭据变化后失效。最多 8 个会话、序列化正文估算合计 4 MiB、10 分钟有效，超大页不缓存，公开评审和演示不缓存。不写 localStorage/sessionStorage，不持久化完整 transcript；刷新浏览器和新标签页仍从后端读取。

切回时先显示已读取快照并提示更新中，ready 后仍请求权威最近页。失败保留缓存和重试入口，重试优先更新最近页；成功替换缓存，权威空页清除旧历史但保留期间的新消息。原有请求编号及会话身份校验继续拒绝迟到响应。未产生历史的新会话收到 ready 后结束加载状态。

会话选择同时拥有独立的浏览器观察连接。切换、新建或恢复历史时先让旧连接回调及在途建连代次失效，再连接目标会话；旧输出、ready、关闭回调和未发送文本不得写入新目标。此措施兼容不含会话 ID 的旧文本/工具事件，不调整后端消息协议，也不停止原会话的代码任务。队列和后台任务摘要随选择清空，目标 ready 后从其自身快照恢复；最近页缓存仍按登录凭据与服务器会话 ID 读取。

最近页全被工具过滤隐藏时显示状态文字及原生按钮恢复工具可见性，支持键盘操作与窄屏换行；不自动循环加载旧页、不另建弹窗。界面测试覆盖恢复按钮和初始加载提示。缓存是浏览器局部呈现优化，不改变引擎上下文、权限、验证或交付生命周期。

## 最新消息定位恢复（2026-10-12）

适用 OBJ-01、CTX-01、FEED-01、IDEM-01、EVID-01，无原则例外。主对象及唯一身份仍是服务器会话 ID，复用现有历史接口与消息列表按钮，不新增页签或覆盖层。诊断确认权威最近页包含用户截图之后的最终回复；原按钮只定位已加载数组，缓存切回后的同条数替换不触发 Virtuoso 的按条数跟随，点击时开始的 1.5 秒高度校正也不能覆盖慢请求。

显式跳转在连接 ready、正在生成、已有可见消息且没有历史请求在途时，直接在当前实时列表中定位实际滚动底部并恢复跟随，不先读取可能滞后的落盘历史。其他状态保留读取权威最近页后、在 React 提交后的当前列表定位。Virtuoso 统一持有滚动、尺寸测量与内部重试；列表总高度、视口尺寸或跳转后的原生滚动位置变化时，每帧合并一次校正，先读取真实离底距离，超过统一的 8px 贴底容差才通过其公开 scrollTo 接口对齐实际底部，不直接写 DOM 滚动位置。Virtuoso 的离底状态通知只更新按钮状态；实际滚动事件核对仍有效的跟随意图，不使用该状态通知驱动滚动；清除加载状态也不重复下发相同末项的定位。补齐不使用固定时间窗口、不持续轮询，保留跟随意图直到用户主动导航。最近页读取在途时复用同一结果；更早页在途时先等待，再读取最近页，仍由会话身份和请求编号拒绝旧响应。成功更新同一有界缓存并保留新实时消息；明确区分读取失败和原生历史尚未就绪，失败保留内容，按钮显示失败重试，不宣称缓存已是最新。

未主动离底时，缓存替换依据最新条目的身份补齐位置，即使条数仍为 30。上滑、触摸阅读、键盘导航、定位旧消息或切换会话会撤销待完成的定位意图；迟到成功不能将用户拉回底部。按钮保持原位，键盘可达，获取中禁用重复操作，手机自动换行。主窗口、分屏、悬浮窗与公开评审页沿用各自已有授权历史通道。只核对最近页，不全量读取 transcript、启动模型或改变草稿与队列。该修复保持 AI 编程架构契约。
