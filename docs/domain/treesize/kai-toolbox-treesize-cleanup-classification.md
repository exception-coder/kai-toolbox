一次磁盘扫描结果不是直接罗列大文件/大目录，而是先归类成「清理候选」，再按安全等级排序展示给用户。分类与排序口径本身就是业务规则：换一套扫描引擎重写，只要还想给用户「这个能不能删」的建议，就需要保留同样的判定标准。

## 业务定义

候选分五类，判定条件互不依赖实现细节：

1. **缓存类（安全）**：目录名命中常见构建产物/依赖缓存/临时目录关键词（如依赖缓存目录、构建输出目录、临时目录），或路径命中日志目录、`.log`/`.tmp` 后缀。业务含义：通常可重建，建议优先清理；但若命中的是正在运行服务的日志目录，需先确认该服务的日志轮转策略再删。
2. **Docker 占用（需人工确认）**：路径命中 Docker 数据目录特征（镜像/容器/卷/构建缓存的存储路径）。业务含义：直接删目录风险高，应通过 Docker 自身的清理命令或精确定位无用卷来清理，而不是本工具直接删除。
3. **大而旧文件（需人工确认）**：单个文件大小 ≥ 1 GiB，且最后修改时间在 90 天以前（或修改时间缺失，出于保守也归入此类）。业务含义：具备"占地方 + 长期未变动"两个信号，值得人工确认是否还需要，但不能确定就是垃圾。
4. **疑似重复文件（需人工确认）**：文件名（忽略大小写）与大小同时相同、且同一批扫描结果里出现 ≥ 2 份。业务含义：只是"名字+大小一致"的弱信号，不代表内容一致，精确判重需要额外做内容校验（如哈希比对），本工具只提示疑似，不代自动下删除结论。
5. **危险区域（仅提示风险，不建议在本工具内处理）**：路径命中数据库数据目录特征（MySQL/Postgres/MongoDB 等）、上传/业务数据目录特征，或文件名以数据库文件后缀结尾（`.db`/`.sqlite`/`.sqlite3`）。业务含义：疑似是数据库文件或业务上传数据，误删代价极高，工具只做风险提示，不建议在本工具内直接删除，应先确认备份、业务归属和停机窗口。

**安全等级排序**：候选列表先按安全等级升序（安全 → 需人工确认 → 危险）排，同等级内再按体积降序排，让用户优先看到"最安全、最值得清"的候选，危险区域排在最后仅作提示。

每一类的判定条件互相独立、可以同时命中同一节点（如一个大文件同时落在"大而旧"和"危险区域"里），各自作为独立候选呈现，不做去重合并。

## 适用范围 / 边界

- 该分类只是"建议"，不代表自动执行删除；是否真删、删哪个，仍需人工在候选列表里逐条确认。
- 阈值（1 GiB、90 天、每类最多展示 80 条）是当前产品给出的经验口径，属于业务口径的一部分，调整需要走 owner 评审而非随意改动。
- 疑似重复文件的判定仅基于文件名+大小，不做内容校验，因此不能作为"确认重复"的依据。
- 该口径与具体扫描引擎、存储介质无关，只要还提供"清理建议"这个功能，五类候选 + 安全等级排序的语义就应该保留。

## 备注

- 口径来源：kai-toolbox 代码调研起草（阈值来自 tool-treesize 磁盘清理建议逻辑），待 owner 核实是否仍是当前生效值。
- 易混点：安全等级（SAFE/REVIEW/DANGEROUS）是"删除风险高低"的排序依据，不是"文件重要性"的评判——危险区域排最后是因为最容易误删、不是因为最不重要。
