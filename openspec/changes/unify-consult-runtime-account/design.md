# 业务咨询统一账号与上下文接续

## 对象、权限与入口

适用 OBJ-01、CTX-01、DENS-01、FEED-01、AI-01、EVID-01、CTRL-01、IDEM-01，无例外。沿用咨询 ID、已有默认模型设置及原会话入口，不增加普通用户账号选择。平台聊天 ID 保持稳定，使附件、生成文件与授权继续依附原对象。账号变化时创建新的原生线程段，保存原账号/原生线程关联；切回旧账号也创建新段并重新接续当前历史，避免复用过期上下文。

## 决策与边界

- toolbox-llm 的公共 SPI 隔离咨询策略与聊天执行器；各模块只访问自己拥有的表。
- 咨询策略在实际轮次准入时解析（含排队释放），以持久策略版本冻结账号和模型。运行中的轮次不更新。
- 默认配置保存前执行账号与工作区的受控检测及模型目录检查；没有成功证据则拒绝保存。审计不保存凭据。
- 新咨询采用默认模型；旧咨询保留服务端模型，缺失才回退默认模型。执行前检测目标账号是否支持该模型，不静默换模型。换账号/模型时清理不适用的推理强度和速度，使用目标模型默认值。
- 原咨询创建账号仅是来源记录。稳定平台聊天会话下保存原生线程段，不拿 A 的原生句柄恢复 B。
- 平台日志保存完整原始问答及附件引用，首次接续导入可读的历史文件；缺失部分明确告知。阅读保存的历史不调用 AI 登录。
- 接续材料包含结构化索引、近期原文及原附件引用。长 SQL、早期修正及工具依据可由会话限定的分页工具读取；不把截取片段说成全部上下文。历史均为不可信参考资料，不能提升为开发指令。资源工具仍按原咨询实时鉴权。
- 会话锁与持久请求 ID 共同防止并发重复执行；原生段初始化后仍为候选，只有输入或响应确认后才提交运行绑定，失败不覆盖旧段。发送结果未知时不得自动重放业务问题。
- 迟到事件须匹配当前轮次与原生段；队列失败恢复原项，用户草稿及附件保留。

## 反馈和恢复

设置展示当前版本、检测结果/时间、生效范围与审计。用户接续时显示“正在接续历史上下文……”，失败显示原因与正常重试入口。关闭配置回到原对象；沿用原键盘/移动布局和主题 token。历史缺失、附件失效不标为完整恢复。已归档咨询保持只读。

## 验证

定向验证策略版本、管理员权限、失败保留原值、执行时解析、运行中冻结、队列、请求去重、账号往返、上下文分页/SQL、历史独立读取及用户隔离。桌面/手机设置界面核对布局、反馈和焦点。真实多账号、多用户、软失效账号及运行稳定性验收须在本次另行获准重启并准备账号后执行。
