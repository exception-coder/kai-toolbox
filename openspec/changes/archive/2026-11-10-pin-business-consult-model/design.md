## Context

业务咨询通过 `ForeConsultPage` 创建咨询记录，再把记录中的模型快照交给复用的 Vibe Coding 会话。当前页面对非管理员传 `null`，管理员可传任意目录中的模型；`ConsultService.startSession` 原样保存该值，因此普通用户实际模型不稳定。

适用产品原则：OBJ-01（咨询会话是唯一对象）、DENS-01（固定策略不应伪装成可编辑配置）、AI-01（前端与 Agent 共用同一服务端业务边界）、FEED-01（未配置和未保存必须给出恢复动作）、IDEM-01（单例策略重复保存应稳定收敛）、EVID-01（模型与 Auth 快照必须反映真实请求）。

## Goals / Non-Goals

**Goals:**

- 管理员从当前 Auth 的模型目录选择并保存默认模型，保存实际 ID 和展示名称，不依赖硬编码 slug。
- 管理员从服务端发现目录中保存唯一业务默认 Auth，所有用户的新咨询由服务端强制使用。
- 普通用户的新咨询由服务端固定为已保存默认模型，页面只读展示该配置。
- 管理员保留单次咨询模型选择及其它已授权的 Codex 运行选项。
- 历史会话保持原模型快照。

**Non-Goals:**

- 不改变普通 Vibe Coding 会话的模型策略。
- 不批量迁移历史咨询记录，不改变模型目录同步机制。
- 不改写既有咨询的模型或 Auth 快照。

## Decisions

1. 业务咨询策略服务继续使用模块自有的单行表，保存 `{model, displayName, codexHome}`；专用 API 允许已登录用户读取，只允许管理员更新。`codexHome` 必须命中服务端实时发现目录，表由启动 schema 幂等扩展。
2. `ConsultService` 在服务端按当前身份解析模型：普通用户无条件使用管理员默认值；管理员优先使用本次请求模型，未选择时回退默认值。仅在前端限制无法防止旧客户端或直接 API 绕过。
3. `ConsultService` 不再信任创建请求中的 `codexHome`；所有身份均从单例策略解析 Auth，防止旧客户端或直接 API 绕过。模型仍维持管理员可单次覆盖的既有规则。
4. `ForeConsultPage` 的管理员可编辑模型与 Auth 并一次保存；普通用户只读展示。管理员选了不同 Auth 但尚未保存时禁止开始并提示保存，避免界面选择与服务端实际值不一致。
5. 不修改历史记录。已有会话继续按创建时模型与 Auth 快照恢复，默认配置变化只影响新咨询。

## Risks / Trade-offs

- [普通用户默认模型尚未配置] → 禁止开始新咨询并提示联系管理员配置，不静默回退 Auth 默认模型。
- [配置的模型已不在当前 Auth 目录] → 页面沿用现有 Auth 不匹配提示；管理员从当前展示目录重新保存，不根据旧 slug 猜测替代模型。
- [升级后旧策略没有 Auth] → 新咨询返回可恢复冲突，管理员选择目录并重新保存；不静默猜测历史账号。
- [客户端伪造 Auth] → 服务端忽略创建请求中的值，仅使用已保存策略。
- [通用配置组件增加一个禁用维度] → 仅新增可选属性，默认行为不变，并用组件测试验证。

## Migration Plan

发布新前后端后，应用启动时幂等增加 `codex_home` 列；管理员在业务咨询页选择模型与 Auth 并保存，随后只影响新咨询。旧策略行在配置前保持 Auth 未配置状态，不做猜测性回填。无需人工 SQL。
