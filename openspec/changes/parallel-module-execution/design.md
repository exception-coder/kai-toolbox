# 设计

## 对象与原则

主对象是既有 execution，稳定身份为 project + executionId + sessionId。适用产品原则：AI-01（沿用项目与执行身份）、CTRL-01（可查询与具名中止）、EVID-01（只以本范围提交证明完成）、IDEM-01（重复绑定复用执行）。没有新增页面或导航；键盘与窄屏行为不变。失败时返回冲突并保留原绑定，调用者通过 `inspect_execution_writer` 找到具体执行后恢复；重试不会接管其它模块。

## 模块写入权

`discover_execution.files`、受影响设计文件和活动 Change 共同形成写入声明。源码按最近的 Maven/npm/Gradle/Go 模块清单目录归属；普通无归属路径按精确文件，根构建配置及根数据库目录才是全局范围。设计文档按具体文件、OpenSpec 按 Change 或正式 capability 占用；相同共享目标互斥，不同模块各自的设计或 Change 不互相阻断。项目级 AI 架构、产品哲学及其它治理文件按同文件互斥处理。任一执行声明多个范围时同时占用这些范围；全局范围与任何执行冲突。

锁内读取全部活跃写入者，先回收已证明完成的冲突执行，再判断范围交集；按实际投影范围判断，不能只因存在其它 writer 就阻断。旧 `execution-writer` 与新索引均从经过身份核验的原执行完整范围重新投影，缺少可靠记录时保留现场并明确拒绝；不删除指针或修改精确写入许可，新增写入索引保存多执行。Sidecar 普通源码按精确文件互斥，构建配置仍按父模块范围协调。每个执行的 session 绑定、验证和审计仍独立。只读查询返回 `writers`；仅有一个执行时保留 `writer` 兼容字段；显式中止以 executionId 精确定位，只释放目标。

## Git 与恢复

Git HEAD 和暂存区仍共享。Agent 应只暂存本执行文件；`BEFORE_COMMIT` 检查全部暂存路径属于当前执行，否则拒绝。提交和自动回收要求基线以来本执行路径至少有一个提交，不能把另一模块导致的 HEAD 前进当作完成。已验证输入和实际提交内容仍由既有门禁检查。此方案不对绕过 Hook 的原生命令提供原子提交锁；同一 index 的并发 `git add/commit` 需要宿主按任务协调，后续如需强隔离应由宿主分配 worktree。

## 验证与恢复

覆盖不同模块并行、同模块及共享文件冲突、多执行查询与单执行中止、其它模块提交不触发自动完成，以及旧单写入状态。门禁失败保持原执行和文件，按查询快照审计恢复。仅更新 sidecar 代码与文档，不自动重启服务；新运行版本需另行授权重启后验收。
