## ADDED Requirements

### Requirement: 会话列表兼容未建立身份与历史缺失字段

系统 SHALL 保留符合访问规则的新会话及历史咨询，不因 SDK ID 或创建人为空导致整个列表失败。

#### Scenario: 尚未建立 SDK 身份

- **WHEN** 可见开发会话的 SDK ID 为空或空白
- **THEN** 列表正常返回且不将该会话判定为记录丢失；非空 ID 按历史索引的 trim 规则比较

#### Scenario: 历史咨询没有创建人

- **WHEN** 已通过现有访问过滤的历史咨询没有 userId
- **THEN** 保留原咨询 ID、运行会话绑定及状态，创建人信息为空，不推定所有者

### Requirement: 咨询恢复不依赖辅助运行列表成功

系统 SHALL 以新鲜咨询历史决定初始恢复，以原连接 ready 与实时状态继续保护发送。

#### Scenario: 辅助列表失败或未完成

- **WHEN** 咨询历史成功而开发会话列表失败或一直等待
- **THEN** 恢复原待归档咨询一次；没有待恢复记录时开放入口，不自动发送或创建咨询

#### Scenario: 历史失败后重试

- **WHEN** 咨询历史失败或只有缓存且新请求仍未完成
- **THEN** 继续锁定新问题入口；历史重试成功后恢复原咨询，不重发原问题

### Requirement: 未关联原会话的历史记录有界恢复

系统 SHALL 区分进行中咨询记录与已关联的底层会话；0 轮问答不证明有可连接的原会话。未关联时保留历史内容，不自动创建替代会话或重发问题。

#### Scenario: 原会话绑定一直缺失

- **WHEN** 用户查看进行中且没有底层会话 ID 的历史记录
- **THEN** 展示已经保存的问题和回答，独立计时最多等待 30 秒
- **AND** 到时明确显示尚未找到关联会话，停止自动轮询，允许重新检查与返回历史
- **AND** 每次重新检查具有同样的等待上限，不自动重发问题

#### Scenario: 0 轮记录稍后关联成功

- **WHEN** 查询取得原会话 ID，即使问答轮数仍为 0
- **THEN** 复用原会话自动进入咨询，不创建副本
