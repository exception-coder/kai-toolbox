## 授权与执行

采用 L3（权限与数据安全），文档沿用 forge-lite。遵循 OBJ-01、AI-01、CTRL-01、FEED-01、IDEM-01：继承资源绑定，复用原执行入口和历史，结果不明不重放，不另建导航或授权配置。

- `QUERY` 保持强制只读；`EXECUTE` 逐次携带用户授权原话、适用范围、稳定请求 ID。会话 ID 由 MCP 装配注入，不由模型填入。Agent 判断用户是否已明确授权具体对象与操作；“开发功能”“生成 SQL”或笼统开启写能力不代表授权任意写入。
- 这是对话授权契约：授权原话和范围仍是 Agent 声明，后端只核验字段、资源、环境和单语句边界，**不是独立的人审凭证或自然语言授权鉴定器**。沿用现有宿主权限策略，不新增重复确认弹框，不宣称 `destructiveHint` 或布尔参数证明人工批准。咨询/评审不装配通用资源工具，不能借此扩权。
- 后端每次重读数据源，只允许 LOCAL/DEV/TEST/UAT；QUERY 不能因携带授权转为可写。普通 DDL/DML 经既有单语句分析与连接器执行，其他语句类型拒绝。
- 写前用既有操作历史主键原子认领请求，保存 SQL 与授权声明；完成更新原记录。同一 ID 再请求只返回已记录结果或明确未知，不再次连接目标库；换目标或内容复用 ID 拒绝。若崩溃停在 RUNNING，必须核对实际数据，不能将它当作失败后重试。此去重以保留历史为前提，不承诺跨历史删除仍然幂等。
- 未获授权或仍需人工交接的脚本沿用待执行登记；已执行 SQL 不再次登记成待执行。DDL 不充分须告知风险，不能冒充已核验，实际执行仍须符合用户授权范围。

MCP 规范区分模型控制的调用与宿主交互，工具注解不能替代可信授权。本实现沿用当前对话授权与宿主策略，未引入独立审批服务：[官方工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。当前实际数据库操作仍受当前会话注入规则与已加载工具限制；代码变更不会修改正在运行的会话权限。
