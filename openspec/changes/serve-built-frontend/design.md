# 本地生产资源运行与自动更新

## 范围与现状

runner 原先固定执行 npm run dev，后端 dev/full 不决定前端模式。既有 Java 自动更新拥有远端 Git 检查与工作区收敛；本能力只观察本地已提交 frontend 树，不进行 pull、stash、reset 或第二套分支管理。源码工作区已有其他未提交作业，构建通过 git archive 获取不可变源码，依赖安装与产物均放在用户 runtime 目录。

## 一期闭环

`--frontend-mode static` 在既有前端进程内运行静态服务器。复用当前 mkcert 叶证书，也支持显式证书路径，不自动安装 CA。默认 HTTPS 与原端口；HTTP 须显式设置并同步既有隧道回源。API、WS、SSE 和 supervisor 使用固定本机目标代理；不缓存或重试业务请求，不增加新中间件。

每 15 秒读取 HEAD:frontend；后端独立提交不触发前端构建。一个构建串行运行，连续提交下一轮读取最新树，失败树不无限重试；新前端提交或手动 build 可恢复。同一 runtime 使用进程锁，防止手动与自动构建互相覆盖。`frontend build` 不启动服务；`frontend status` 读取当前资源指针。

候选从归档中运行现有 npm run build，包含类型检查、功能目录、助手产物与 Vite 构建。按锁文件隔离 npm ci 缓存，不安装或覆盖运行工作区 node_modules。Vite base 使用版本路径，校验 HTML 不是开发入口、入口脚本存在并生成 SHA-256 清单，预生成 Brotli；目录完成后重命名，再原子替换 active.json。开发入口检查读取真实 script src，不因启动诊断脚本中的开发地址字符串拒绝生产 HTML；该误判由真实产物构建发现并纳入回归。新进程验证持久版本完整性；候选失败不切换。对每个文件逐请求做哈希不在首屏路径。

根 HTML 与版本检查不使用长期缓存，版本路径资源 immutable；保留所有七天内版本和至少最近三个版本，活跃版本不清理。超出保留期的旧标签页可能需要刷新，不能承诺永久可用。静态服务拒绝路径越界和点文件，支持 HEAD、ETag、Range，缺失脚本返回 404，不回退 HTML。build.lock、快照、依赖、状态和源码归档均不可通过静态服务访问。

## 页面恢复与保护

发布时 HTML 写入版本 meta，生产 App 按需加载更新提示；开发或旧版没有 meta 时不轮询。当前页面每 15 秒及重新可见时读取小型状态响应，失败继续使用当前版本。只有可见首页、聊天引擎从未激活、没有 Query mutation、对话框、busy 标记、输入/文件/富文本内容，且 30 秒没有交互时自动刷新一次。业务页一律等待显式操作，并使用已有确认弹框提醒保存输入、等待上传或生成；用户仍可选择刷新，不能把刷新解释为取消服务器任务。刷新前再确认资源服务可用，失败提供重试。“稍后”只忽略当前目标版本，新版本继续提示。未知业务后台状态不作为全局可安全刷新证明，本期自动刷新只覆盖上述保守首页条件。

适用 OBJ-01（唯一版本身份）、CTX-01（输入保护）、FEED-01（失败保留旧版与恢复）、CTRL-01（明确切换授权）、IDEM-01（树身份、防重建与单次刷新）、EVID-01（代码、运行、手机性能分别验收），无例外。更新提示沿用 quiet-luxury-ui 和已有按钮、确认框，不增设菜单或管理平台。

## 管理与授权

所有运行控制仍走 node forge.mjs。模式切换使用显式 full restart 参数，不能由后台构建触发后端/控制器/隧道重启；旧运行模式保持可选。构建成功后的原子资源发布由用户选择静态模式及自动更新开关授权，不重启服务进程。修改运行器/配置的生效仍需要另行授权重启，不热替换 Node 执行代码。

## 验收

覆盖不可变归档与 dirty 隔离、后端提交不重建、构建失败不切换、完整性、旧资源、压缩/缓存/Range、路径保护、POST/SSE/WS、模式默认值与现有重启授权，以及更新提示/输入/聊天/隐藏页保护。使用本任务快照做真实生产构建与隔离 HTTP/浏览器验收；不复用其他 dirty 作业的 PASS，不启动日常端口或改动在线服务。首次切换、稳定观察及公网手机性能属于授权切换后的运行验收。

依据：当前 Vite 6.4.2，[Vite 6 构建文档](https://github.com/vitejs/vite/blob/v6.4.1/docs/guide/build.md)支持生产构建与监听；[静态部署说明](https://vite.dev/guide/static-deploy.html)明确 preview 不是生产服务器。使用现有 Node 22 HTTP/TLS 和流式代理，不使用 preview 承担长期运行。无已确认二、三期需求。
