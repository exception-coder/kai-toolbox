# 咨询补充只读 Git 联系线索

在 `consult-readonly` 中新增 `source_git_history`，调用方只能选择相对文件路径、`log/blame`、条数与行范围。先收敛并核对相关源码，再查本地 HEAD。log 跟随文件重命名，返回作者与提交者、邮箱、时间、哈希和主题；blame 返回提交版本对应行的归属，不把未提交工作区当作已归属。最多 20 条或 200 行，总预算 10 秒、子进程输出 64 KiB，超时/超量失败后缩小范围，不静默补拉历史。

实际路径和仓库根须处于授权根内；拒绝父仓库、目录、符号链接逃逸和 Git 内部/图谱/依赖缓存。外层复用源码文件类型限制。命令固定、参数数组传递、路径为 literal pathspec，不接受模型命令、引用或仓库目录；清理继承的 Git 环境覆盖、关闭 pager、textconv、fsmonitor、可选锁和隐式 lazy fetch。错误不回显凭据或任意宿主配置。仅查询本地对象，非 Git/SVN 目录需明确告知无 Git 证据，不借终端回退。

能力目录、Codex 白名单、Claude 权限代理和 stdio 实际暴露同时登记。默认实现证据节点包含工具；历史冻结流程只有已授予 source_read 时，在服务端运行装配追加更窄的历史能力，不改写快照或全局发布版本；缺少快照或源码读取权限不补授。规则要求将结果作为运维联系线索，不依据最近提交、行数或提交次数认定主要开发者或故障责任；本地 HEAD/浅克隆不证明远端最新或生产已部署。

依据 [Git log](https://git-scm.com/docs/git-log)、[Git blame](https://git-scm.com/docs/git-blame) 与 [Git 环境和路径参数](https://git-scm.com/docs/git) 核对行为；本机 Git 2.54.0.windows.1 进行临时仓库验证。产品原则 AI-01、EVID-01、CTRL-01：沿用原身份和权限，区分提交事实与责任判断，查询不产生仓库写入；无例外。组件能力边界与架构说明同步，运行版本效果仍待授权重启后的验收。
