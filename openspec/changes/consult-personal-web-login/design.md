# 设计

当前采用[用户持久绑定设计](persistence-design.md)，由用户于2026-11-17明确要求；替代最初仅当前咨询15分钟内存授权。保留本人所有权、非生产环境、同源和只读请求边界，表单保存路径仅向模型返回引用；原生登录路径使用用户明确提供的凭据。初版验证证据仅证明当时实现，不代表持久绑定部署通过。

2026-11-18按用户要求简化个人账号入口：内网与自定义端口不要求先登记资源，个人保存和读取不依赖项目库或服务端源码定位。咨询系统仍是已有持久保存归属，不是外部站点注册证明；公共账号与数据库规则不变。按OBJ-01/AI-01在原对象内完成操作，FEED-01区分登录结果与保存结果。详见持久绑定设计的本次范围。

用户进一步明确优先使用Codex原生站点授权：不再把表单当成登录入口前提。Codex咨询配置移除browser/computer/code-mode的强制false覆盖，继承宿主实际能力及权限；SDK路径允许咨询的只读联网，评审和禁用模式仍关闭。开发者说明允许用户指定站点的登录与只读内存请求，并注入动态节点恢复约束。已有签名consult_web仍只接收引用，不新增携带密码的工具或登录协议；Claude等没有原生能力的宿主仍可用现有表单。原生可用性和真实模型轮次必须独立核验，配置改变不等于已装配浏览器工具。

咨询内“我的系统账号”按需展开；账号加密保存到当前用户与系统，同一范围后续咨询复用。状态查询与实际登录检查分离，展示上次结果和时间，不把保存或历史成功作为当前在线保证。解除绑定同时关闭浏览器context，禁止不同用户/系统交叉引用。重新保存替换当前绑定；仅已验证目标范围的账号可保存，登录失败保留失败状态且不自动重复尝试。

登录、状态读取、检查和解除绑定的页面等待均限制为60秒，涵盖鉴权续期及响应体。超时只结束客户端等待，清空密码，不宣称服务端取消；未知登录结果先查询或解除绑定，不直接重复提交。GET状态不等待慢浏览器，mutations按用户系统互斥、忙时快速拒绝。适用OBJ-01/CTX-01/FEED-01/CTRL-01/IDEM-01，无例外。

浏览器仍只在内存保留Cookie，context15分钟释放；持久绑定没有15分钟失效。读取登录失效时最多重登一次，初次登录失败或重登失败不重复撞密码。验证码和跨域SSO仍要求外部处理，不新增任意业务POST能力。接口返回401和可见登录页被判为需要登录，其他HTTP错误不盲目重登。

新表幂等创建，复用已有加密端口与独立密钥，缺失密钥报错不降级明文。无运行库SQL写入，须构建宿主装配及权限/持久化/过期真实浏览器回归。未获本次重启授权，不重启；真实站点需目标版本加载后验证。
