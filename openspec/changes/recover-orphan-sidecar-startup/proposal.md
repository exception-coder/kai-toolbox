## Why

同事报告后端启动反复报 Sidecar 18890 等待释放超时，随后 Forge 不可用。启动器在 Java 启动前直接抛错，Java 内的懒启动清理无法介入；现有 Sidecar 也没有父 JVM 退出后的管道监控。PM2 的有限重试不能解决仍存在的占用。未取得同事完整进程树和控制器日志，不将控制器退出原因当作已核验事实。

## What Changes

- Sidecar 跟随所属 JVM 的 stdin 管道生命周期，异步清理有退出时限。
- 正常启动阶段先等待端口，再核实并回收本工作区孤儿；未知归属、活跃父进程和旧版相对入口均不自动终止。
- 无法回收的端口冲突只阻止 AI 运行时准备和使用，保留依赖与构建产物，后端继续启动并输出恢复说明。
- 后端不把任意端口监听者当成自身 Sidecar，关闭时等待进程退出，拒绝关闭期间再次启动。

## Impact

涉及 Forge 启动器、Claude Sidecar 和 Java 进程注册器。无数据库或前端变更。PM2 重试策略与服务重启授权不变；修复提交不代表同事机器已加载或验收。
