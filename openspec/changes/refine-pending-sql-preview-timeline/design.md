## Context

主对象是当前会话唯一的待执行 SQL 登记，以 `sessionId` 标识。常驻 SQL 工作区负责只读审阅，管理弹窗负责编辑登记；本次不创建新的列表、页签或事实源。

## Goals / Non-Goals

**Goals:**
- 首屏优先呈现标题、状态、目标库和 SQL 正文。
- 用共享时间线展示登记、更新、执行/取消事实。
- 保持移动端操作可达并减少重复卡片、重色告警和大面积状态胶囊。

**Non-Goals:**
- 不执行数据库，不改变 SQL 登记协议或持久化模型。
- 不新增审计历史；时间线只展示现有时间戳可证明的里程碑。

## Decisions

### 产品原则

- `OBJ-01`：沿用当前会话的唯一 SQL 登记，不要求再次选择登记对象。
- `DENS-01`：标题、状态、目标和正文为主；安全边界与 DDL 证据降为短说明和可展开详情。
- `CTX-01`：管理弹窗保留现有草稿、关闭和全屏行为，窄屏底部操作持续可达。
- `EVID-01`：时间线只使用 `createdAt`、`updatedAt`、`executedAt`，不从 SQL 内容或聊天文本猜测。

### 时间信息

常驻清单只显示用户决策所需的登记时间；管理面板补充最后更新时间。当前模型没有完整状态历史，因此不把关键时间戳包装成多节点流程时间线。

### 信息层级

常驻工作区使用平面清单：登记标题与时间、执行库、SQL 条目标题；SQL 正文按条目展开。状态、安全边界和 DDL 证据只在管理弹窗出现。管理弹窗将安全边界改为单行说明，DDL 证据保持可展开但不再使用大面积警告底色；编辑字段按“登记信息—目标—SQL”顺序排列。

## Risks / Trade-offs

- 当前模型没有完整状态变更历史，因此时间线是关键里程碑而非审计日志；通过明确标签避免误解。
- 极长目标库名称仍需横向滚动；保留 title 提示并验证移动端无页面级横向溢出。

## Verification

- 单元测试覆盖登记/更新时间线和终态节点。
- 执行前端 typecheck、测试与生产构建。
- 在真实浏览器验证约 390px 移动端与 1440px 桌面端，检查层级、滚动、弹窗操作和空/错误状态。
