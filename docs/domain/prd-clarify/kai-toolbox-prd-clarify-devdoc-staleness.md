## 业务定义

一次PRD澄清会话在PRD正文生成完成后，可以再基于PRD正文生成一份配套的"开发文档"（面向工程师的技术方案）。开发文档的内容依赖PRD正文作为输入，因此需要一套判定"开发文档是否还跟得上PRD最新内容"的规则：

- 只要**PRD正文的最后更新时间**晚于**开发文档的最后生成时间**，就判定"开发文档已过期"。
- 触发"PRD正文最后更新时间"推进的动作有两种：① PRD正文被重新生成一次；② 用户手动编辑并保存了PRD正文。两种情形都可能使已有的开发文档滞后于最新PRD内容。
- 用户手动编辑并保存开发文档本身，会刷新开发文档自己的"最后生成时间"，使其重新被判定为"最新"（不过期）。

## 适用范围 / 边界

- 该判定只是给使用者一个"建议重新生成开发文档"的提示信号，不具备强制性——不会阻止用户继续查看/使用已过期的开发文档，也不会自动触发重新生成，是否重新生成由用户手动决定。
- 只适用于"已经生成过开发文档"的会话；从未生成过开发文档的会话不涉及此判定。

## 备注

- 口径来源：kai-toolbox 代码调研起草，待 owner 核实。
- 易混点：过期判定比较的是"PRD正文更新时间"与"开发文档生成时间"两个时间戳的先后，不是简单看"是否点过重新生成"这个动作次数。
