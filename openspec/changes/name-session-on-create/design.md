## Context

新建表单位于 `ChatPage.tsx`；`useClaudeChatSocket.open` 发送 WebSocket `open`，`ClaudeChatService.openSession` 目前以 `title(null)` 创建会话。已有 `/sessions/{id}/title` 适合后续编辑，但创建时再请求会产生短暂错名和竞态。Graphify 当前不可用，坐标来自定向源码核对。

## Goals / Non-Goals

目标：创建时确定可选标题，目录选择与显示名称分离；表单布局按填写顺序组织并兼容窄屏。非目标：修改旧会话标题、项目目录别名或自动生成标题。

## Decisions

- WebSocket `open` 增加可选 `title`，服务端 trim 后与新会话同次持久化；空白为 `null`，由既有 `sessionDisplayName` 根据 cwd 回退。限制长度与既有标题输入兼容。
- 客户端 `open` 参数在末尾增加可选标题，不改已有调用位置；重连保留同一创建意图。服务端只在创建路径读取标题，切换和恢复不覆盖已有标题。
- 表单按“工作目录 → 会话名称（可选） → 运行配置 → 开始”排布；选目录只填路径，不自动把项目目录别名写进会话名称。选项操作和手填路径保留。
- 使用既有中性边框、字体与按钮；不增叠卡片。窄屏输入单列，开始动作位于配置末尾。

## Risks / Trade-offs

- 旧客户端不传 `title` 仍可创建，原有目录名回退不变。
- 不把目录别名与会话别名混淆，避免修改项目注册身份。后端拒绝过长标题并保留错误反馈。
- 会话配置弹层沿用原有模型与服务商交互。档案查询未返回时使用稳定空列表，模型目录已空时不重复写入状态，避免弹层挂载阶段形成 React 更新循环；这是保持既有行为的缺陷修复，不改变创建标题协议。

## Verification / Rollback

验证 DTO 兼容和会话初始标题、前端类型/构建与新建表单交互；桌面及窄屏实测依赖新版服务加载，未重启前不宣称运行验收。回滚本 change 的协议字段、持久化赋值与表单输入即可恢复旧创建流程。
