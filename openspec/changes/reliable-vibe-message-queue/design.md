# 可靠消息队列设计

## 对象、范围与交互

适用 OBJ-01、CTX-01、FEED-01、AI-01、EVID-01、CTRL-01、IDEM-01，无例外。主对象仍是 sessionId，队列项 messageId 与当前执行 turnId 分离；不增加页面或导航。复用队列列表，显示执行、追问次数、挂起原因和“已核对，继续队列”。键盘使用原生按钮，窄屏原因换行；真实浏览器检查及运行启用单独记录，不能以预览入口代替验收。

## 状态与一致性

SQLite 原队列保存输入，新 runtime 表保存当前轮次、完成准入、原任务文本、追问次数及阶段；delivery 表保证同一会话最多一个在途队列项。认领与关闭准入在同一事务，正常终态与删除原文在同一事务。每次新任务重置追问次数，重启/刷新同一任务不重置。新建表通过应用 SchemaInitializer 幂等创建，不交付人工执行脚本。

Sidecar 回执保存在当前本机用户数据目录，每端口独立文件；只存轮次元数据，不复制消息及凭据。接收记录 fsync 后才开始执行，终态落盘后再广播；重复轮次返回旧回执。最多保留 2048 条，优先裁剪已完成记录并更换证据代际；全为未收口记录则拒绝新输入。损坏文件不得静默当空文件。

原文直到确认完成前保留。FAILED/UNKNOWN 不自动删除，也不直接重做原动作；真实空闲后在同一会话追问，允许模型在原权限内处理剩余内容。三次上限在派发前持久扣计，明确完成标记必须位于本次回复最后一行并绑定本次 turnId；该标记只表明模型确认，不能当作独立验收证据。连续三次无明确完成即挂起。取消/中断、待确认授权、后台任务及内部 OpenSpec 监督消息保持各自语义。

巡检串行、每批 16 项，网络查询在会话锁外，返回后对比持久轮次防止迟到快照覆盖新任务。进程停止关闭 worker。有持久队列时，首次巡检沿用现有 SidecarProcessRegistry 受管懒启动，应用启动周期仅尝试一次，不等待浏览器先打开。随后只尝试有界连接已监听的 Sidecar；启动失败保留输入，不形成巡检重启循环。恢复保留原 native session 与引擎/服务商/模型/权限，不能创建随机原生会话伪装恢复。所有真正开始工作仍经过 admission gate 和项目访问检查；确认继续前反查真实空闲，并核对查询期间任务未变。

## 完成核对的状态显示修复

2026-11-11 续接采用 L2：修复既有模块的状态反馈和兼容快照，保留原准入、暂停/删除、回执及安全放行规则，不修改数据库、权限或原生 SDK。适用原则仍为 OBJ-01、CTX-01、FEED-01、AI-01、EVID-01、CTRL-01、IDEM-01，无新增导航与例外。主对象是 sessionId，核对轮是既有持久 turnId。

`result → queueCheck → assistantDelta` 必须形成前端新轮次：收到结果关闭上一轮，只有 Sidecar 接收当前核对轮后广播 `queueCheck`，前端据此解除终态门闩。准备派发不等于接收，发送异常保留 UNKNOWN 及原文。`ready.queueCheck` 从现有 runtime 与当前轮次恢复已接收核对进度，避免断线缓冲被淘汰后退回泛化“正在运行”。已结束轮次的重复核对与旧结果不得影响当前新轮。公开评审投影继续剔除核对元数据。

前端以状态事件递增的查询代次隔离 HTTP 快照，结束、核对、审批/回答、中断回执和后台任务变化立即换代并取消旧请求。相同渲染批次中 running 先结束后再次运行也不能复用旧查询。顶栏、专注阅读、底部状态栏共享执行状态投影，历史结果仅在权威空闲后补充展示；发送门禁继续由后端决定。

回归覆盖同轮接收去重、手动任务无 delivery 行、派发失败、恢复快照、迟到请求、快速连续轮次、审批/收口与断线。沿用既有键盘、焦点及窄屏结构，不自动发送真实用户消息。源码、构建、质量探测和新版本浏览器/模型验收分开记录；本次未获重启授权。

## P1：原生状态与失败恢复

继续沿用 L2 和以上交互原则。Codex Adapter 接收 `thread/status/changed` 的等待审批、等待回答、空闲及系统错误；Claude Adapter 开启 SDK 原生 `session_state_changed` 事件，并接收 `api_retry`。仅观察当前根会话、当前 Forge turnId，子线程及迟到旧轮不覆盖当前状态。原生 idle 只是执行证据，不能直接释放队列；已有 TurnLifecycle 仍等待结果和原生进程清理结束，后台任务、暂停及中断规则不变。不改变 SDK 后台子任务等待策略。

原生观察通过既有 `engineEvent` 协议的 `engine.status` 事件通知，运行快照携带 `nativeStatus`。前端只触发当前代次刷新，由后端聚合为等待回答、自动重试、收口或引擎异常。原生提供次数时显示次数，不推测重试总数。旧版本或未提供状态的引擎保留既有状态路径。

结果附带可选失败类别及短错误代码，按额度/限流、上下文、鉴权、网络/服务、请求/工具、拒绝、执行上限、未完整完成分类；没有结构化证据时保留未知。不根据助手自由文本猜测错误，不透传原始请求或凭据。成功、中断、用户暂停和未入队保持独立。分类是恢复提示，不改变完成核对、回执及队列放行规则。

最新失败轮复用消息详情、草稿、会话配置和同目录新建会话入口。压缩指令仅在引擎广告支持时出现，核对重试与调整需求写入草稿，不自动重发。次数上限或未完整完成可由用户点击继续，并再次通过现有发送门禁；运行中或出现新用户任务时不展示旧轮恢复操作。公开评审仍剔除技术元数据。历史原生记录缺少结构化错误代码时显示未知，不新建失败数据库。

验收覆盖原生 idle/result 两种到达顺序、子线程隔离、自动重试不中断、失败分类透传、迟到事件隔离、手机/桌面失败恢复与现有 Codex 生命周期/配置回归。构建在 Sidecar 隔离目录进行，禁止覆盖运行中 dist；新版启用和真实模型/浏览器验收仍须本次重启授权。
