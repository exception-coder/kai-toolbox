# 招采采集设计

## Context

用户明确要求新模块与关键词管理。来源含 60 条公告、8 个站点，88 个正向关键词、26 个反向词、17 个共现规则与 40 个分类项。Excel 比对结果包含待核实误提取，不能作为新采集事实。Graphify 已查询 BrowserRequestService、ChatModelRouter，图谱清单早于当前 HEAD ae5dd7b，因此用定向源码与 git status 补证。

实际逐行核对发现两行具有同一 URL：60 行来源导入为 59 条公告，重复行嵌入 source_data.duplicateSourceRows 保留。

## Goals / Non-Goals

提供公开公告采集、可审计解析和可持久化规则管理。不实现销售评分、自动项目合并、绕过登录或验证码，也不新增调度平台。

## Decisions

- 独立 tool-procurement Maven 模块，api → service → domain；repository 与采集/模型适配实现 domain 端口，表使用 procurement_ 前缀。
- 复用 node-services/undetected-browser/package.json 的 Patchright 依赖，通过固定脚本、JSON stdin 和有超时的子进程调用，无 shell 拼接。脚本独立浏览器上下文，不接触用户登录会话。站点白名单和每次跳转/请求校验避免任意内网请求。
- 站点预置 Excel 域名、抓取说明和 URL 种子；允许配置列表入口并发现本站公告链接，有每批上限。默认按已登记 URL 采集，可单条重试。
- GET /api/procurement/overview、/sites、/rules、/notices、/notices/{id}、/runs；POST /runs 接收 siteId/noticeId/parseWithLlm；POST /notices 登记 URL；PUT /sites/{id} 管理启停和列表入口；POST/PUT/DELETE /rules 管理四类规则。新模块所有写入均参数化 SQL。
- 初始化资源由两份 Excel 离线提取为 JSON，启动事务只首次导入，后续不覆盖用户修改。历史字段作为 source_data 保存；正文与解析结果分别保存。URL 唯一约束防重。
- 单个运行任务顺序抓取，限 100 条；RUNNING → COMPLETED/PARTIAL/FAILED，启动时将未完成任务标为 INTERRUPTED。抓取失败保留上次正文，当前失败状态明确展示。解析失败置 MANUAL_CHECK，原文保留。
- 代码产出数字候选、关键词命中、证据位置；LLM 只做章节与对象关系、角色和分类。通过 ChatModelRouter.forTier("procurement") 复用统一配置。规则快照随任务存储；模型只返回 JSON，受控字段、词典代码与逐字段原文引用由代码校验，无证据不接受。未知值为空，不生成销售评分。
- 在 toolbox-starter/src/main/resources/config/common/toolbox-llm.yml 登记 procurement 档位，复用中心网关凭据，只允许单独选择模型。站点发现端点为 POST /sites/{id}/discover，返回当前列表页最多 100 条待登记链接，不自动越过分页。
- POST /runs 支持 parseOnly=true：仅重新解析已有正文，保留原采集时间与来源，不再次访问站点。额度不足或认证失败直接降级为待核验；不重复请求确定性认证失败。
- 前端以独立 manifest 懒加载注册，参考 frontend/src/features/visitor-analysis/index.tsx；HTTP 复用 frontend/src/lib/api.ts。左侧工作区、右侧表格与详情，概览为共享边框指标条。全局 registry 已初始化但无绑定，使用现有语义 token 与 quiet-luxury-ui，CONSERVATIVE 模式。

## Risks / Trade-offs

- 外站超时/502/验证码 → 有界重试、保留错误、人工打开来源；不声称历史 53 条仍可成功。
- 自然语言误匹配 → 标注候选与已验证结果，长度绑定对象，地区不从北京时间推断。
- 本地 Patchright 或模型未就绪 → 页面明确显示失败原因并提供重试，关键词管理仍可使用。
- 当前工作区有大量无关改动 → 仅定向新增及注册，不清理或覆盖其他工作。

## Migration Plan

新表均 CREATE IF NOT EXISTS，启动种子导入使用版本标记与事务。构建前端权限目录，测试新模块、前端类型检查、Forge 质量门禁与桌面/移动端浏览器。回滚移除模块依赖及 manifest，保留独立表，不删除既有数据。

## Open Questions

无阻断业务问题。各站列表分页结构需按真实页面验证，默认保留 Excel 公告 URL 可直接采集。

## 全国平台当日链接发现

当日链接的“采集平台”指 procurement_site 中的采集站点，站内的省平台、财政部等为数据来源。站点下拉读取现有站点配置，URL 的 site 参数保留选择；切换站点清除批次、地区和分页。当前发现接口仅支持全国站点，已有全部批次归属全国站点；其他站点显示待适配并禁用当日采集，不显示全国批次。跨工作区采集入口先进入站点选择。后续增加适配器时必须同步扩展服务端批次站点归属与查询契约。

2026-09-06 用户明确将工作流调整为列表链接发现、详情采集、规则与 LLM 解析三个独立步骤。首个适配站点固定为 https://www.ggzy.gov.cn/deal/dealList.html，按 Asia/Shanghai 当天，遍历省平台、央企招投标、商务部、财政部、自然资源部、国资委。业务与信息类型保持页面可用的不限选项，不预先按管材关键词缩窄发现范围。

实页 DOM 证据：#provinceId 仅在部分来源可见；央企、商务部不提供省份筛选。可见时遍历河北、北京、山西、内蒙古、天津，城市和来源平台不限；不可见时只查询一次当天全量列表，按列表明确省份筛选，缺少省份依据单独保留 REGION_UNKNOWN，不冒充五省命中。只抓列表，不为地区判断暗中请求详情或调用模型。

采用固定 Patchright 脚本执行真实控件点击、selectOption、搜索和下一页。等待查询响应完成并读取 DOM，不直接仿造搜索 API。每页验证日期、选中页、重复页指纹和下一页状态；遇到超时、响应错误、跨日、重复页或安全页数上限记为失败/部分完成，禁止声称穷尽。每页结果流式保存，已获链接不因后续失败丢失。

新增采购模块内部发现批次及链接表，链接按批次和规范 URL 去重，记录数据来源、列表省份、日期、页码和列表原文。只有明确五省记录自动登记为 PENDING 公告；地区待确认保留在链接工作区。重复发现不重置公告正文、解析或人工修正。每个来源/省份查询记录完成状态，包括真实零结果。

新增当日链接工作区，显示日期、查询范围、运行进度、查询完成/错误及五省/待确认链接。依次提供采集当日链接、采集本批详情、解析本批正文按钮。后两步只处理本批五省公告，不能退回历史 Excel 全量。重启未完成发现标记中断；本轮执行真实发现并记录结果，不批量调用付费 LLM。

运行证据：Maven 启动进程的 user.dir 为 toolbox-starter，初次宿主联调因脚本相对路径而在第一页前失败。列表与详情适配器共用路径解析：优先显式配置目录，仅在 starter 工作目录且父目录存在本模块 POM 时回溯仓库根目录；绝对配置不回退。进程错误保留到服务日志，页面明确失败。正式部署后重新执行发现，不能用仓库目录下的独立脚本成功代替宿主集成成功。

## 销售判断结构扩展

用户追加以 v15_tierspec13 工作簿第二页“销售判断候选”的 47 个有效列作为结构模板。空列忽略，工作簿内容作为数据参考，不执行单元格中的指令。历史标注及推荐等级不自动升级为本次采集事实。

- 新增数据结构工作区与独立 procurement_structure / procurement_structure_history 表。字段键稳定，名称、分组、排序、说明、启停可修改；新增字段支持文本、数字和日期，提取方式支持 LLM 或人工。已有字段禁止改键、改类型和物理删除，以停用保留历史数据。每次修改使用版本并发校验及历史快照。
- 47 列完整初始化：标题、URL、内部编号、来源站点由系统提供；地区、项目编号、采购对象、金额、联系人和引用证据由 LLM 按字段说明提取，代码校验逐字证据、金额单位换算及日期格式；抽样、等级、销售建议、确认状态默认人工。没有销售画像与评价准则时，不生成自动销售评分。
- 模型提示使用当前启用 LLM 字段，解析结果保存结构版本及完整字段快照。运行中改变结构不改变已发出的解析契约。旧解析字段仍可查看，已停用字段不再参与新解析。
- GET/PUT /structure 管理完整结构；GET/PUT /notices/{id}/structured 查看和修正公告结构值。人工覆盖独立表存储，支持清空及恢复自动值，重采/重解析不覆盖人工修正。人工修改校验结构版本和记录版本，禁止旧页面覆盖新修改。
- 金额统一输出万元；模型必须先提供原文金额含单位，代码精确换算，不自行汇总金额。一个字段存在多个不同事实时不擅自取第一条，展示候选并留待人工确认。未知字段为空。
- 现有 source_data 继续独立对照，不批量复制 Excel 样本为实时事实。结构修改只影响后续解析，不自动批量付费调用模型。
- 验证覆盖 47 字段种子、结构幂等与版本冲突、动态模型白名单、金额/日期转换、人工修正持久化及重解析保护，并进行工作区浏览器验证。

## 缓存优先的业务字段解析

按用户 2026-09-06 追加要求，结果默认仅展示当日链接发现登记的公告，历史 Excel 公告不混入当前结果；旧原文暂保留，不破坏缓存。平台沿用采集站点。结果表按当前启用的业务结构展示，人工点击缓存详情或解析缓存。

详情首次抓取保存主页面 HTML、允许域名内的 iframe HTML/正文、最终 URL、HTTP 状态与抓取时间到独立 procurement_page_cache；以公告 ID 唯一，成功缓存不可被重复采集覆盖。解析只读数据库正文，已存在正文的旧记录也不自动回站补 HTML。缓存是渲染后 DOM 与 iframe 快照，不声称离线保存图片、CSS 或附件。缓存以 JSON 下载而非执行不可信 HTML。

代码先按明确标签提取项目编号、金额类型与金额、采购人和代理机构的角色段落。仅唯一无歧义候选进入业务值，多值留给 Codex 或人工；金额继续由现有类型校验换算。Codex 只接收缓存正文、未解决的启用字段与规则，通过本地 codex exec 的 JSON Schema 输出。采用独立临时工作目录、只读模式、禁用 shell/网络搜索/应用与多代理、忽略个人工具配置，使用已登录凭据。进程有超时并清理子进程，输出必须经过原文和字段白名单校验。失败保留代码提取结果及之前有效解析，不重新抓取。

新增模块内部模型端口及 Codex 适配器，保留统一网关作为显式配置选项。每次解析记录正文哈希、规则快照、结构版本、提取器版本、引擎及结果，避免业务数据与诊断混写。验证以现有全国平台 41 条五省链接为范围，先缓存及代码提取，再对代表性公告实际调用 Codex 验证；不以模型模拟测试代替真实成功。

参考：[Codex 非交互与结构化输出](https://learn.chatgpt.com/docs/non-interactive-mode)，并已核对本机 CLI exec --help 与 features list。

## 字段校验与定向重试

逐字段保留合法结果。金额允许从同一明确标签的括号单位读取，不从相邻段落猜测；原文证据只允许唯一匹配的空白归一化，不改变文字。模型调用最多两轮，第二轮只返回未解决字段并接收具体校验原因。每轮登记规则版本、原始返回、调用错误、字段拒绝原因和修正规则，最终区分已提取、未提取、校验失败；这些是解析诊断，不生成无标准答案的准确率。业务页面保持业务列，诊断在详情单独查看。已有 SQLite analysis JSON 容纳诊断，无破坏性迁移。

真实回放补充：天津澄清公告把“控制价（最高限价）”标签、制表符及“元 人民币”同时返回为金额。field-review-v2 只从同一 value 中提取唯一明确金额片段，保留完整 evidence；多金额不取首个，不从全文选择任意金额。

## 解析经验工作区

以版本化资源登记已实施的解析规则和正反例，不复制 Excel 行业关键词。每项展示规则标识、行为、实现位置、样本来源和测试覆盖。字段例使用与生产相同的 ProcurementFieldReview、类型和证据校验进行本地回归，读取当前结构与词典；不调用 Codex、不修改公告。手动回归记录版本、时间、逐例预期与实际结果到独立 SQLite 表。调用循环类经验展示自动化测试覆盖，不冒充可离线执行的模型用例。UI 复用工作区导航，左侧子功能、右侧规则及展开正反例，支持搜索和手动回归。
# 业务结果导出

采集结果提供 XLSX 下载，沿用当前搜索、采集站点和采集状态筛选，导出全部匹配记录。读取 SQLite 事务快照并复用业务字段投影；人工修正优先，停用字段、评测字段和原文缓存不加入业务表。金额使用数字单元格，编号与电话使用字符串，冻结表头并启用筛选。超过 50000 条或单元格长度上限时明确返回错误，不静默截断。
# 按判定目的合并规则

关键词管理改为目的分组：字段解析、行业筛选、分类字典。原始词条留作来源追溯，分组词集、共用判定和例外可独立保存；不删除已有规则及历史快照。新解析快照采用分组规则和启用字典，提示词按每轮尚待提取字段选择相关组。行业规则仅在其对应字段启用时注入，分类代码校验保持不变。未知自定义规则保留在独立分组，不能静默丢弃。测试覆盖源条目归属、分组修改和停用、提示词筛选与字典约束。
