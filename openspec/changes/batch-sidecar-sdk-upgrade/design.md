# 多选 SDK 统一升级

复用 SidecarSdkUpgradeService 和现有隔离工作区，将管理员选择的 Codex、Claude、Qwen、OpenCode 合并为一次安装、协议校验、编译及提升。外部 Antigravity 不属于 npm SDK，不纳入升级。本次 L2，保持管理员权限、维护栅栏、空闲复核和失败回滚边界，无整体架构契约变化。

接口接受重复 engines 参数，兼容旧单 engine；两者同时提供、空列表、超出四项、非白名单任一项均拒绝。去重后只查一次版本目录；已最新或更高版本跳过（包括更高主/次/补丁版本的预发布包），同版本预发布可升级到正式版，构建元数据不触发重装。任一目标缺少稳定版本时整批失败，不安装部分目标。无升级项不重连。有升级项一次 npm install，任一验证失败不提升；切换失败沿用整组回滚。单 JVM 任务互斥及浏览器轮询沿用原逻辑，不承诺跨 JVM 重启恢复。状态 engine 保留字符串类型，单选仍为单 ID，批量为逗号分隔的所选 ID，面板据此恢复进行中选择。

## 产品交互

运行时与升级选项按同一份会话引擎目录显示，版本接口提供包版本补充。探测未返回时展示已知引擎并标注可用性待检测。会话可选状态与批量升级资格分别展示，外部运行时和未开放升级的引擎保留禁用选项。全选仅选择现有批量升级白名单内的 SDK。沿用 OBJ-01、NAV-01、DENS-01、FEED-01 和 CTRL-01。

适用 OBJ-01、NAV-01、CTX-01、FEED-01、CTRL-01、IDEM-01，无例外。主对象为同一 Sidecar 的所选 SDK 集合；保留团队依赖面板，不新增导航。用有标签的 checkbox、全选与清空替换单选框，默认选择 Codex；空选择禁用提交，任务执行时禁用选择，关闭面板不取消服务器任务，重新打开查询状态。错误保留选择并允许刷新核对；成功刷新版本目录，已最新明确显示无需切换。稳定目标为去重后的白名单 ID 集合，运行中重复请求拒绝，完成后重新触发先检查实际版本。

键盘使用原生 checkbox 的 Tab/Space，窄屏换行并保留至少 40px 标签触控区；测试多选请求、全选、空选择和管理员边界。构建和模拟回滚不能代替实际升级验收；Agent 不因开发授权执行会重连 Sidecar 的升级，须先说明目标和影响并取得本次确认。

## 定时检查与安全切换

Java 定时任务仅在部署方配置 Cron 时运行，使用北京时间，默认关闭。检查范围沿用现有四个受管 npm SDK，外部 CLI 仍单独维护。自动和手动任务共享批次互斥和版本状态入口。自动任务在独立目录安装、核对安装版本、验证协议并编译，然后最多等待一小时空闲。等待期间继续接收工作。

切换复用源码更新所用的 Agent 准入锁，与源码更新的最终排空及切换互斥。持锁后复核运行中任务、待确认状态、后台任务及持久队列，并阻止普通 Sidecar 消息和启动。先摘除旧连接，通知受管 Sidecar 退出，确认已知子进程与可识别的依赖目录原生程序退出，并核对端口释放。进程仍在或归属无法核实时，保留原文件并尝试连接旧版本。进程检查受操作系统可见性限制，文件移动错误仍走恢复流程。

开始移动前原子创建恢复标记，备份旧包清单、锁文件、依赖及构建目录。新版本重连后核对会话状态、进程和 WebSocket 身份，观察至少 60 秒，起止均查询 Sidecar 协议。期间保留准入锁以便安全回滚，因此这段时间新的 Agent 工作会收到维护反馈。验收失败时恢复旧产物并重新核对会话。恢复失败保留标记和现场，阻止后续切换以及启动阶段的依赖覆盖，需人工核对。该标记防止继续写入，进程崩溃后的跨 JVM 自动回滚不在本次范围内。

该批次升级沿用当前目录提升，会改变配置的 Sidecar 目录内的包清单和锁文件。源码工作区部署应把这些文件纳入日常版本管理，源代码更新继续遵守原有工作树保护。候选、日志及备份保留供处置，按实际磁盘容量人工归档。源码更新的独立重启授权不包含本功能。自动模式部署、真实引擎会话验收及当前机器异常恢复均待运行验证。
