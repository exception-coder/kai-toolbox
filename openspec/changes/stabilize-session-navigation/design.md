# 稳定导航与手动置顶

## 事实与范围

`ClaudeChatService.switchSession`、冷恢复 attach、Sidecar 重连恢复调用 `repo.touch`，把查看写入 last_seen_at；`RecentSessions` 每三秒按此值重新切片、分组排序，`SessionList` 同时重排项目及日期分段。并非点击设置了 favorite，而是访问时间制造了类似自动置顶的表现。

本次修复开发工作台的最近会话和项目会话选择；会话看板是实时监控视图，仍保留既有排序契约。核心 AI 执行、监督、writer 及交付生命周期无变化，不修改 AI 编程整体架构契约。

## 数据与状态

2026-10-31 用户调整最近会话契约：该区域跨项目平铺，手动置顶在前，普通会话按最近显式查看排列；目录分组与点击不重排约定仅保留于项目导航。此处是 NAV-02 的用户明确指定例外，不将查看写为真实活动或手动置顶。后端访问、活动和置顶接口保持不变。

最近与项目会话行在明确打开时记录逻辑 session ID 和查看时间，使用当前 origin、当前用户范围的浏览器偏好，最多保留 50 项且去重；不记录标题、路径、对话或凭据，不宣称跨设备同步。刷新和组件重挂载恢复顺序，同页及跨标签变更通知最近列表；跨标签并发写沿用 localStorage 最后写入生效，不宣称原子合并。存储失败保留当前页面顺序并明确提示，再次打开可重试保存。只与当前已授权、未过期且符合状态筛选的会话列表求交，删除/隐藏对象立即移除，不能从偏好恢复越权数据。

最近列表不再呈现目录标题或折叠按钮；会话元信息保留目录短名及完整路径提示以识别同名会话。普通项排序先取显式查看顺序，再用原活动快照补齐，条数上限在排序后应用；手动置顶按原 pinnedAt 在全局最近列表优先。后台轮询只更新行内容，未查看新项仍由“更新排序”纳入。稳定行 key、原滚动容器、更多菜单、键盘和焦点恢复沿用原实现。本次无新页面/弹框，无模型运行、后端写入、重启或整体 AI 编程架构职责变化。

查看/恢复仅 `updateStatus`，不改活动时间、favorite 或历史。真实发送、收轮、执行中断仍由原 `touch` 记录活动。列表新增 `lastActivityAt` 投影，保留 lastSeenAt 兼容；两者使用现有 last_seen_at 列，不凭猜测回填旧会话时间，不扫描大 transcript。历史值可能已含旧访问时间；修复后查看不再写入。不新增未使用的 lastOpenedAt，也不伪造无法独立证明的 lastMessageAt。

置顶复用 favorite PUT/DELETE 和原会话访问策略，`SessionPinService` 将 session ID → pinnedAt/0 保存在 claude_chat_setting 的当前用户键中；0 明确覆盖旧收藏。每次列表一次读取、内存投影，写操作在单实例内串行合并，重复置顶保留时间。用户身份仅来自 AuthContext，不接受客户端用户 ID。旧 favorite 仅回退给会话原拥有者；管理员查看他人会话不继承其偏好，匿名本地模式独立保存。原收藏列、历史及所有权不改，无人工 SQL 或数据迁移。

`useStableSessionOrder` 保存进入视图时的活动排序依据，显示数据继续使用实时对象；不冻结标题、运行状态或记录大小。切换会话不改变快照；轮询的新活动/新会话触发提示，尚未展示的新普通会话等用户更新排序后纳入。删除、权限/过滤排除即时隐藏；手动置顶按 pinnedAt 在组内优先，取消后回到当前普通快照顺序，项目不因置顶重新归组。项目进入/筛选/视图重挂载或用户更新排序可重新采纳最新活动。

最近会话保留全部符合过滤条件的置顶项，加最近 N 个普通项，避免置顶被截断。项目内存在置顶时才显示“置顶会话”段；原日期段只包含普通项，同一会话在该列表不重复。最近与项目入口是既有两种视图，本次不另建全局置顶列表。

## 产品原则与交互

适用 OBJ-01、NAV-01、NAV-02、CTX-01、FEED-01、AI-01、EVID-01、CTRL-01、IDEM-01；NAV-02 对最近会话采用用户明确要求的查看次序例外，项目列表仍保持稳定。

1. 主对象是原 session ID 和原项目/目录分组。沿用列表、行更多菜单和 favorite API，无重复导航。
2. 置顶是行内动作，不打开新页面；小图钉显示状态，更新排序依附原列表标题。点击会话选中高亮并在最近入口记忆查看次序，项目列表位置不变。
3. 提交期间禁用重复置顶，确认后更新当前缓存并重新核对服务器；失败保留原状态和可恢复错误，不伪称成功。关闭菜单不撤销请求；用户偏好加载损坏保留数据库原记录并报错。无新全局草稿。
4. 稳定 React 对象 key、排序快照和原滚动容器保持连续操作位置；不因轮询挂载另一套列表。键盘/手机沿用既有 Popover，Escape 返回触发器，按钮及更新排序可达。
5. 幂等身份为真实用户 + session ID；PUT/DELETE 明确目标值，重复 PUT 不刷新 pinnedAt。用户偏好跨页面刷新保存；正常无新活动时不出现空置顶分组。

## 验证边界

定向回归覆盖三会话连续切换、后台更新不移动会话/分组、手动刷新、日期归属稳定、旧置顶不被最近限制裁剪、置顶/取消/失败、滚动和菜单焦点。SQLite 测试证明用户隔离及重新构造服务后回读，HTTP 测试证明访问限制和批量一次查询，WebSocket 用例证明查看不 touch。手机/桌面真实组件浏览器使用 HTTP 夹具，不替代待授权重启后的当前服务验收。
