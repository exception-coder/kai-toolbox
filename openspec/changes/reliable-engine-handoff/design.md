# 设计

## 状态与证据

- Java 保存交接状态及每引擎确认游标；追加文字记录使用持久序号，不依赖浏览器数组下标。首次从既有历史导入可获得的文字，缺失段显式记录。新轮记录用户原文与助手输出，工具执行状态不跨引擎搬运。
- 每次切换冻结消息上界，持久化操作 ID、目标引擎、原生句柄和交接文本。重复相同目标复用进行中的操作；不同目标在接管期间拒绝。完成时按操作 ID 比对再原子保存目标句柄、游标和当前引擎。
- 交接内容为不可信用户历史，包含目标/约束的原文、近期进展与完整证据文件引用，不冒充系统授权或已验证业务事实。完整文字留在本机私有运行目录；超过提示预算保留首条目标和近期文字并明确缺口。不引入另一个摘要模型。
- Sidecar 用隔离 Session 恢复目标原生句柄，执行禁止业务工具的交接轮，必须返回有效原生句柄及成功终态才允许提交。旧 Session 保持原绑定。失败不推进游标，不静默新建替代失效原生会话。各引擎必须有可执行的工具禁用约束；不支持时明确拒绝。
- 接管只确认历史已提交给引擎并成功完成一轮，不证明模型理解全部资料。原生历史不是文件快照，下一轮必须检查当前工作区。切回增量与原生历史合并；从未接入统一记录的旧引擎段可能缺失。
- 活动轮、后台任务和未处理队列阻止切换；所有发送入口检查交接中状态。断线不自动重放；Java 重启后将 PREPARING 操作标为需重试并保留原绑定；ACTIVATING 保留已提交的目标绑定并等待运行连接确认。准备阶段超时终止候选轮，旧会话可继续。

## 产品交互

适用 OBJ-01、NAV-01、CTX-01、FEED-01、AI-01、EVID-01、CTRL-01、IDEM-01，无例外。主对象为原 Forge sessionId，复用既有引擎菜单，不加导航。选择后保留当前引擎并显示接管进度；成功才更新引擎，失败保留草稿并可重新选择重试。重连由服务端重发交接状态。键盘、手机菜单复用原控件，状态使用现有提示区；真实浏览器及登录态验收待加载目标版本。

## 结构证据

prepare_sql_context：DDL_MISSING（05b415f0-6cc1-4d66-acb2-014e632d4468），项目扫描达到上限；Forge 系统 9f900c09-62b6-42f0-a2cf-a10e00ed220f 无绑定资源。基于本仓 SQLite schema 增加幂等表，仅在测试库核验；运行 DDL 未核验、不写运行库。

## 实施补充

- 状态为 PREPARING → ACTIVATING → COMPLETED。PREPARING 失败保留原绑定；ACTIVATING 已持久保存目标绑定，必须等目标原生句柄对应的运行连接确认，不能当作原绑定未变。重连期间禁止发送，重启不自动重跑接管模型调用。
- 已确认位置同时绑定原生句柄和认证目录/服务商环境指纹，身份变化重新补充上下文。提交前比对源配置，防止并发改账号、模型、权限模式造成混用。
- 当前受限接管适配器为 Claude、Codex、Pi、Copilot；Codex 复用已有 review-only 沙箱及 MCP 禁用配置，Claude 强制空工具/空配置来源，Pi/Copilot 使用确定性工具权限回调拒绝。其他适配器没有等价机制时显式拒绝，此缺口不能用提示词代替。
- 首次导入调用一次现有原生历史读取器；每次切换按索引读取本会话证据，生成一份完整文字文件和有预算的提示。成本随单会话历史线性增长，无逐行远程请求；大型会话现场性能尚未验证。各轮按消息身份追加，文本快照更新不改变稳定序号。
- 不新增自动摘要模型。结构包保留首次目标原文、近期增量和完整文字引用，决策与验证结果以历史发言呈现，不自动提升为可信事实。
- 设计依据沿用 [Claude 会话恢复](https://code.claude.com/docs/en/agent-sdk/sessions) 与 [ACP 会话能力协商](https://agentclientprotocol.com/protocol/v1/session-setup)。具体适配以本仓锁定 SDK 和现有原生接口为准。
