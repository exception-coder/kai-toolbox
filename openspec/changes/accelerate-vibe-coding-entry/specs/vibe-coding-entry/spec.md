## ADDED Requirements

### Requirement: 首屏按需加载

系统 MUST 保留前端 manifest 的菜单与路由权威性，注册菜单时不求值无关页面组件。隐藏的悬浮窗和语音界面 MUST 不阻塞首屏下载；开启后仍可使用同一常驻会话。普通 Markdown MUST 不预先下载图表库，品牌图标 MUST 保持原有形状与可访问属性。

首屏工具类 MUST 仅由真实 UI 源码生成，不将父目录、本地缓存或构建输出作为扫描范围。入口 HTML 加载壳 MUST 沿用独立的手写样式。

#### Scenario: 进入开发工作台

- **WHEN** 用户直接进入 Vibe Coding，未开启悬浮窗与语音界面，消息不含图表
- **THEN** 先加载工作台必要资源，不通过菜单注册连带下载交付弹窗、SQL 控制台、整套品牌图标集合或图表库

#### Scenario: 使用按需功能

- **WHEN** 用户开启悬浮窗或语音界面，或收到后台提问，或消息含 Mermaid 图表
- **THEN** 加载对应功能，维持现有会话与权限边界，功能失败由自己的错误边界或源码降级呈现，不拖垮工作台

#### Scenario: 工作区存在本地构建或分析缓存

- **WHEN** 开发工作区中存在临时构建产物或本地分析缓存
- **THEN** 主样式仅扫描 UI 源码，现有桌面和手机界面的工具类继续生成，入口 HTML 的加载壳样式保持独立，不因无关文件扩张样式扫描

### Requirement: 最近会话快速恢复

系统 MUST 在有近期已确认会话提示时立即启动恢复，并异步核验提示；无提示时按服务器列表恢复最近会话。提示 MUST 不包含聊天内容且不能绕过服务端授权。

#### Scenario: 刷新最近会话

- **WHEN** 用户刷新 Vibe Coding 且浏览器有有效会话提示
- **THEN** 客户端不等待完整会话列表即可发起连接，聊天记录另行加载

#### Scenario: 提示失效

- **WHEN** 列表中不再存在提示会话
- **THEN** 客户端更新提示并恢复有效的最近会话，不覆盖期间用户主动选择的其他会话


### Requirement: 最近历史有界复用与加载恢复

客户端 MUST 以当前登录凭据和服务器会话身份隔离最近消息页缓存，限制缓存容量、数量与有效期。缓存 MUST 不落盘，切回显示缓存时 MUST 标明正在更新并继续请求最新页；公开评审和演示不得复用登录缓存。

#### Scenario: 切回已读取会话

- **WHEN** 当前登录凭据下存在未过期且未被淘汰的最近页
- **THEN** 立即显示该会话缓存，在 ready 后更新权威历史，更新失败保留内容并提供重试，重试不误读更早页

#### Scenario: 过滤导致空白

- **WHEN** 已加载消息经工具隐藏过滤后没有可见消息
- **THEN** 页面说明已加载及隐藏状态，并提供显示工具记录的按钮

#### Scenario: 切换期间旧会话迟到事件

- **WHEN** 用户选择其他会话，原会话的输出、ready 或历史响应随后到达
- **THEN** 不将这些内容写入新会话或其缓存，不改变当前选择；目标会话的正常输出继续呈现，快速连续切换只连接最终目标

#### Scenario: 登录变化或缓存超限

- **WHEN** 登录凭据变化、缓存过期或正文容量超限
- **THEN** 不复用失效缓存，按现有授权流程读取历史且显示最近消息加载状态
