## 业务定义

kai-toolbox 里每一项可配置参数（分门别类归到不同"配置块"里），实际生效值可能来自好几处：部署时的配置文件、环境变量、以及运维/使用者在"配置中心"界面里手动保存的"覆盖值"。这几处来源同时存在时，谁说了算是这条业务规则要定义的：

**配置中心界面保存的覆盖值，优先级永远最高**——只要某个配置项被保存过一次覆盖值，不管配置文件/环境变量里写的是什么，实际生效的都是这个覆盖值。这是一种"一旦手动改过，就以手动改的为准"的语义，而不是"谁最后加载谁生效"这种时间顺序语义。

第二条规则是**热生效**：覆盖值一旦保存成功，系统里所有依赖这项配置的地方立刻按新值运行，不需要重启进程、不需要重新部署。这意味着配置中心不只是"存了一份值"，还承担了"让运行中的系统知道值变了、并重新应用"的职责。

组合起来看，这是一个"运行时可调、优先级最高、即时生效"的配置覆盖机制，区别于常规的"改配置文件要重启才生效"的运维认知。

## 适用范围 / 边界

- 成立范围：所有被登记进配置中心、支持"可刷新"的配置块。
- 不适用：没有被登记进配置中心管理的普通配置项——那些依然遵循"改文件/环境变量需要重启才生效"的常规认知，配置中心管不到它们，覆盖优先级规则也不适用。
- 特例：应用重启后，之前保存的覆盖值依然会被重新加载并保持最高优先级——"覆盖"是持久化的决定，不是临时的运行期状态，重启不会让它失效、回退到配置文件的原始值。
