## 实现边界

在 `.forge/execution-control.json` 增加 `verificationCadence`，使用同一项目身份、乐观版本与原子保存，记录操作者和原因。缺省为 CHECKPOINT；旧请求不传该字段时保留已配置值。新前端面对旧服务禁用选择，避免保存假象。

- CHECKPOINT：关联实现和测试完成后集中做最小充分验证。跨任务仍需既有 VERIFY_GROUP 标记及 Runtime 授权，最多六项；未标记仍单任务。
- PER_TASK：本轮只下发一个任务的验收描述，不授权跨任务合并验证。
- 两种节奏都保留权限、事务、迁移、失败修复的及时定向验证。已有有效证据可引用；输入改变、失败或环境敏感检查需适用重验。直接命令不享受 Forge 缓存，不宣称自动阻止所有重复测试。
- 当前任务多次派发且完成数未变化时保留诊断计数并提示收口，不推断没有代码进展，不增加暂停或阻断。任务切换或完成数改变后清零。
- 任务文本是规格数据，不授予新权限。只从匹配 revision/phase/task 的快照取验收内容；进度仍由真实任务勾选及 Runtime 重读决定。
- 设置对下次新生成的自动续跑消息生效；已排队消息与当前活动轮不改写、不打断。上线需要获授权后加载新版后端；本次不主动重启。

## 产品原则

适用 OBJ-01、NAV-01、CTX-01、DENS-01、FEED-01、AI-01、EVID-01、CTRL-01、IDEM-01，无例外。

主对象是当前会话所属的真实项目目录。复用监督面板项目控制区，不增加导航或配置副本；选择器紧邻门禁设置，44px 触达与换行适配窄屏。原生 select 保留键盘/焦点；不打开覆盖层、不丢草稿。

加载或旧服务时禁用；请求中禁止重复；保存成功后更新服务器结果并刷新同项目面板。冲突/未知结果提示核对实际状态和重试，不乐观伪报成功。相同值幂等无新审计，跨会话过期版本拒绝覆盖。

## 验证与限制

覆盖旧配置默认值、审计与并发、旧请求保留节奏、API 访问边界、批次收窄、门禁关闭仍传验收、诊断不暂停、前端旧服务和保存失败恢复。专项与质量门禁结果记录在 tasks.md。上线后的目标会话推进效果另验，不以单元测试代替运行事实。
