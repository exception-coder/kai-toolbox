## 4. Phase 6 Code Review

审查中除原四项问题外，继续修复了六项收敛缺口：公开 SDK 仍依赖内部 React Bridge、草稿等动作仍走额外 HTTP、离线待发送消息未纳入 SDK 持久恢复、声明构建误包含整个前端、外部 WS 缺少动态 Token 与 Origin 白名单配置、局部页面更新误清空其他上下文。修复后相关类型检查、定向测试、独立构建和 Chrome 冒烟均通过。

隐藏与移动能力复审中又修复了四项边界：打开动画短暂透出宿主内容、无 Transport 时隐藏状态未同步、窄屏切回桌面后未恢复已保存位置、移动端胶囊无法拖动。最终交互采用无功能语义、低冲突的 `Ctrl/Command + Alt/Option + Shift + 0` 默认开关、可选本地显示密钥、宿主主动 `open()` 直达、跨端胶囊拖动、桌面对话框拖动、`Alt + 方向键` 微调、位置按应用与用户保存；窄屏对话框切换为固定全屏。显示密钥明确不是认证凭证。

对话状态复审对齐 Vibe Coding 的交互不变量：发送动作先乐观追加用户消息，再采集上下文；准备和回复状态进入消息流；完整忙碌状态集合统一锁定按钮与键盘提交；失败后保留输入草稿并恢复发送。当前 54 项 SDK 测试、桌面回复态及窄屏失败恢复态真实浏览器取证通过。

第三方接入复审补齐了两个可恢复入口：准备阶段中止会取消当前 Provider 收集，连接或执行阶段中止会复用既有 WS `interrupt` 协议；调试面板以最多 200 条内存日志展示准备、连接、发送、接收和错误阶段，仅记录协议元数据。另修复漏配 `wsUrl` 时提交事件无人消费而永久停在准备态的问题，现会立即显示配置缺失。中止按钮和调试面板已完成 Chrome 实际交互取证。

外部认证复审发现普通 Forge 登录响应包含长期 Refresh Token，因此未直接给 `/api/auth/login` 开放 CORS。最终增加 `/api/auth/external-login` 专用入口：复用同一账号认证和权限解析，只签发短期 ACCESS Token；CORS 仅覆盖该路径的 `POST/OPTIONS`，普通登录、刷新和用户管理继续保持同源。

当前未发现阻断受控试用的高优先级代码问题。剩余项均属于已声明的环境或产品决策：三宿主真实接入、真实浏览器故障注入与截图、HTTPS 部署配置、正式评测样本和阈值。
