## 业务定义

```mermaid
flowchart LR
  A[创建澄清会话，确定原始需求与提问角色] --> B[逐轮追问：每轮基于原始需求+历史问答提出下一个问题]
  B --> C{AI判断信息是否已充分？}
  C -- 是，输出完成信号 --> E[结束追问]
  C -- 否，且未达5轮上限 --> B
  C -- 否，但已达5轮上限 --> E
  E --> F[转入"生成PRD"阶段]
```

- **每轮只问一个问题**：与早期"一次性生成5个问题"的方式不同，当前流程每一轮只提出当前最关键、最影响需求完整性的一个澄清问题。
- **动态追问**：每一轮提问时会带上"原始需求 + 已经完成的历史问答"，AI据此决定下一个问题问什么，问题会随着已知信息的积累而变化，不是预设好的固定问题列表。
- **两种终止条件（任一满足即停止追问）**：
  1. AI主动判断信息已经足够支撑生成PRD，输出一个"完成"信号；
  2. 无论是否判断充分，轮次达到上限（最多5轮）后强制停止。
- **追问结束后的收尾**：完整的问答历史会被固化保存，供后续"生成PRD"阶段读取使用。
- **完成即转场**：追问结束不会停留等待，而是直接作为"生成PRD"阶段的输入前提，两个阶段前后衔接。

## 适用范围 / 边界

- 该流程只描述"澄清提问"这一个阶段的交互协议，不覆盖PRD正文如何生成、开发文档如何生成——那是各自独立的产出阶段，衔接点仅在于都读取本流程固化下来的问答历史。
- 提问的内容深度、语言风格由"提需求方角色"决定（见同模块的角色知识点），但轮次结构（每轮一问、最多5轮、两种终止条件）对两种角色都一致，不因角色而变。
- 早期"一次性批量生成5个问题"的方式已被本流程取代；若代码中仍留有相关痕迹，属于历史实现细节，不代表当前业务口径。

## 备注

- 口径来源：kai-toolbox 代码调研起草，待 owner 核实。
