## 业务定义

```
一次调用成本 = 输入token数 / 1,000,000 × 输入单价(元/百万token)
            + 输出token数 / 1,000,000 × 输出单价(元/百万token)
```

变量含义：
- **输入 token 数 / 输出 token 数**：这次调用实际消耗（或估算）的输入、输出 token 数量，两者分开计价，因为输入和输出的单价通常不一样。
- **输入单价 / 输出单价**：以"每百万 token 多少钱"为口径配置在模型规格上，每个具体模型（同一档位 tier 下可能有多个模型成员）都可以有自己独立的单价。
- 如果某个模型没有配置单价（典型情况是本地部署、不产生真实费用的模型），单价按 0 处理，这次调用的成本核算结果就是 0，代表"不计费"而不是"数据缺失"。

这条公式是纯算术，不依赖任何外部实时汇率或第三方计费系统——它是 kai-toolbox 自己对"这次调用花了多少钱"的口径定义，用于监控页面的成本展示和统计，不代表向模型供应商实际结算的账单（如果供应商计费规则跟这里配置的单价不一致，两边数字可能对不上）。

## 适用范围 / 边界

- 成立范围：所有被 LLM 监控记录下来的调用，不论成功、失败还是被配额拦截，只要产生了 token 消耗都会按这个公式核算成本。
- 不适用：模型未配置单价时（如本地模型），核算结果恒为 0，不代表真实免费，只代表"这里选择不对它计费"。
- 特例：token 数如果是估算值而非真实值（比如流式响应或不返回精确用量的情形），成本也是基于估算 token 数计算的，属于近似值，不是精确账单。
