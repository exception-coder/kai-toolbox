## 操作与状态

复用会话控制队列，置顶执行/追问/待核对项显示“暂停核对”和“终止询问”，每项显示“删除”，44px 触控目标可换行。沿用主题 Token，不添加导航。请求中禁用重复操作，失败通过现有同步警告反馈；切换会话后旧请求不得改写当前会话。

后端复用会话访问检查和会话锁。待发项仅删除自身；有派发记录或置顶完成追问时，先保存 `user_cancelled` 撤回自动化意图，再核对 Sidecar 活动轮次，匹配才请求中断。查询失败、错轮或中断未送达不撤销已保存的意图，也不声称原生停止；保留运行证据并提示核对。单纯终止前一任务追问时保留待发队首；删除则移除指定项并同步任务 CANCELLED，不再退回 WAITING。清空携带确认过的 ID 集合，避免误删新增项。

新增“暂停核对”保存 `user_paused`，保留队首及原生执行，停止自动调度和完成追问。迟到接收、失败或完成回执不能恢复自动化；恢复仍须明确核对与原生空闲准入。消息删除的身份／时间以 SQLite 撤回记录保存，防止旧 POST 重新入队；当前浏览器以会话和消息 ID 过滤迟到列表。关联任务投影为 PAUSED 或 CANCELLED，不改变原生实际结果。

撤回意图在会话锁内保存，引擎状态 RPC 在锁外等待，取得快照后重新核对当前仍为同一撤回轮次，避免接收线程处理终态时被会话锁堵住或错误中断新任务。批量清空逐项核对，不在外层持锁等待引擎；已处理项与未处理项由重新读取列表反映，不伪报全部清空。

新增幂等 `claude_chat_queue_retirement` 表，只保存撤回消息身份与时间，不复制正文或凭据。知识库 DDL 工具返回 DDL_MISSING（扫描达到上限），运行库 DDL 未核验；以仓库 schema 与隔离 SQLite 为验证依据，不对真实运行库执行修补 SQL。

适用原则：NAV-01（动作依附队列对象）、CTX-01（保留会话与其他消息）、DENS-01（直接可见的关键控制）、FEED-01/EVID-01（区分终止请求与停止事实）、CTRL-01（使用者接管）、IDEM-01（旧 ID 不影响新任务）。无原则例外。现有业务全景中的会话排队、暂停能力及主流程不变；本次补齐该能力的具体恢复控制，不重绘全景图。
