## 业务定义

```mermaid
flowchart LR
  A[收集当前全部活跃需求(排除已取消)] --> B[整体提交AI做横向对比]
  B --> C[产出组合优先级摘要 + 每条需求的排名与对比差异说明]
  C --> D[覆盖回写每条需求的AI洞察结果]
```

- **背景**：对单条需求做AI洞察分析时，只能孤立评估这一条需求本身的价值，无法体现需求相互之间"谁更该先做"的比较关系。组合(Portfolio)分析流程用于弥补这个不足。
- **收集范围**：取当前全部"活跃"需求（即排除已取消状态的需求）作为一个整体集合，一次性提交。
- **横向对比而非逐条打分**：AI不是独立评估每一条，而是综合考虑这批需求相互之间的业务影响面、战略重要性、投入产出比、实现风险、相互依赖关系，给出一个整体的、相对的最优开发顺序。
- **排序考虑的优先级因素（按重要性依次）**：业务影响面（影响越多关键流程越优先）> 战略重要性（与核心业务路线图的关联度）> 投入产出比（高的优先）> 实现风险（同等条件下技术复杂度低的优先）> 依赖关系（被其他需求依赖的先做）。
- **产出**：一份"整体建议摘要"（说明本期的核心优先策略），以及每条需求的排序结果——排序结果比单条分析多两项：**绝对排名**与**与其他需求相比的差异点说明**。
- **回写方式**：每条需求原有的AI洞察结果会被整体覆盖更新为本次组合分析的结果（含新增的排名与差异说明字段）。

## 适用范围 / 边界

- 与单条需求AI洞察分析共用同一个存储位置：触发一次组合分析后，此前单条分析得到的洞察内容会被整体替换掉，两者不能共存。
- 该流程只产出"排序建议"，不直接改变需求本身的状态（不会让某条需求自动进入"开发中"等状态），是否采纳排序建议由产品经理自行决定。
- 只纳入"活跃"需求参与比较，已取消的需求不参与本轮横向对比。

## 备注

- 口径来源：kai-toolbox 代码调研起草，待 owner 核实。
- 易混点：这里的"排名(rank)"是相对本次参与比较的这批需求而言的相对名次，不是一个可以跨批次累加/比较的绝对分数——不同批次的组合分析之间排名不能直接对比。
