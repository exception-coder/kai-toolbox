## 业务定义

有些配置项的值本身是"一组值"（比如一份名单、一批地址），不是单一的数字/字符串。这种"列表型"配置项的覆盖行为跟普通配置项不太一样，容易被误解，所以单独讲清楚：

**默认语义是按 key 逐条覆盖，不是整体替换**：保存覆盖值时，如果没有对某个列表型配置项声明"整体替换"，那么这次保存动作不会清空这个列表已有的旧内容；同一个列表的多次局部改动，实际语义更接近"针对某些具体条目做增量调整"，而不是"每次保存都用新提交的内容完全取代旧列表"。

**要真正清空/替换一份列表，必须显式声明"整体替换这个前缀（列表项）"**：只有明确表示"这个列表要被整体替换"，旧列表的全部内容才会被真正清除，换成这次提交的新内容。这是一个需要使用者主动做出的选择，不是保存列表型配置的默认行为。

**"整体替换为空"和"从未覆盖过"是两个不同的状态，必须能区分**：如果显式选择"整体替换"、但提交的新内容是空的，业务含义是"我要把这个列表清空"，这跟"这个配置项压根没被覆盖过、还在用默认/文件里的原始列表"是完全不同的两种情况——前者是一个有意义的"清空"决定，后者是"没有人碰过它"。系统需要有办法把这两种状态区分开、分别持久化，不能因为"空列表"和"没有覆盖"在某些存储形式上看起来相似就把它们混同处理。

## 适用范围 / 边界

- 成立范围：所有值类型为"字符串列表"的配置项，覆盖操作走这套语义。
- 不适用：单值型配置项（数字、字符串、布尔）没有"逐条 vs 整体"的区别，覆盖即整体替换该值本身，不涉及这条规则。
- 特例：如果一个列表型配置项从未被覆盖过，它展示/生效的就是配置文件/默认值里的原始列表；只有当使用者主动做过"整体替换"的覆盖动作，才会进入"覆盖态"，此时清空动作才有意义地表达"我要的就是空列表"。
