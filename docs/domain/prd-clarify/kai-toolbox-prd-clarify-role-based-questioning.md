## 业务定义

"提需求方角色"是发起PRD澄清会话时确定的身份标签，代表"这次提需求的人是什么背景"，决定了整个澄清过程"该问什么、怎么问"的基调。分两种：

- **产品/开发角色**：面向懂技术的提需求方。提问可以深入到功能边界、交互流程、边界异常、技术约束、系统集成点等层面，允许问题直接引用代码结构、数据库字段、已有接口、枚举取值等技术细节，目标是尽快把需求钉死到可以直接开发的颗粒度。
- **业务人员角色**：面向不具备技术背景的业务提需求方。只问业务本质相关的问题——业务目标、使用场景、关键数据、业务规则与例外、验收标准；不问界面细节、数据库/接口、框架选型等技术问题（例外：若界面本身直接影响业务流程，仍可以问）。语言力求通俗，避免出现技术术语，帮助非技术人员把业务痛点转化为清晰的需求描述。

角色在会话创建时一次性确定，贯穿整个多轮追问阶段，不支持中途切换角色。

## 适用范围 / 边界

- 角色只影响"怎么问、问什么深度"，不影响会话的状态流转——两种角色走的是同一套"澄清中→生成中→完成/出错"状态机，也不改变追问轮次的结构（每轮一问、最多5轮、两种终止条件对两种角色一致）。
- 角色不影响最终PRD文档的章节结构——无论哪种角色发起，生成的PRD都遵循同一套标准章节模板。
