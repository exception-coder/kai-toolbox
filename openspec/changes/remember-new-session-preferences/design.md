# 新建会话偏好设计

适用 OBJ-01、CTX-01、FEED-01、EVID-01、IDEM-01；无例外。对象是当前浏览器中 Forge 用户的手动新建选择，目录以完整路径、服务商以已有档案 ID 标识。既有工作区、引擎目录和服务商服务仍是可用性来源，不从偏好推断身份或权限。

用户在新建表单手动切换工作区、选择项目或输入目录、切换引擎与服务商时即记录，不要求先点击开始会话；离开、关闭或刷新保留这些选择。仅打开表单、导览定位、服务商异步加载及跨模块程序填充不写偏好，也不自动创建会话。手动选择调用专用 select，普通 setters 保留为程序填充；在 React 提交选择后保存白名单字段并反馈存储失败，旧账号回调不能写入新账号。默认工作区已按首个可用目录显示时，其他手动选择一并记住该完整根路径，避免工作区重排选错。开始会话仍确认一次完整选择。目录恢复为工作区及项目选择，路径编辑在工作区设置中提供，别名、模型、Key、地址、权限和 SDK 句柄不进入新存储。Codex Auth 目录沿用已有独立偏好。恢复服务商时模型默认值取当前档案，迟到结果不能覆盖手填模型。

偏好位于当前 origin 的 localStorage，按用户 ID 分隔；刷新、重新挂载恢复，其他浏览器、设备、站点不自动同步。版本与字段验证失败使用默认值并提示；存储拒绝时保持本次表单可用。

根目录按路径匹配，不使用下标；删除或不可访问的根不跳到其他目录，提示重新选择或在设置中登记。运行目录未确认时不展示猜测的引擎；旧引擎失效时选择当前可用项并提示，未加载或删除的服务商保留提示和恢复入口；原服务商失效不切换官方。用户明确选择当前可用值后继续。记忆仅是默认值，不跳过后端路径或服务商授权校验。

复用新建表单、状态与既有选择控件，逻辑落在专用 hook 和偏好函数中。集中验证刷新/账号隔离、工作区重排、迟到档案、失效选择、存储拒绝及正常会话配置；前端类型、适用构建和质量检查，不运行全套前端测试或重启服务。

最近有效配置沿用同一 v1 偏好中的可选 recent 白名单字段，仅在显式发起已校验的创建时更新；手动草稿修改不覆盖该字段。旧偏好可作为待核验候选，目录、项目、引擎或服务商失效时不直接复用。呈现和验证要求见 [极简新建会话设计](../simplify-vibe-new-session/design.md)。
