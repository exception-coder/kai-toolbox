# 共享会话默认名称与所属工程缺失

2026-11-24。接收侧不能区分不同工程的同名会话，新分享的无自定义标题会话只显示“共享会话”。

## 原因与修复

普通 ChatPage 的标题使用 `title.trim()`，为空时使用 cwd 末级目录名；SharedSession 原来直接返回可空 title，接收页回退为“共享会话”。共享投影也没有项目显示名。

SessionSharingService 现在复用原会话的名称规则，仅返回末级名称，不返回完整路径。所属工程通过 ProjectCatalog 的规范化路径包含关系匹配，子目录显示所属工程名；目录本身优先使用登记显示名。列表一次加载项目目录，详情在 requireReader 成功后加载。没有可靠匹配、目录暂不可用时省略 projectName。

收件列表和接收侧栏第一行显示会话名，第二行显示项目、权限和引擎；只读与协作共用页头展示相同项目名，长名称截断且可在信息浮层中完整阅读。授权失效时不呈现项目名。沿用共享授权和项目排除检查，无架构契约、数据库结构或认证变更。

## 验证范围

定向测试覆盖两工程同名会话、名称默认值及改名同步、项目目录不可用、只读和协作页头、历史数据与撤回失权。类型检查和 OpenSpec 严格校验通过。质量门禁的运行检查仅为当前运行版本 `/api/tools` HTTP 200，不代表新共享行为已上线。

未重启服务，真实桌面和手机具名账号验收待目标版本加载后执行。规格及交付状态维护于 `openspec/changes/share-chat-with-users/`。
