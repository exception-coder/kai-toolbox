## Context

`RolePage` 当前直接渲染标题、行内编辑表单与角色表格；`PermissionExplorer` 已提供更成熟的工作台式权限配置体验。源码坐标由 Graphify 定位后，以当前工作区的定向源码读取复核。项目存在大量与本需求无关的未提交改动，因此实现范围必须限制在 `frontend/src/features/forge-role` 及本 change。

设计注册表没有项目绑定，采用 global core；由于项目已经具备语义主题变量、Button/ConfirmDialog 等共享组件，Guardian 选择 **CONSERVATIVE** 模式，按 Reuse → Extend → Compose 实施。视觉方向为“安静的权限治理工作台”：强左对齐、舒适密度、细边界和单一功能强调色。

## Goals / Non-Goals

**Goals:**

- 让管理员能快速理解角色总量、启停状态、数据范围和每个角色的主要动作。
- 将角色编辑从无标签的横向控件流改为有语义标签、说明和明确提交状态的表单。
- 桌面端保持可扫读的数据密度，窄屏自然重排且不依赖整页横向滚动。
- 加载、错误、空列表均保留角色管理上下文并提供恢复动作。

**Non-Goals:**

- 不修改 API、权限码、角色业务校验、数据范围枚举或内置角色规则。
- 不引入新的状态管理、表格或表单依赖。
- 不重新设计权限分类算法和父子权限联动。

## Decisions

1. **角色列表使用响应式实体行，而非传统 `<table>`。** 桌面端采用对齐网格呈现列语义，移动端折叠为单实体行的两层信息结构。相比给表格增加横向滚动，这能保持关键操作在窄屏可见；相比卡片网格，它保留了业务管理页需要的扫描密度。
2. **编辑区以内嵌 section 呈现。** 继续保留当前页面上下文，不新增抽屉/模态依赖；用标题、说明、字段标签和底部动作带建立层级，避免 Card 套 Card。
3. **只使用现有语义变量和共享控件。** Accent 仅用于主操作、选中/启用状态和 focus ring；状态使用文字与小型指示符共同表达，不依赖颜色单独传意。
4. **错误与空状态提供恢复动作。** 查询失败显示重试；空列表在有编辑权限时可直接新建，否则解释当前状态。保存/删除失败保留当前表单或列表上下文。
5. **权限浏览器只做必要的一致性修整。** 主体三栏模型、搜索和保存行为保持不变，避免扩大业务风险。

## Risks / Trade-offs

- [Risk] 非表格网格可能降低原生表格语义 → 使用列表与清晰的桌面列标题，并为操作提供可访问名称；移动端阅读顺序与视觉顺序一致。
- [Risk] 当前 API 未直接返回每个角色的权限数量 → 页面不虚构数据，只呈现已有字段并把权限配置作为明确动作。
- [Risk] 工作区其他未提交修改可能影响全量构建 → 先运行前端定向 typecheck/build，并在交付中区分本变更与既有问题。
- [Risk] 真实数据可能包含长名称和编码 → 网格列使用 `minmax(0, ...)`、截断与 title，移动端允许安全换行。

## Migration Plan

纯前端兼容改动，无数据迁移。部署沿用现有前端构建流程。回滚时只需还原 forge-role 页面及本 change，不涉及后端或数据库。
