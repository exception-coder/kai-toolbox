# 深层文档大纲设计

## 范围与证据

变更前 `TocPanel` 只查询和观察 h2、h3；目标文档的“3.3.1”实际渲染为 h4。复用此组件及现有桌面侧栏、移动端抽屉，不新增页面、折叠状态或设置。文档 h1 仍作为正文标题，不加入章节大纲。

## 行为与兼容

- 提取与 DOM 变更观察使用同一 h2–h6 选择器，层级来自实际标题标签，不解析文本中的编号。
- 大纲按正文顺序排列，h2 左侧留白 8px，之后每级增加 12px；长标题截断并提供完整标题提示。
- h2、h3 继续按它们自己的顺序生成旧格式锚点，新增 h4–h6 使用独立的锚点前缀与计数，避免改变旧备注关联。已有显式 ID 原样复用。
- 点击链接仍滚动到标题正文，显示当前定位项；动态加入或移除标题沿用已有观察与空状态。

## 产品原则与交互

适用 OBJ-01、NAV-01、CTX-01、DENS-01、EVID-01，无例外。

1. 对象是当前文档，由文档源与文件路径标识；复用当前预览节点和章节锚点。
2. 沿用大纲侧栏与抽屉；用户直接选择深层章节，不需要离开文档或切换额外页签。
3. 加载、错误、刷新及未保存草稿沿用所在文档页；无标题显示原空状态，章节移除后清理大纲。
4. 原生链接保留键盘操作；选中项使用 `aria-current` 标识。桌面和窄屏沿用已有滚动容器与抽屉焦点管理，实测深层章节定位。
5. 重复提取复用已有 ID，重复点击仅定位，不创建备注或执行写操作。

## 验证

仅增加深层导航与异步标题更新两项定向回归，检查实际 Markdown 渲染、旧锚点兼容及点击定位；执行前端类型检查、该 change 严格校验与项目质量门禁。使用用户提供的文档页核验桌面和窄屏入口；不触发服务重启或 SDK 发布构建。
