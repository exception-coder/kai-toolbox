## ADDED Requirements

### Requirement: 项目绑定的只读代码审阅
系统 SHALL 从已登记项目或当前会话关联仓库打开统一 Project Explorer，继承项目上下文、现有权限与排除政策，不接受客户端指定任意根路径；窗口 SHALL 提供目录、提交与工作区独立视图，关闭和 Esc 恢复原上下文。

#### Scenario: 查看目录与历史
- **WHEN** 用户浏览目录或翻页提交历史
- **THEN** 系统按目录/页有界加载，以不可变提交快照关联后续查询；选择提交显示其文件列表和新增/修改/删除/重命名语义。

#### Scenario: 审阅单文件
- **WHEN** 用户选择变更文件
- **THEN** 仅加载该文件前后版本，默认 Unified 且允许 Split；删除展示删除前内容，重命名展示原路径，审阅区域不提供文件修改或 Git 写操作；已登记项目可在同一窗口的独立 Git 操作区使用既有 Push 能力。

#### Scenario: 查看尚未提交变化
- **WHEN** 用户进入工作区
- **THEN** 系统分清 HEAD、暂存区、工作树及未跟踪文件，允许选择比较层，不将其作为已提交历史。

#### Scenario: 大量工作区变更按需浏览
- **WHEN** 用户打开包含大量未跟踪文件的工作区
- **THEN** 系统分组展示已跟踪变更和未跟踪目录，后者按目录和有界页面展开，并遵守 Git 忽略与项目排除规则；未展开目录计作一项而非文件总数。
- **AND** 搜索仍覆盖未展开文件；切换层级或查看文件不得更改 Git 状态，重命名保留原路径及暂存 / 工作树状态。

#### Scenario: 无法安全完整展示
- **WHEN** 文件为二进制、编码不支持、超过上限、路径越界或请求失败
- **THEN** 系统明确提示原因并提供适用的返回/重试；不显示截断 Diff 为完整结果，不读取项目外文件，不修改项目文件或 Git 状态。

#### Scenario: 按分支浏览历史
- **WHEN** 用户选择本地分支或已获取的远端分支
- **THEN** 系统固定该分支的提交版本查询分页历史，联动提交说明和变更文件；浏览不会 checkout 或 fetch，工作区变更继续描述真实当前工作区。

#### Scenario: 从项目审阅进入 Git 操作
- **WHEN** 用户从已登记项目打开浏览器并进入 Git 操作
- **THEN** 系统复用当前项目的既有工作区快照和 Push 能力；推送期间保留结果上下文，会话来源的审阅仍为只读。
