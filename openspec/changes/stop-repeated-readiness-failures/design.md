## Context and decision

引擎可在工具失败后仍正常结束一轮。Runtime 必须独立处理 `forge/check_execution_readiness` 和 `forge/check_change_readiness` 的结果，不能依赖 Agent 自报阻塞。

使用既有工具结果事件中的 session、turn、call ID；MCP 业务拒绝和传输失败均识别。按 run、generation、change、revision、phase、task 隔离计数，按工具名与规范化错误摘要计算指纹，去重回放。成功校验或不同失败重新计数；容量、限流和网络超时不计入配置阻塞。

第二次一致失败通过现有版本比较更新为 WAITING_USER，既有任务投影呈现 BLOCKED，清除内部续跑消息并发布看板更新。任务进度和用户消息保留。旧调度结果在派发前复查当前状态。已有“恢复”操作创建新 generation，使计数重新开始。

不强杀正在运行的引擎回合；当前回合可以收口，后续自动续跑停止。首个失败的计数仅存在有界内存中，后端重启后重新计数；已经写入的阻塞状态持久保留。最多保留 256 个上下文，每个上下文去重最近 256 个调用，避免长期会话占用无界内存。

## Boundaries and recovery

用户提供的缺配置英文错误没有在源码中找到，目标会话接口返回 403；不据此猜测配置项、不越权读取会话数据库。原始失败可在现有工具记录查看，看板展示重复前置失败及修复后恢复指引。仅限两个明确的前置工具，普通测试失败仍允许 Agent 修复代码。

复用原有对象上下文、阻塞原因和恢复操作，适用产品原则为 OBJ-01、CTX-01、FEED-01、EVID-01 和 CTRL-01（对象上下文、操作反馈与可恢复状态）；不新增导航、弹窗或审批。上线需另行确认后端重启，再验收真实会话；本地测试不能替代此项。
