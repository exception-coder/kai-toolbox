# Codex 静默期间误报警与中断

截图中上一轮完成标记下方仍显示“正在处理工具结果”，累计 829 秒。2026-10-08 日志确认 free 会话的中断被接受，4 秒后引擎终态未到而触发兜底，随后完成中断。状态文案来源是最近工具结果，不是模型仍在有效作业的证据。尚未确认是引擎、网络或终态事件丢失导致无响应。

2026-10-13 用户反馈两分钟警告，并指出实际任务可能超过两小时。Sidecar 原代码把两分钟静默映射为 `stalled` 和黄色警告，五分钟静默调用 `interrupt`。静默不能证明模型停止工作，这种本地推断会误伤长思考轮次。

## 修正边界

两分钟静默仅记录一次诊断日志，不改变任务阶段、不生成警告消息、不触发中断或重试，也不提前释放写入权。有效响应恢复后重新计时。整个任务没有由该监测器施加的总时长上限，三小时静默仍保持等待。

实际工具执行继续遵守原工具 watchdog 的独立空闲和总时长限制；本修复不代表单次工具调用可以无限执行。等待工具或人工确认期间不生成模型静默诊断。本地 turnActivity 和 watchdog 心跳不刷新有效活动时间。真实 result 停止检测，异常退出、RPC 错误、明确的连接恢复失败和用户取消仍走原有终态与清理逻辑。

依据 [OpenAI App Server 生命周期协议](https://learn.chatgpt.com/docs/app-server#lifecycle-overview)，模型结束或取消后由 `turn/completed` 提供最终状态，不能用没有输出替代终态。官方文档没有给出桌面应用内部全部超时策略，本修复不推断其实现。

维护时查找日志事件 `codex_response_idle`，关联 sessionId、turnId、phase、idleMs；action 固定为 `observe`。日志不记录正文、工具输入或凭据。静默不能证明任务完成，也不能证明连接异常。

## 验证状态

Sidecar TypeScript 编译与 18 项定向测试通过，其中 5 项诊断测试覆盖模拟三小时静默、三小时持续进度、伪心跳、工具/人工等待排除、响应恢复、终态与下一轮重置；另 13 项覆盖连续发送、清理屏障、取消、崩溃和工具超时。旧实现在新诊断测试中失败，修正后通过。三小时使用可控时间模拟，不是三个小时的线上观察。
