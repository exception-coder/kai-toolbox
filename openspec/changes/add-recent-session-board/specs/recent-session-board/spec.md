## ADDED Requirements

### Requirement: 最近会话集中查看
系统 SHALL 在 Vibe Coding 工作区提供“会话看板”，按 `lastSeenAt` 从最新到最早展示最多 20 个会话。范围 MUST 沿用已有访问策略，排除业务咨询与规划已过期的会话，不受收藏置顶或侧栏状态筛选改变顺序。

#### Scenario: 查看最近工作
- **WHEN** 用户打开会话看板
- **THEN** 看板展示最近 20 个有效开发会话的标题、项目或工作主目录、引擎、活动时间与状态
- **AND** `RUNNING` 且 `live` 的会话标为进行中；非活动的 RUNNING 记录标为待恢复，不能冒充正在执行
- **AND** 桌面和手机均可进入看板；无当前会话时仍可打开

### Requirement: 查看尚未发送的队列任务
系统 MUST 按逻辑会话 ID 读取服务端持久队列，显示待发送条数与前三条任务摘要，并保持队列先后顺序。看板 SHALL 支持筛选进行中或有待发送任务的会话，筛选范围仅限最近 20 个。

#### Scenario: 空闲会话仍挂有队列
- **WHEN** 最近会话已经空闲或中断但服务端队列不为空
- **THEN** 看板显示尚未发送的任务和条数
- **AND** 在“有待发送”范围中仍保留该会话，提供进入会话查看和处理的入口
- **AND** 查看或筛选不发送、删除、恢复或重新排序队列任务

#### Scenario: 部分队列无法读取
- **WHEN** 某个会话的队列请求失败、超时或尚未完成
- **THEN** 该会话标明队列未核对，不能以零条或健康状态替代
- **AND** 已成功读取的其他会话继续展示
- **AND** “有待发送”范围保留未核对的会话，用户可以重试

### Requirement: 查询有界且缓存隔离
系统 MUST 先显示会话名单，再渐进读取队列；最多读取 20 个队列，同时进行的队列请求不超过 4 个。读取 SHALL 有超时和取消，并仅在看板挂载且页面可见时轮询。缓存 MUST 按账号和逻辑会话 ID 隔离，不以列表下标绑定结果。

#### Scenario: 排序变化或切换账号
- **WHEN** 会话顺序变化、请求较晚返回或登录账号切换
- **THEN** 队列结果仍归属于原账号与原会话，不能显示在另一条会话上
- **AND** 离开看板取消未完成的查询，不后台轮询全部历史、模型或运行态

#### Scenario: 进入对应会话
- **WHEN** 用户选择某条会话的进入操作
- **THEN** 工作区切到该会话的对话视图，并复用既有切换接口和运行提示
- **AND** 打开看板本身保持原会话、草稿与正在执行的任务
