# 需求持续推进设计

## 范围与复用

主对象仍为当前会话及其真实项目目录，以 session ID 和 Runtime run ID 标识（OBJ-01、AI-01）。沿用原自动推进覆盖层和监督看板，增加方式选择，不增加菜单或第二套项目/任务目录（NAV-01、DENS-01）。默认仍按规格推进，原调用缺省策略与严格预检不变。

`REQUIREMENT_BEST_EFFORT` 持久化在已有 completion_policy。`RequirementAutopilot` 管理目标交接和证据停滞判断，Service 继续负责队列、版本、预算和状态。SQLite 既有 change_id 非空列保存 `goal-<runId>` 作为兼容身份，change_revision 保存上轮证据摘要；两者不是 OpenSpec 事实，任务和工件查询返回空，不送入 OpenSpec adapter 或严格完成证据聚合。无需迁移或人工 SQL。界面展示需求、运行编号及报告，不显示虚构 task 百分比。

## 执行与完成边界

用户在原弹框输入至多 2000 字需求与预期结果，可调 1–200 轮、15–1440 分钟，默认 60 轮、480 分钟。Runtime 在事务提交后排队；需求模式不安装或激活严格 OpenSpec Continuous Execution Skill，由专用服务端指令交接目标和上一轮报告。Agent 自行明确必要验收、按项目规则补规格/写入绑定并实施，不能用需求编号冒充 change 或跳过门禁。

复用原会话引擎、服务端私有上下文、run/generation/turn 幂等身份、暂停/停止/恢复、预算重置及后台巡检（CTRL-01、IDEM-01）。活动运行的同项目同需求重复提交复用原结果，其他目标拒绝覆盖；暂停/结束后显式新建沿用现有替换当前投影约定。过期 generation、暂停状态、预算耗尽的内部消息不可领取。无需浏览器常驻。

只有成功且允许释放队列的引擎终态才能裁决。CONTINUE 继续派发；缺报告或连续相同/无证据递增停滞，达到默认 3 轮暂停。证据内容变化重置此计数，不以摘要改写算进展。COMPLETE 必须提供非空摘要、非空证据及显式空 remainingWork；字段缺失或仍有工作拒绝上报。Runtime 保存报告并显示“Agent 自验完成 · 待复核”（FEED-01、EVID-01），不自动归档或执行 OpenSpec 严格阶段。证据由 Agent 声明，平台检查形状与续跑规则，不独立证明命令真实执行或需求全部满足；不能用此结果替代原严格模式的验收。

WAITING_USER/BLOCKED、失败、手动接管和预算按已有边界停下；恢复保留运行身份、证据基线，并增加 generation。必要验收待重启或缺授权时不得完成；生产、发布、资源权限、writer 及每次重启确认不因本模式放宽。无不可逆操作授权不等待普通小步骤批准。

项目选择“编码优先”时先完成实现、不自动测试或构建，结束报告 WAITING_USER 并留下待验收项；后端拒绝此状态下的 COMPLETE。开发者切回标准验收并恢复后再继续，不把编码完成等同需求自验完成。

## 交互与恢复

原弹框保留关闭入口、Radix 焦点约束和 Escape；同会话需求草稿关闭或切换方式后保留，换会话清空，避免错投（CTX-01）。提交期间禁用重复提交与方式切换；覆盖层关闭不撤销已创建持久运行。错误保留输入并提供重试，超时不能假定服务端未创建；活动同需求重试复用原运行。预算与底部发送操作在窄屏可滚达，使用既有组件和 tokens。

验证覆盖默认严格模式兼容、无规格启动、重复提交、真实阻塞、重复证据暂停、缺报告/预算、重启恢复巡检、过期队列、SQLite 枚举回读、完成证据保留，以及手机/桌面弹框、键盘恢复和错误重试。真实模型长任务与目标版本运行验收单列待办，不以浏览器接口替身作为该项通过依据。
